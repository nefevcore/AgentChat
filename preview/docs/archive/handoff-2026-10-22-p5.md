## 3. 本五轮新增的坑与事实（省时间）

- **durable interactions 文件一行非法（如缺 state）→ 壳 boot fail-loud 起不来**（主线 store validate 既有语义）。诊断时手造种子必须带全字段：`{id,key,kind,payload,state,correlationId,owner,createdAt,updatedAt}`。
- **ask_questions pending 会占壳串行化门**（ConversationMachine 单门 per 壳）——挂起的交互阻塞该 agent 一切会话。恢复链 = interaction/list（cr-580 已通）。
- 同 tick 并发 deliver 的信封会在宿主→壳投递竞争中滞留 **outbox**，转投触发面只在 adopt/ensure——不丢（at-least-once）但延迟；产品化可考虑 dispatch 失败即时重试或周期 flush（记档未做）。
- 壳/宿主侧诊断盲区：**宿主从不读壳 stderr**（orchestrate spawn pipe 但无消费者）——壳侧报错看不到。直跑壳抓 stderr 的脚本形态：spawn boot.ts + stdin JSON 控制帧 + stdout TSV 回执（本轮 shell-direct.cjs 已清，照描述重写）。
- 长时序控制帧探针要在 **deadline 15s 之外**再探一次才能暴露 orchestrate 循环自杀类 bug（回归测试已锁）。
- 通道产物 `plugins/<name>/ui` 是 10/22 切换时构建的**快照**——若前端仍有视觉缺块，怀疑通道与主线组件漂移 → `pnpm --filter ac-ui-app build:channel` 重建（未验证过，注意通道落 pluginsDir 的写回路径）。
- mock 壳毫秒级收束——busy 排队窗口活体打不进（并发突发走 outbox），queue-changed 帧只能单测验（cr-579 已单测 + 同管线 run-error 两轮活体实证）。
- 老坑仍有效：块注释别写 `agents/*/sessions`；一个数据根只允许一个宿主（G4）；只信 /api/healthz（G9）；preview/ 未入库。
