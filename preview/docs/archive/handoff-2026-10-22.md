## 3. 现场环境坑位（踩过的，按编号认）

| # | 症状 | 根因 / 处置 |
|---|---|---|
| G1 | 封存 `rename workspace/home` 报 **EBUSY/EPERM**，重试 6 次全败 | 有进程持有该树里的**目录句柄**——本次真凶是**资源管理器窗口**停在 `sessions/singles/ws-…/<session>`。处置：关掉窗口即可。诊断法：`Shell.Application` 枚举窗口，或逐层 `Rename-Item`→改回 二分定位（脚本见 cr-557 报告） |
| G2 | `start AgentChat …` 起了个不相干的东西 | PATH 上有**同名全局包** `@nefevcore/agentchat@0.8.1`。一律用 `pnpm.cmd`/全路径，或 `start "" pnpm …` |
| G3 | `vite build` 末段 `[vite:esbuild-transpile] remove %TEMP%…: Access is denied` | esbuild 临时文件被实时防护占用。已用 `preview/apps/ui/scripts/build.mjs` 把 TEMP 指向包内 `.tmp-build`；**构建一律走 `pnpm --filter ac-ui-app build`** |
| G4 | 第二个宿主起不来：`EADDRINUSE … ipc-post-office-sock` | 数据根单写者 = 邮局命名管道。**一个数据根只允许一个宿主**；现在会给出可读提示 + exit 78 |

## 8. 纪律提醒

- **一个数据根只允许一个宿主**（G4）；验证/测试实例一律用独立数据根（`AGENTCHAT_DATA_ROOT` 指到 `preview/sandbox/diag-*`）。
- **构建产物不入库**：`dist/` 与通道产物都在 `preview/apps/ui/`；新机器/新克隆要先 `pnpm --filter ac-ui-app build`，否则 3830 只有 WS/RPC。
- 切换是**重操作**：`scripts/cutover.mjs` 的封存段不可逆（改名前先确认没有窗口/编辑器停在数据根里）。
- 写 RPC 时**永远不要**把 `api_key` 明文落进 `config.json`（主线不变式）。
