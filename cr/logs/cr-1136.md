# cr-1136 check 守门懒 sync 落盘副作用根除

- **日期**：2026-11-16
- **标签**：#meta
- **状态**：done

## 现象

每次 `node cr/cr-git.mjs check` 后 `cr/cr-commits.json` 必定显示为脏，
需要额外一笔「投影收尾」提交——cr-1120 批次因此连续追了 3 笔 chore。

## 根因

check 锁6（commit 引用面校验）经 `doSync(false)` 懒同步，而 `doSync` 在
entries 有变化时无条件 `writeFileSync` 落盘——**守门命令自带写副作用**。
校验只需扫描结果（dangling/悬空引用），落盘却耦合在同一次调用里。

## 修法

`doSync(rebuild, persist = true)` 拆读写职责：

- `persist` 缺省 true——显式 `sync` 行为不变（唯一落盘入口）；
- check 锁6 改 `doSync(false, false)` 内存态校验：只算不写，扫描
  结果（dangling）原样返回，投影文件不被触碰；
- 顺带把 `refCount` 计算上提到 unchanged 分支之前（两分支共用，
  消重复）。

## 验证

- check 前后 `git hash-object cr/cr-commits.json` 哈希不变（零写副作用）；
- 显式 `sync` 仍正常落盘（542 cr 号 / 823 引用，悬空 0）；
- `migrate` 幂等（已是 v3.1 形态 no-op）；`node --check` 语法过；
- check 全量通过：1136 条，锁 1-6 全绿。

## 工作流影响

此后 check 可随意跑（含 CI/验证阶梯）不再污染工作区；投影增量由
显式 `sync` 收敛，提交链不再出现「投影收尾」尾巴。
