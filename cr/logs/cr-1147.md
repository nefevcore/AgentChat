# cr-1147 定时器脚本化重做

## 动机

旧 5 模式 declarative 状态机复杂度税（compensateMissedTriggers 70 行猜测逻辑、
ISSUE-22 系列 gate 外挂）。重做定位（探讨后收敛）：**探测循环 + 判定脚本**，
Agent 自管理（人类经 Agent 间接设置）——next 是下次探测时刻非业务触发时刻，
无模式无排定锚点。

## 契约（v2 终版——多轮探讨收敛）

- args = { now, last?, count, state? }（4 字段纯数据快照；tz/entry/派生量全砍）
- utils = { at, after, minute, day, dow, workday, ms }（纯函数包作第二参——
  utils.minute(now) 显式传时刻形态，可对 a.last 等任意时刻求值）
- verdict = { action?, next?, state?, active? }（四轴不变）
- next = Date 唯一形态（意图时刻可持久化；数字串/间隔串词形退役，u.after 承接）

## 关键裁决

1. 探测循环定位：使用者是 Agent——旧模式是人类配置界面遗产，等价性投资停止
   （compileEntry 降级为「不炸、不丢」）。
2. persistNextAt 断点：重启直排未来值防触发风暴（v1「重启重跑全部脚本」
   会让编译产物 started 旗标立即触发——真 bug）。
3. 状态前置持久化：gate 跳过轮也保存 state（v1 缺陷）。
4. 迁移清 scriptState 保记账：防 v1 残留旗标风暴 + count 连续。
5. utils 双参注入：与 run_code tools/lib 同构；墙钟判定一律经 u（进程时区陷阱）。
