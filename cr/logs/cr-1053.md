# cr-1053 时区缺省链统一

- **日期**：2026-11-13
- **动机**：cr-1052 收口了日/月键派生（UTC 单源），遗留三处墙上时钟缺省分叉——timer-core 函数缺省 = 进程本地时区、timers-row 行基线 = Asia/Shanghai 字面量、ac-datetime 日期行 = 进程本地。同一 Agent 的「定时几点触发」（owner 时区）与「今天几号」（进程本地）在非上海部署/非上海宿主机器上口径不一致。
- **改动面**：
  1. `ac-core-utils/time-keys.ts` 增 `DEFAULT_TZ`（'Asia/Shanghai'）与 `resolveTimezone`（空/白/非法 → DEFAULT_TZ，Intl 预检）——缺省时区与降级链全仓单源 + 单测；
  2. `ac-timer-core`：msUntilTime / withinActiveHours / createHolidayResolver / renderHint 的 tz 缺省与非法降级全部收口（缺省 = DEFAULT_TZ；「进程本地缺省」与「非法 tz 降级本地」两条路径移除）；localISO 缺省参改 DEFAULT_TZ，原 catch 内硬编码 UTC+8 分支删除（resolveTimezone 归一后不可达）；package.json 增 ac-core-utils 依赖；
  3. `ac-timer-core` 测试：msUntilLocal 直接路径的用例全部改显式 UTC 锚 + 上海墙钟预期（原用例隐含「宿主时区 = 上海」，非上海机器必 flaky——UTC 服务器 CI 上 8 例失败实锤）；非法 tz 断言从「不抛错」升级为「归一 DEFAULT_TZ 确定值」；
  4. `ac-host-rows/timers-row.ts`：行基线字面量 → DEFAULT_TZ 单源引用；
  5. `ac-datetime`：日期注入行从进程本地时区改为 owner 生效时区（settings〔timers〕.timezone ∪ 全局默认层，缺省 DEFAULT_TZ）——与定时触发同一词汇（timers.timezone），Agent 对「今天」与「定时」恒同口径；inject 增 agents 硬依赖；package.json 增 ac-core-utils 依赖；description/注释同步。
- **裁决**：
  - DEFAULT_TZ 取 Asia/Shanghai：产品主市场基线，与 timers-row 既有行基线一致——行为保持；原「进程本地」缺省是历史产物（src 轨道单机时代语义），宿主部署到 UTC 服务器时定时语义随环境漂移，属 bug。
  - ac-datetime 复用 timers.timezone 设置词汇而非新设 datetime.timezone：一个 Agent 只该有一个墙上时钟——「定时几点」与「今天几号」必须同源，两个设置项必走散。
  - singles 快照行的 agent 身份取 call.request.agent：无 agent 身份的直连 loop → DEFAULT_TZ。
  - timer-core 测试改 UTC 锚后，本地（上海）与 UTC 服务器 CI 预期一致——测试不再依赖宿主时区。
- **验证**：typecheck ✓ check:deps ✓ 定向 eslint ✓ 定向 vitest（timer-core/core-utils/datetime/host-rows）179/179 ✓ pnpm test 全量（unit+integration）✓（见登记行）。
- **影响**：非上海时区部署的宿主上，定时触发时刻、节假日/工作日判定、活动窗口、日期注入行从「随宿主时区漂移」变为「DEFAULT_TZ 基线 + owner 时区覆盖」；上海时区部署行为不变。
