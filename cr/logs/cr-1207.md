# cr-1207 · package 形态安装期保留名门禁补缺

## 动机（缺口）

cr-1075 把「插件名不得占用官方命名空间」落在 `validatePluginManifest`（manifest.json 在场臂）+
`plugin-guard`（装载期硬闸）双层。但 v2.1「包即插件」主格式是 package.json 形态——
`readPluginPackage` 对 manifest.json 缺席的目录直接读 `package.json` 投影，**不做任何名字校验**；
`loadManifestFromDir` 回退臂同样裸投影。结果：`ac-evil` 同名包能通过安装门禁入库（installed.yml + registry 落账），
静默哑弹到壳 boot 才被 plugin-guard 拒载——fail-closed 保住了（进不了进程），但「安装期即拒绝」对主格式不成立，
用户看到的是装完用不了，而非安装回执的可诊断错误。

## 改动面

- `packages/ac-plugin-core/src/manifest.ts`：拒绝文案抽出 `reservedPluginNameError(name)` 单源导出
  （validate 臂内联块改为调用，字面不变）；头注释 permissions 词表补 risk（cr-1074 漏注）。
- `packages/ac-plugin-core/src/pkg.ts`：`readPluginPackage` 的 package.json 读臂在 name/version 检查后补
  `isReservedPluginName(name)` → throw `reservedPluginNameError(name) + '：' + dir`。
  该函数是包描述符读取单一收口——`admissionOf` 门禁、`stagePlugin`、v1 `loadManifestFromDir` 回退臂、
  试跑（plugin-dev loadSession）全经它，一处门禁全链收口。legacy 臂经 `validatePluginManifest` 已覆盖，注释注明。
- 测试：`pkg.test.ts` 官方名 fixture（`ac-plugin-todo`）改第三方名 `dev-plugin-todo`（官方名从此会被
  新门禁拒收，不能继续当合法 fixture）+ 新增门禁用例（ac-evil / shell-fake / root 三名 throw）；
  `installer.test.ts` admissionOf 用例追加 package 形态保留名拒绝断言。

## 裁决与边界

- 门禁放 `readPluginPackage` 而非 `admissionOf`：后者只是三入口共用的门禁求值器，前者才是全部安装/试跑
  路径的必经收口——放 admissionOf 会漏掉 `stagePlugin` 直接调用路径（v1 行 :168）。
- 安装回执文案归一：门禁失败在 installPackage 回执 reasons 呈现（admissionOf 捕获读取 throw 入 reasons），
  与 engines/permissions 门禁同通道，无需新面。
- 技能文档（plugin-dev SKILL.md）cr-1076 已写「安装期即拒绝装载」——本 CR 是让该承诺对主格式成立，文档无需改。
