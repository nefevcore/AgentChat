# cr-1166 source 视图读授权（timer-v3 §五/§七分期项兑现）

> 登记于 2026-11-20 · →cr-1161（timer-v3）→cr-1165（采集层）· 状态：done

## 动机

cr-1165 复查修补时确认的缺口：exports/ 已入 sandbox 双禁表（封死读写），但「授权后可读」未做——wechat/news 多 Agent 场景三面洞开（任意订阅 / 无读面 / 无白名单）。本 CR 兑现设计 §五「读授权：per-agent inline asset」与 §七「源订阅受视图读授权约束」。

## 改动面

- **ac-auth-core `source-view.ts`（新增）**：InlineAsset spec 定形 `{kind:'source-view',source,view}`；`sourceViewsOf`（per-agent 投影——grants ∪ denials，与 projectEffective inline 路径同语义；rowset 不参与）；`hasSourceView`（单条判定）；`sourceViewDir`（路径组件拒绝——防穿越）。三方共用单源：timer set 校验 / timers 分发 / fs 读白名单。
- **ac-sandbox-core**：`createDenyListsFactory` 产出加 `sourceAllowed`（授权物化目录绝对前缀）；`DenyListsSource` 加可选 `sourceViewsOf` 面（软依赖注入，纯库不依赖 auth）。
- **fs-tools / fs-search**：读路径（read/glob/grep 结果过滤）先查 sourceAllowed 再查 deny——授权目录内读放行；`str-replace-editor`（写路径）**不豁免**（授权是只读语义，防改物化面投喂触发层）。
- **timer-face**：set 分支加授权闸（`maySubscribe` 查询面——未授权视图校验拒，错误消息指引 inline grant 配置）。
- **timers-row**：`maySubscribe` 公开面（GLOBAL_OWNER 恒过——全局条目扇出面是用户配置 target 白名单，不经 LLM）+ 分发二道闸（每事件现查——授权吊销后已存条目自动失效；直改 timer.json 绕不过 set 校验）。
- 依赖：ac-fs-tools / ac-fs-search / ac-host-face +ac-auth-core（dependencies，值导入）。

## 裁决

- **只走 per-agent inline，不加 GlobalAsset 形态**：源视图是小额直享（单 Agent 单视图），与 inline 定位一致；全局层是凭据/行装载/MCP 等平台资产的家。
- **读豁免≠写豁免**：白名单只开口读路径（read/glob/grep）；编辑器写路径照常双禁——物化面是触发层输入，Agent 侧永远只读。
- **每事件现查授权**：不做授权快照缓存——auth.json 每 run 前重读的最终一致语义同拍，吊销即时生效。
- **二道闸的理由**：timer.json 在 Agent 双禁域内（现状无旁路），但闸的成本是每事件一次投影（微秒级），换来「授权面失效即投放面失效」的不变量——纵深防御不依赖单点。
