# cr-1183 markdown 表格列宽优化（hug + 贪婪列封顶）

- 日期：2026-11-21
- 状态：doing → done（本批）

## 动机

用户反馈表格列宽分配偏贪婪。实测（无头浏览器 + 仓库 markdown.css 规则复刻）：

- `width:100%` 使小表恒拉满气泡（720px 容器里 2 列键值表两列 267/453px）；
- auto 布局按各列 max-content 比例分配剩余宽，长 URL/SHA 列吃光表宽
  （720px 容器「描述」列 643px、「字段」列 77px）；
- `word-break:break-word` 只影响 min-content 计算（哪里能断），不改变
  max-content 分配权重——治得了撑爆治不了贪婪（实验：td 加 anywhere 后
  列宽逐像素不变）。

## 方案（对齐主流）

GitHub `github-markdown-css` 主源验证：`width:max-content; max-width:100%`
（hug + 封顶滚动）是文档型渲染主流；chat 前端多为 w-full + wrapper 滚动
（同样贪婪）。列级封顶需渲染器参与（内容语义纯 CSS 不可选），参考 lody
项目 hast 列分类思路（长 token 列 `overflow-wrap:anywhere` + `max-width` 封顶）。

## 改动面

1. `apps/ui/src/assets/markdown.css`
   - L1：`.md-table-wrapper table` `width:100%` → `width:max-content; max-width:100%`；
   - L2：新增 `th/td.md-col-clamp` 封顶规则（`max-width:20em`，td 另加 `overflow-wrap:anywhere`）。
2. `packages/ac-client-ui-renderer/client/useMarkdown.ts`
   - `TABLE_LONG_TOKEN_RE`（≥25 连续非空白）+ `cellHasLongToken`（text/code_inline children）
     + `detectClampColumns`（table_open 起前瞻 token 树，th/td_open 后邻 inline 判定列标记）；
   - `table_open` 时算列分类（渲染期闭包态，render 同步不重入不串扰），`tr_open` 重置列号，
     `th_open/td_open` attrJoin('class','md-col-clamp') 后走默认 renderToken 链。

## 关键实验数据

| 场景（720px 容器） | 改前 | 改后 |
|---|---|---|
| tiny 2 列键值表 | 拉满 720px | 62px 内容宽 |
| URL 贪婪列 | 643px 吃光表宽 | 286px（=20em 封顶） |
| 短列（说明/字段） | 56~77px | 恢复自然宽 |
| 360px 窄容器 | 折行 | 行为不变（max-width 兜底） |

性能：列分类扫描实测占 md.render 的 4~13%（大表 50×8 约 0.22ms/次）；
v2 分块渲染下表格进已提交前缀后 HTML 缓存复用，不随流式 tick 重扫。

## 裁决

- 不改滚动优先（td nowrap）：聊天气泡窄，折行优先多列才滚动更适合；
- 封顶 20em：对齐 lody 方案经验值，实测 286px；
- 阈值 25 字符：URL/SHA/长路径的最小公共长度，中文短词不误伤（softbreak 分段天然保护跨行长文）。
