# cr-1205 fs-search grep 双收口：快照镜像树排除 + rg 解析改主包 rgPath

## 动机（cr-1205 2026-11-22）

用户报告 `grep({ pattern: "meta/", include: "*.ts", limit: 40 })` 耗时异常、疑 cr-678 rg 优化未生效。实测排查：优化**已生效**（工具 1597/1999ms ≈ 等价 rg 直跑 1580ms 三次稳定，未落 Node 回退），但揪出两个实现面缺陷：

1. **file-snapshots 镜像树污染搜索面**：数据根按会话镜像用户文件树（URL 编码路径副本）。本仓 workspace/home/file-snapshots 内 **3985 个 .ts / 83MB**——无 path 全仓搜索时 147 个命中文件里 **110 个是陈旧快照副本**（total=363 注水约六成），既浪费扫描（~250ms）更误导检索结果。
2. **rg 二进制解析链脆弱**：`require.resolve('@vscode/ripgrep-<plat>-<arch>/bin/rg')` 从 rg-core.ts 解析，pnpm 布局下平台子包不在常规解析链——实测命中 **`C:\Users\xiaofeng\node_modules` 的偶遇散装副本**（脱离 lockfile 管控）；干净机器解析失败 → resolveRgPath undefined → **静默降级 Node 回退**（慢一个数量级，用户无感）。

## 改动面

- `ac-glob-core/src/walk.ts`——SKIP_DIRS 增 `file-snapshots`（构建产物层；SKIP_BASE 不动）。段名匹配语义：path 直指该目录时照常全搜（rg 排除 glob 以 cwd 为基准自动恢复；walk 排除仅在根层之下生效）。
- `ac-fs-search/src/rg-core.ts`——resolveRgPath 改经主包 `(await import('@vscode/ripgrep')).rgPath`（主包是本包 dependencies 直依赖，软链恒在解析链上；其内部在 .pnpm 邻位解析平台子包，pnpm-safe）。动态 import + promise 单飞缓存：缺平台子包时主包模块级 throw 被捕获 → undefined → 优雅回退。删 `import type {} from '@vscode/ripgrep'`（主包现值导入，依赖声明自足）。runRg 消费方随之 await。
- `ac-fs-search/src/index.ts`——行层 rg 引擎判定改 `await resolveRgPath()`；`rgEngine` 中间变量内联。
- 测试：glob-core 锁 SKIP_DIRS 含 file-snapshots；fs-tools 新增 rg 路径镜像排除用例（normal.ts 命中、file-snapshots/mirror.ts 不进结果——Node 回退路径同享 walkFiles 免重复用例）。

## 运行时实测（壳重启后）

- 原始命令 `grep({pattern:"meta/", include:"*.ts", limit:40})`：**total 363 → 92**，命中文件 147 → ~37（快照副本注水 271 条命中全消），`file-snapshots` 命中 0。
- A/B 交替计时（同一时刻、仅差 `--glob '!**/file-snapshots/**'`）：排除 1408/1524/1558ms vs 含快照 1672/1782/1705ms——**每轮省约 220ms（13%）**。
- rg 解析路径实测：`...repo\node_modules\.pnpm\@vscode+ripgrep-win32-x64@1.18.0\...\rg.exe`（仓库内、lockfile 管控），不再命中用户主目录副本。
- 回退路径（walkFiles）语义确认：默认跳过 `file-snapshots`；`path` 直指该目录时照常搜出其内容（排除仅在根层之下按段名生效）。

## 耗时结构结论（诊断记录）

该命令耗时主力是全仓 `.ts` 枚举+读取（21885 个文件 ≈1.4s，NTFS 上属基本盘），rg 已是同口径最快引擎；cr-678 优化本就生效（工具耗时≈rg 直跑、未落 Node 回退）。本次两项不做数量级提速，收益在**结果质量**（命中不再被陈旧镜像注水）与**部署稳健性**（换机不再静默降级）。要显著提速须带 `path` 收窄搜索根。
