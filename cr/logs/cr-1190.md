# cr-1190 续修：v1 混合会话归档三连修（writer 实证）

## 现场与根因

writer 的 user~writer 会话（v1 头行 2026-09 创建 + 后续追加 v2 事件行——writer.ts「头行永不重写」的合法混合形态）两次归档整理轮正常跑完（含 session_digest 提交、摘要行落账），但 compaction 事件恒不落、行数不变。三处叠加根因：

1. **版本判据错位**：archiveAndRebuild 按 header.version 分流——v1 头行会话走 v1 分支（content-only 截断），而 90% 行是 content 空的 v2 事件行 → truncateTail 零成本吃完全表 → archive 恒空。修：行面判定（任一行带 type/seq 即走 v2 语义——与 events-v2 归一化「按行判别」同源）。
2. **splitForArchive 漏传 viewer**：v2 分支伪行（content=''、轨迹在 steps）按 content-only est=0 → 同样全表零成本。修：传 { viewer: agentId }（回放口径计量，与 estimateOf 同源）。实测伪行真实体积 32.5 万 token 此前全漏计。
3. **boundary 取源含摘要行**：伪行尾部追加进 enriched 使刚落账的摘要行位置落进归档段 → boundary= 摘要行 seq → 自 shadow → 回放头蒸发。修：boundary 改从 archivedOriginal（机制行已排除）取 max seq。

## 验证

- 新用例「v1 头行 + v2 事件行混合会话走 v2 语义」锁三处修复；ac-shell-rows 51/51、三包 220/220 绿。
- writer 实证（修复代码重拉壳后手工触发）：第二代 compaction boundarySeq=780 / shadowedRows=783（此前恒 0）；三条摘要行 seq 728/751/781，最新（781）> boundary（780）不被 shadow；foldDigestOf 返回最新摘要 ✓。

## 续修 4：整理 hint 删「整理工作文件」条目

writer 实证驱动的评估：该条目是主线 ac-archive 时代遗物（V3 平移时照抄）——TODO.md 归 todo 工具、note/ 知识库归 memory 行，归档轮插手 = 双事实源；DONE.md 无出清机制滚至 268KB；每次归档固定 2-3 步 + 大文件读开销。删除后 hint 收窄至总结提交 + 机制边界说明，归档轮职责单一化。
