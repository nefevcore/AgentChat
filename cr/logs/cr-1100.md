# cr-1100：meta/sessions 前缀快照分居（幻影「新会话」根因修复）

## 现象

session/list 涌出大量「新会话」空条目。实况：`.singles-registry.json` 1302 条中 91 条 id 以 `.prefix-snapshot` 结尾，全部 count=0 / agentId='' / 无标题——前端 titleOf 对无 lastActivity 会话恒回落「新会话」。

## 根因

两级叠加：

1. **cr-973 聚居埋雷**：prefix 快照与 singles 元数据同居 `meta/sessions/`（`<sid>.prefix-snapshot.json` 寄居在会话元数据目录）。
2. **listIds 通配误收**（`ac-host-rows/src/singles-row.ts`）：目录扫描只判 `endsWith('.json')`——快照文件剥后缀成假 id `<sid>.prefix-snapshot`；`userMetaFile(dataRoot, '<sid>.prefix-snapshot')` 恰好指回快照本体，readMeta 窄化通过（快照 JSON 有 createdAt）→ 幻影空会话视图成立 → 装载对账固化进注册表，每次宿主启动从盘上快照文件复活（11-15 清理档只清注册表、源文件还在，故复活）。

附带伤害：UI 删幻影条目时 `singles/delete` 的 `rmSync(userMetaFile)` 删的是真会话的快照文件（快照缺席走重新物化，非数据丢失，但误删真资产）。

## 修复（方案 B：分目录）

- **`ac-shell-conversation/src/prefix-snapshot.ts`**：`snapshotFileOf` 落点改 `meta/prefix-snapshots/<sid>.json`（类型物理隔离，listIds 通配天然正确）。只认新位（旧位读窗不留——迁移由宿主行幂等搬空，fail-safe 物化兜底）。
- **`ac-host-rows/src/singles-row.ts`**：
  - apply() 装载对账前一次性 sweep：旧位 `*.prefix-snapshot.json` → 新位（新位在场优先、同名残留即清；幂等归零后零枚举直通）。放宿主侧非 shell 侧：宿主单进程先于壳与 web 请求，无换代窗口；测试 harness 直接 apply() 天然覆盖。
  - `listIds` 收窄：剥 `.json` 后 id 段含点即非会话（uuid 形无点；实况 99 合法 meta 文件名均无点）+ 词汇锁注释：meta/sessions/ 只收裸 `<sid>.json`，新的会话级产物勿再寄居。
- **测试**：singles-row 追加 4 用例（sweep 搬空/新位在场不搬/幂等/幻影不收）；prefix-snapshot.test.ts 旧路径注入改新位。
- **文档**：session-design.md 目录树 + §5.2 落点同步。

## 自愈路径

无需数据迁移脚本：下次宿主启动 sweep 搬 93 个快照文件 → listIds 不再产出假 id → reconcile 摘除注册表 91 个幻影键（diskIds 不含 → delete）。

## 迭代：per-file 容错（同变更面复用本条）

活体验证暴露初版实现缺陷：sweep 的 try/catch 包在**整个循环**外，
单个文件 rename 失败（Windows 文件锁挡住活壳正在写的旧位文件）会中断整批剩余文件；
catch 注释还写成「目录缺席」，语义不符。

修法：抽 `migrateLegacyPrefixSnapshots(dataRoot, fsApi = fs)` 导出函数——
逐文件独立 try/catch（失败留待下次装载重试）、fs 面可注入（单测造失败面）、
apply() 退化为一行调用。残留对 listIds 已无害（词汇锁排除含点文件名）。

配套：singles-row 测试 +1 用例（注入 fake fs 使首个文件 EPERM → 断言其余照搬、失败者留守、list 不产幻影），36/36 绿。

## 壳侧装载（附记）

`ac-shell-conversation` 由 shell.yml 点名——宿主重启只让 sweep 生效，
快照**写入**路径随壳换代才变。故需 restart_shell；切换窗口内旧壳写的旧位文件
由下次宿主装载 sweep 幂等清掉。
