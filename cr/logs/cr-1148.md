# cr-1148 ask_questions 无人值守会话两道防线（C 超时兜底 + B peer 路由）

## 动机

admin~news 事故（2026-11-17）：无人值守消化链上 admin 调 ask_questions 挂起 awaiting_user，
无应答者（peer 不知、用户不看该桶）→ run 无限挂死 + 会话队列积压 + pending 交互永生。
存量防护三面各管一段：self 桶工具裁剪（requiresInteraction）/ humanPresentOf 判定（cr-1079，
明文不用于交互轴）/ subagent 子域父路由（cr-730/731/863）——agent~agent 桶无任何保证。

## 改动面

- C（超时兜底）`packages/ac-ask-questions/src/index.ts`：发起体判 humanPresentOf(key)===false
  → payload 记 noReply + noReplyDeadlineMs（10min）；loop/run-idle 挂起等待 poller 超龄对账
  close('timeout')——closed 注入支线（「用户未响应——请自行决断」）零新机制接管。
- B（peer 路由）`packages/ac-shell-conversation/src/service.ts`：
  - 发起壳 opened 事件（owner=本壳 & agent~agent 无人桶）→ pushPeerAsk：peerAsk 信封
    deliver() 双层会合投对端（活壳 ipc 直投 / 缺席落对端 inbox——requestId peer-ask-<id> 幂等），
    正文 = 问题全文 + [peer-ask:<id>] 标记引导 + send_agent 回信说明；发起侧 peerAskSeen 自记。
  - 回信到达发起壳收信面：正文含 [peer-ask:<id>] 且册内未消费 → forwardPeerAnswerIfAny 构造
    interactionReply 信封（budget=0）投回本壳 → 收信面既有 iReply 分支 → durableInteraction.reply
    → answered 三态注入（挂起半边/忙步 steer/late-reply）全既有。
  - 设计修正记录：登记册初版放对端收信侧（测试红）——对端壳装不装 conversation 行不可知，
    改发起侧自记（pushPeerAsk 成功即记），对端零状态、只按正文回复。
- D（纪律句）ask_questions 工具描述补无人值守使用指引。
- 依赖：ac-ask-questions +ac-agents（值导入 humanPresentOf）；devDeps 补测试树 4 包。
