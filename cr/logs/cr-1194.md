# cr-1194 TokenGauge 显示算法 P+delta 实施（cr-1193 交接）

## 根因（见 docs/design/session/token-gauge-p-delta-handoff.md）

锚点机制 `E×r = E×(P/E) = P` 绕圈重推 P 已知的答案，且 P/E 配对存在三病灶：P 语义漂移（首步 prompt vs 收束后盘读不同拍）、双数据源分叉、三态切换跳变。cr-1191 跨代守卫是在给补丁打补丁。

## 方案（两态显示）

- run 中：displayTotal = livePrompt（不变）
- idle：displayTotal = P + delta
  - P = cache.lastRunPrompt（usage.prompt 覆盖轨 = 末步 prompt，天然含 system/工具定义/模板/轨迹全部真实开销）
  - delta = Σ 锚后新行 est_tokens（estimateRowTokens 白名单单源：机制行 NULL、subcall 0、摘要行计入——cr-1190 Q2）
  - 锚 = **末次 run 在 records 的末行时刻**（见下「锚来源两轮修正」）
  - 跨代失效：锚 <= 末代 compaction end_ts → pdelta 缺席（后端单源判定，替代 cr-1191 病理界 [0.33,3]）
- 降级：索引缺席/未入账/无 P → pdelta 缺席 → 前端净估算（原第三态保留）

## 未竟事项裁决（交接档 §四）

1. est-since 取源：**后端精确值**（records 表 ts_num > 锚 + 活跃代过滤，SQL 单源，口径与 E 同源）
2. 无 P 场景：pdelta 缺席回落净估算（原第三态保留为降级路径）
3. delta 边界：est_tokens 白名单现状即与回放注入同口径（estimateRowTokens 单源）——不另设判
4. 四段条减法语义：P+delta 态沿用锚点态语义——contextTokens = displayTotal − 开销实值（clamp ≥0），开销未取按 0（净估算语义已由 displayTotal 兜住）
5. KV sparkline：独立数据面不动

## 锚来源两轮修正（活体验证暴露，最终形态）

1. **首版：journal-settled 行 ts** → 活体探针证明 pdelta 恒缺席：真源 `JournalSettled` 接口（ac-ledger/records.ts L198）**没有 ts 字段**（只有 type/run/finish/usage/model/seq），真实 partials.jsonl 实证同样如此（`{"type":"journal-settled","run":…,"finish":"ok"}`）——`MAX(ts)` 恒 NULL。
2. **二版：按 run 反查 records MAX(ts_num)** → 仍恒缺席：实读 1113 个 partials.jsonl 后发现 `journal_lines` 表对多数会话**大面积不入账**（抽查三个活跃会话 journal 行数为 0，而 records 有 394/83/1938 行）——journal_lines 不能作判定依据。
3. **终版（纯 records 自足）**：锚 = 末次 run 的末行时刻——`SELECT run … ORDER BY ts_num DESC, seq DESC LIMIT 1`（run-end/步行都带 run）取末 run，再取该 run 的 `MAX(ts_num)`。方向偏保守：该 run 尾部少量行不计入 delta（那些行本已含在 P 的末步 prompt 里，宁低估不重复计）。无带 run 的 records 行 = null（从未跑过 run，P 无依据）。

教训：锚的可用性必须由**实读真源**确认（字段存在性 + 表填充度），不能从索引 schema 反推。

## 验证锚点（设计档 §三）

收束瞬间读数 = 末步 livePrompt（连续无跳）；随后每条新消息增量稳定；归档后回落净估算、下轮收束重锚。

## 运行期生效（前端产物）

活体验证暴露一条容易漏的链路：**`build:channel`（行包 factory 产物）不等于前端生效**——`ac-client-ui-agents` 的 `rosterApi.ts` 被打进 `apps/ui/dist/assets/main-*.js` 主 bundle（宿主实际服务的就是它），只跑 build:channel 时主 bundle 仍是旧构建（实测 old main 含 `lastRunPrompt` 但无 `pdelta`/`estSince`）→ fetchSessionTokens 不透传 pdelta → 前端恒走降级净估算（弹层 18% / `~182K`），而环形因 run 中 livePrompt 显示 13%，两处读数打架。

修：`pnpm webui:build` 重建主 bundle（main-BS4lhLVQ.js 含 pdelta）→ 刷新页面后弹层 = 13% / `133K / 1M`（无 `~`，即 P+delta 态）。**改动涉及 ac-client-ui-* 且要看运行时效果时，build:channel + webui:build 两件都要跑。**
