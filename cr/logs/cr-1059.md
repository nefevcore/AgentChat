# cr-1059 修复 web deliver 边界 pair 缺省不归一对桶键（直答会话碎化）

- **日期**: 2026-11-13
- **状态**: done
- **标签**: #fix #session

## 现象

前端 Agent 列表选 Agent 发消息，落进一次性 uuid 会话而非 agent 长会话（对桶键）。
`__creator__` 名下 211 个 uuid 会话目录、0 个 `user~__creator__` 对桶目录；其中 148 个
为 pair 路径出生（无 singles meta / meta 滞后于首条 send），64 个只发过一条就蒸发。

## 根因

前端 pair 路径不传 `conversationId`（chat-core deliver 仅 single 显式传 sid）→
`ac-host-webui/src/web-api.ts` deliver 边界把 undefined 透传给 `user.send` →
`UserStub.send` 的 `options.uuid ?? issueConversationId()` 每次新签发。注释自称
「D3：前端不传 conversationId 时边界显式计算」，但只有 model 合并点算了 pairKey，
uuid 本体从未归一——与 `ac-conversation` deliver 的对桶缺省（L411）脱节。

## 修复

- `web-api.ts`：`conversationId = optStr(p.conversationId) ?? pairKey('user', agentId)`；
  model 合并点同源化（复用已归一的 conversationId）。
- 断言更新：`e2e-cutover.test.ts`（/-7/ 新签发 → alpha~user）、`e2e-host-web.test.ts`
  （typeof string → alpha~user，防回归锚）。
