# cr-1278 —— V3 消息架构补回多模态附件旁路

> 状态：done（2026-11-24）｜标签：无｜前置：cr-1273/1274（V3 账本与摘要单源）

## 动机（现场）

用户发图（JPG）问「能看到图内容吗」，Agent 只收到 `[附件] <路径>` 文本行；
系统提示词的 `[模型能力]` 行却按 `visionOf()` 判定该模型支持视觉，声明「附件图片
会直接送达，不要声称无法查看」——链路断开时这句防御幻觉的话反而制造幻觉。

可证实的事实（非猜测）：

- 全数据根会话盘面 `agents/**/sessions/**/messages.jsonl` 搜 `"attachments"` 命中 0
  ——V3 之后从未有一张图真正落过账；
- `ac-host-webui/src/web-api.ts` deliver 内留着欠账注释「attachments 面未接（恒缺省）」，
  是 cr-703 单轨重组（ac-web-api → ac-host-webui）时留下的；
- 前端采集（`chat-core.ts` `imageAttachmentsOf`）与 provider 物化
  （`ac-llm` contract + `ac-openai-completions` `resolveMedia`/`visionModels`）两端完整，
  中间层整段缺失：UserStub 信封、壳侧入站行、账本行协议、fold 回放。
  `docs/design/archive/platform/multimodal-vision-input.md`（M1-M4 标「已实施」）
  所列落点 `ac-session SessionRecord.attachments?` / `ac-conversation project 闭包`
  均已被 cr-973（viewer 账本退役）/ cr-974（事件日志 v2）/ cr-1245（类型迁 ledger-core）
  的重写替换而未同步迁移。

## 裁决与取舍

- **引用旁挂不内联 base64**（沿 M1 原裁决）：落盘/信封/事件只带几十字节 ref，base64 物化
  收敛在 provider 适配层，前缀缓存不受污染。
- **非法项丢弃而非拒信**：缺 ref / 超长 ref / 未知 kind 单条丢弃；单图缺失由适配层
  降级文本占位，不炸整轮。空数组归一为 `undefined`（信封不留空壳键）。
- **assistant 位不带附件**：DeepSeek/GLM 均只允许 user 消息携带图片块。
- **存量行零迁移**：`attachments?` 缺席 = 无附件，旧会话刷新/回放行为不变。
- 群聊 `history` 回带附件是 chips 恢复的补充面（正文 `[附件]` 行仍在——非视觉模型走
  `read` 工具的既有路径不回归）。

## 第二处独立断点（同日复查发现·配置面）

打通消息链路后复查视觉门控，发现 `workspace/home/config.json` 的 `llmProviders.deepseek`
**没有 `visionModels`，`models` 也只是裸名（无 `vision: true` 探测标志）**——

- 适配层 `ac-openai-completions` 的视觉门控 fail-closed：清单为空 → 一律剥离 image 块，
  即使 LlmMessage 带着 attachments 也不会进请求体；
- `visionOf()` 返回 undefined → `[模型能力]` 行不注入（前缀快照实证：2026-11-14 23:27 起
  该行消失，此前 16 份快照含「支持图片输入」）。

实证探测（本地凭据直连，1×1 PNG + `image_url` 块，`max_tokens=4`）：

```
deepseek-flash   status=200
deepseek-v4-pro  status=200
```

两者均接受图片输入（换行格式被受理），故为连接补回：

配置形态取设计现行式（**`models[].vision` 探测标志**，不是旧手写清单）：`PoolEntryForm.vue:70-71`
明确「旧 visionModels 手写清单退役（读取侧统一 models[].vision）」，连接表单保存时会 `delete
draft.visionModels`——把显式清单写回 config 只会在下次编辑连接时被再次清除，故按现行形态落：

```jsonc
// workspace/home/config.json → llmProviders.deepseek.models
[ { "model": "deepseek-flash", "vision": true },
  { "model": "deepseek-v4-pro", "vision": true } ]
```

模型清单刷新路径保留能力标志（`PoolEntryForm.vue` 回写合并 `prev.vision === true` 时保留原条目），
故该形态在 UI 刷新模型列表后仍存续。

生效路径：`ac-config` 目录 watch → 防抖 reload → `config/changed` → `ac-llm-pool` 内容签名
diff 重挂 provider（`modelMeta` 进签名，热更即生效，无需重启）。
