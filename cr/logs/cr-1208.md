# cr-1208 删除级联失效——根因诊断与修复面

## 现象
- 用户反馈：会话删除不级联（删 agent 不删其会话面、删会话不删快照/登记），孤儿全靠人工算法追。
- ac-file-snapshots 无 GC + 删除链路 RPC 事件零级联。

## 事实链（全部核过源码）

### 断裂点 A：快照级联是死接线（最重）
- 删除 RPC 全在宿主进程：singles/delete、group/delete（ac-host-rows）。
- 但只 web.broadcast(type, {args})——WS 帧发前端，不 ctx.emit（ac-web-server/service.ts broadcast 774 行：纯 ws.send 循环）。
- 而 ac-file-snapshots 装载在壳进程（ac-shell-rows COMPANION_ROWS fs-tools 伴生行），构造器里 ctx.on 订阅的是壳内事件总线。
- 宿主进程没有任何代码 emit singles/updated / group/deleted 到事件总线；bridge-events.ts 只是 WS 帧格式映射表，不回灌总线。
- 结论：壳内订阅跨进程不可达，级联从未在生产触发过。测试全绿是同进程 ctx.emit 自导自演——测的是「订阅注册正确」，没测「生产 emit 方存在」。

### 断裂点 B：agents/delete 无会话面级联
agents/delete RPC（agent-admin-row.ts:128）= agents.removeAgent(id) = rmSync agents/<id>/ 整树（agents-row.ts:133）。
删掉：config、entries（timer.json 等）、docs、avatar、本侧全部会话目录 agents/<id>/sessions/。
不删（孤儿）：
1. meta/sessions/<sid>.json 中该 agent 的会话元数据——agent 域消失后 listIds 并集不再捞它，成为不可见孤儿堆积在 meta 目录。
2. 对端 agent 会话目录 agents/<other>/sessions/<sid>——单方会话在多 agent 域有副本，删本侧不清对端 → 对端 listIds 并集把会话重新捞回列表（幽灵会话）。
3. 群成员流残留：gid~<removed-agent> 目录留在其他成员域；群名册仍含已删 agent id。

### 断裂点 C：无 GC
- file-snapshots 908 目录 vs meta/sessions 163 会话——745+ 孤儿快照已在生产数据根堆积（2026-11-22 实测 workspace/home）。
- PERSISTENCE_TREES 收录 file-snapshots 只解决检索噪音，不解决增长。

### 既定裁决面（修复对齐）
- cr-376 级联接线——测试有效但生产链路断裂。
- cr-1184 未读计数连带清（clearUnread）——「删除即清理」先例。
- cr-600 分居（meta/sessions + agent 埍）——群成员流键 gid~member 住 agent 域。
- cr-1100/1120 词汇锁——meta/sessions 只收裸 sid json；listIds 锁 uuid 形。
- data-root-layers 契约——file-snapshots 第一层必须备份；GC 只清孤儿，不清活会话快照。

## 待裁决点（见会话提问）
1. 删 agent 的会话面：硬删全部（含对端副本）vs 软删归档。
2. 群内成员被删：移名册 + 清成员流 vs 保留历史。
3. 存量 745+ 孤儿快照：boot 对账清理 vs 保留。

## 影响面（修复涉及）
packages/ac-file-snapshots（级联接线改宿主侧 + dropConversation 供 RPC 调）、packages/ac-host-rows（singles/agents/group RPC 级联）、apps/host（boot 对账）、tests 同步。

## 修复落地（C1 + G3 裁决）

### 根因
级联挂在事件上，但事件只走 web.broadcast（WS 帧到前端），消费方订阅在壳进程的总线——跨进程不可达。归位错误：删除是宿主写权，级联应随删除 RPC 同进程执行，不是事件。

### 改动面
- ac-file-snapshots/src/index.ts：删 cr-376 死接线（singles/updated + group/deleted 订阅）与 memberStreamKey 依赖；dropConversation 注释改指宿主 RPC。
- ac-file-snapshots/package.json：删 ac-core-utils 死依赖。
- ac-host-rows/src/singles-row.ts：singles/delete 直调 SnapshotStore.dropConversation（face-ops 同款 owning 纯库形态，非服务依赖）。
- ac-host-rows/src/groups-row.ts：group/delete（gid 本体 + 全成员流键）/ group/leave（该成员流键）直调 dropConversation。
- ac-host-rows/package.json：加 ac-file-snapshots 依赖。
- 测试：ac-file-snapshots/tests/integration.test.ts 删自导自演用例（改由宿主行测试验收）；singles-row/groups-row 测试补快照目录级联断言。
