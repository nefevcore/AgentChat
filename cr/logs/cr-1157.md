# cr-1157 · unread 计数器方案实施

> 性质：功能重设计（cr-1152 下线后）｜状态：doing→done｜2026-11-19
> 关联：→cr-1152（消费面下线）、→cr-1146/1150/1151（被取代的权威源路线）、计划档 docs/design/session/unread-counter-plan.md

## 裁决（用户定案）

1. 抛弃精准对账，未读 = 事件计数器 + 同步清零，语义降级为 hint（错计不致命，消息本体永远落账）。
2. host 缺席窗口漏计接受（single 会话为主）；壳收束补发闭环属新需求不做。
3. 事实源做成可扩展注册表形态（三源起步：run/settled、独立私信、群消息）。
4. 同步时机 = 重连对齐 + 慢周期兜底（10min），不做严格高频 take。
5. 幂等键必须有（lastKey 最近事件键去重，挡 at-least-once 重投双计）。

## 实施（四批）

1. 纯库换血 ac-core-utils/src/unread.ts：version 2 计数器（bumpUnread/takeUnread/clearUnread + lastKey 幂等 + 原子写 + 损坏留档）；version 1 读位数据作废（读为空表 + 留档）。测试 cr1157-unread.test.ts（10 用例）替换 cr1146 旧测试。
2. host 三源挂点 + RPC：tap 桥 run/settled（轴键归一：~ 直用/uuid 直用/其余 agent~user）、user 桩 onStandalone 私信、groups-row group/send（from!==user 门控）→ bumpUnread；web-api 注册 session/unread（take）+ session/mark-read（定向清）。群 post 帧载荷补 message（前端 live 帧既有解构 [gid, message] 本就期望双参）。
3. 前端徽章面重建 unreadStore.ts（独立于 feed-core，自订阅 wire 流：take 水合 + live bump + 10min 慢周期 + markRead）；ConversationService 挂载 + watch activeDialogId 进会话即清；SessionsClientFace 补 unread 契约面；AgentList.vue Agent/群行角标。
   - 微调批（用户追加）：ActivityBar 双按钮角标——agentsTotal（对桶+群轴，名册行口径）/ sessionsTotal（single uuid 轴）双路聚合，词法归 unreadStore（SINGLE_SESSION_ID_RE 同源），ActivityBar 零词法知识消费。
4. 收尸 ac-session-index：谓词四列/SQL 常量块/refreshUnread/unreadCount/cr1151 等价性测试整体退役（refreshConversation kinds 参数同撤——indexLine 回纯指针职责）；session-design.md §11 重写为计数器方案；unread-authority-plan 归档状态行改「已被取代」。

## 修二（用户实测反馈）

现象：1) unread 双倍；2) 非 user 会话（news~news）计数流入 user 会话（news~user）。

根因：settled 源门控缺「viewer 参与会话」判定（cr-1144/cr-1057 既有口径，本 CR 初版漏抄）：

- 双倍：news 定时 run 在 news~news 自会话收束被计入（轴 news~news）——徽章聚合把 a~a 折算到 Agent 行，与 send_agent(to:'user') 私信（news~user 轴）合流 = 同一行 +2；
- 串台：群成员 run conversationId = gid，被「其余 → agent~user」回落错拼进直答对桶。

修法（host host-web settled 门控 + 前端 axisKeyOfFrame 同款双面）：

- 含 ~ 对桶须一端为 user 才计（自会话 a~a 机制 run 与 agent⇄agent 对不计——动静走 roster 活动面）；
- g- 群轴不计（群由 group/message-posted 单源计，settled 再计即双计）；
- 补「正在看的会话不计数」（cr-1057 原语义——live 已可见）：unreadStore 增 setActiveAxis（装配方注入 axisOf 单源映射，与进入即清共用）。

回归：unread-store 6 用例（新增自会话/agent 对/群 run 三负路径 + 活跃轴门控）；conversation 全量 + e2e-stream 318 绿。

**修二之修（判据单源）**：修二初版把门控词法在 host 闭包与前端 store 各写一份——正是「重复两份迟早走散」，且初版两个 bug 本身就是漏抄的后果。判据下沉纯库 `ac-wire-format/src/unread-axis.ts`（`unreadAxisKeyOf` / `userPairAxisKey`），宿主 tap 桥与 webui 前端同源消费。

- 归位理由：轴键归一 = 「帧 (agent, conversationId) → 计数器键」的投影，属线格式词汇；且本库零 Node 依赖。
- **不能住 ac-core-utils**：该包依赖 ac-plugin-core（node:fs），前端行 import 即被 vite 判为浏览器外部模块——`build:channel` 当场 `readFileSync is not exported by __vite-browser-external` 构建失败（实证）。前端可消费性是纯库选型的硬约束，`pnpm --filter ac-ui-app build:channel` 是这类改动的必跑门（typecheck 看不见它）。
- **真实数据实证（362 会话跑判据）**：`news~news` / `admin~news` 等 agent 对 / `g-…~news` 群成员流全部正确排除；但暴露一处兜底缺陷——非标准键（历史探测残留 `probe-conflict-*`）被「其余 → pairKey」猜成 `news~user`，与用户报的串台同族。判据收紧为「未知形态不猜」：只有 `conv === agent`（旧形态直答）才归对桶，其余一律不计。
- 回归：ac-wire-format 新增 `cr1157-unread-axis.test.ts` 7 用例（自会话/agent 对/群轴三负路径 + viewer 对桶正路 + single/旧形态 + 排序归一）；core-utils 与 wire-format 两包 + store 共 72 用例绿；conversation + e2e-stream 318 绿；typecheck / check:deps / eslint 全绿；build:channel 通过。

## 已知边界

- host 缺席窗口漏计（裁决接受）；多端吞没（一端 take 全局清）。
- 群消息源只挂 group/send RPC 面——群内 Agent 回复经信封扇出触发的 run 收束由 run/settled 源覆盖。
- bump +1 即写盘（事件频率 = run 收束级，成本可承受）。
