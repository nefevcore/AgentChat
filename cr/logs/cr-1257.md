# cr-1257 沙箱假阳性：切段不感知引号致正则交替 | 误切段（ISSUE-31）

## 复现（修复前，2026-11-23 用户报告 + 探针确认）
- `Select-String 'a|\[b\]'` → BLOCK（Unix 绝对路径 /[b/]）
- `sls 'a|\d+'` → BLOCK（/d+）
- `grep 'a|\\b'` → BLOCK（//b）
- `sls 'a|b\[c\]' f.txt` → PASS（对照：\ 前有 b，归一后段首非 /）
- 引号内外无差（如 `cat 'a|\w+/x'` 同拦——切段本就不感知引号）

## 根因（三因叠加）
1. `bashCommandViolation` / `isLowRiskCommand` 的切段 `split(/[;&|]|\n/)` 不感知引号：
   引号载荷内的正则交替 `|`（Select-String/Grep 日常写法）被当命令分隔符切段；
2. 切出的段以正则转义 `\` 开头（`\[` `\d` `\w`），上一步 `.replace(/\\/g, '/')`
   反斜杠归一化使段首变 `/`；
3. 路径启发式 `(?:^|\s)\/…` 的 `^` 恰命中段首 → 判「Unix 绝对路径」整条拦截，
   报错把人引向不存在的越界路径。cr-1224 只修了 node -e/python -c/pwsh -Command
   载荷剥离，通用引号串内切分没覆盖。

## 修法（根因在切段语义，不在路径启发式）
- 新增 `splitSegments()`：引号感知切分（' " 内的 ; & | 换行不拆段）；未闭合引号
  原文不拆——只可能多拦不可能漏拦（fail-closed 保持）。
- `bashCommandViolation` 与 `isLowRiskCommand` 两处切段统一换用；两函数此前各自
  重复同一段切分代码，并源。
- 路径 token 判定不变：仍以 \s 为界（负 lookbehind 吃引号字符），引号内空白前导
  的路径（`-Path ' /etc/x'`）、引号外实参路径（`Select-String '…' /etc/x`）、真管道
  （闭引号后的 |）全照拦。取消此前对无空白前导 token（`a|\w+/x` 形）的误拦——
  那是切段事故的产物，非设计拦截目标。

  `\` 归一化，效果与单反斜杠同——与主根因（切段）无交互。
