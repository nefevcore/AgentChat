# 随机抖动类定时修复的验收范式（2026-11-23 沉淀）

来源：cr-1231（jitter 同刻度重投）验收过程。双方在判据上各错多次，最终收敛为六道闸。
适用于任何「jitter / 随机偏移 / 重采样」类机制的修复验收。

## 核心教训先行

**方向对只是必要条件之一。** 还必须确认：样本真产生过、产生时代际可辨、
该样本对新旧实现**可区分**。缺任何一条，结论都会假绿或假红。

反例（本轮实际发生）：
- 把「一个必要条件」当成「充分条件」→ 区间判据漏了「样本是否存在」
- 把「方向正确」当成「样本有效」→ 正偏样本对旧 bug 零鉴别力（22:34:22）
- 把「区间不重叠」当成「可判」→ 未验「该时刻 ngs 是否仍指向同一格」

## 六道闸（顺序不可颠倒，任一不过 → 判「样本作废」，**不判「修复失败」**）

### 闸0 装载闸：修复代码是否在跑

```
宿主 bootAt > 修复包 mtime    → 否则只能报「未装载」，「修复无效」结论不成立
```
宿主代际**读 `workspace/home/.runtime/host-facts.json` 的 `bootAt`**。
- 不扫进程：壳命令行含 `--host-boot <宿主boot.ts>`，按路径匹配会命中全部壳
- 不看 `activation.lock` mtime：被壳持续 touch，不等于 boot
- 附自洽校验：`|facts mtime − bootAt| ≤ 60s`（独立第二证据源，抓「改了字段没改 mtime」）

壳侧包须查**该 Agent 壳的 boot**（`activation.lock` 的 `acquiredAt`+`bootId`）——
命令沙箱等由 `ac-shell-tools` import 的修复按壳生效，逐壳重启才装载。

### 闸1 发生闸：样本是否真的产生

```
lastFiredAt ≈ 目标时刻  且  firedCount 递增
```
不过则「样本不存在」——可能被重启重采样改点、或投递失败。
**禁止据此判修复失败**（本轮 04:47:09 就因 23:44 重启而消失）。

### 闸2 代际闸：arm 时刻是否使样本保持鉴别力

```
arm 时刻（= 最近一次宿主 boot，因为 boot 会 re-arm）< ngs(lastFiredAt)
```

**边界随样本变化，不是常数。** ⚠️ 本文件初版误把 cr-1231 首个样本的边界 07:30
写成固定值——那是 `ngs(05:20:58)` 恰好等于 07:30 的**巧合**。

理由：`boot ≥ ngs(lf)` 时 `ngs(boot)` 跳到下一格，新码消费判定不触发，
**旧码与本格同形**，cand 区间与「生效」重叠 → **假绿**。

两个样本的实测边界：

| 样本 | lf | ngs(lf) = 边界 |
|---|---|---|
| ① | 05:20:58 | **07:30** |
| ② | 13:23:54 | **15:00** |

样本② 实测：重启于 14:00 → 可分 ✓；重启于 15:00/15:30/18:00 → 不可分 ✗。
若按固定 07:30 判，15:30 的重启会被错判为「通过」，实际是假绿。

### 闸3 鉴别力闸：该样本能否走进修复分支

```
|lastFiredAt − ngs(lastFiredAt)| ≤ jitter
```
不满足则新码**消费判定不触发**，行为与旧码完全相同 → 不可鉴别。

⚠️ **「负偏」不是鉴别条件**（本轮最大认知修正）。消费判定用的 grid 是
`ngs(投递时刻)`，不是 arm 时的采样格。cr-1231 实测：投递点 ∈ [05:15, 07:30) 才可鉴别，
04:00~05:14 虽也是负偏且会复现旧 bug，但消费不触发 ⇒ 新旧同形。

### 闸4 判别闸：新值须落设计区间**且排除旧码区间**

```
先算两个区间，确认互斥（重叠即无鉴别力）
新码区间：消费本格 → 下一格 → [grid_new ± jitter]
旧码区间：不消费 → 本格 → [grid_old ± jitter]
实际值落新区间 → 生效；落旧区间 → 无效；其他 → 作废
```
cr-1231 实测：新 [12:45,17:15] / 旧 [05:15,09:45]，实际 13:23:54，
**高出旧码上界 218.9 min** ⇒ 彻底排除旧码。

### 闸5 弱判据不可单用

「同一时刻是否只投 1 次」鉴别力极低。cr-1231 中旧码在该格立即重投概率仅 2.21%，
投 1 次是 97.8% 的常态结果，**等于没验**。

## 附录：arm 时刻 ≠ persisted armedAt

`state.json` 里的 `armedAt` 是条目**首次装载**时刻（cr-1231 实例：11-21 00:26:51，
比实际 arm 早 23.5 小时），**不能用来算采样格**。
采样格须用**那次 re-arm 的宿主 boot 时刻**去算 `ngs(boot)`。

## 附录：根治方向（ISSUE-30）

上述闸1~闸4 全都在补偿「timer 无 arm 日志」这一个缺失。
**arm 时记一条 `[timers] arm key=… grid=… cand=… lf=…`**，事后直接读日志，
所有反推可废。建议顺序：**先 arm 日志，再诊断 API**——否则 API 会固化一堆推演逻辑。
