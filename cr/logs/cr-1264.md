# cr-1264 net-monitor 判定排除虚拟宿主网卡 + 闸门端点 DNS 预检

## 事故（2026-11-23 午间）

用户中午回家物理断网（无 WiFi），news 五档午间速递（12:00–14:00）全部
以 `fetch failed ← ENOTFOUND api.deepseek.com` 重试形态收束（≈2.7s/档）——
cr-1158 离线闸零触发：整个事故期 net-monitor 判定恒 online、零翻转记录。

## 根因

本机 VMware 宿主虚拟网卡（VMnet1/VMnet8）持有与上行无关的常驻静态 IP，
物理断网时依然 Up——`analyzeInterfaces` 的 `hasAddress` 判据被永久饱和，
离线闸与 DNS 兜底永不启动。属 cr-1158 fail-open 抉择（「虚拟网卡如实计入」）
在虚拟化开发机上的结构性失效。

## 用户裁决（2026-11-23）

1. 主修：判定排除宿主虚拟网卡（名称模式 + MAC OUI 双判据）；误判安全网
   = 既有 DNS 漫游窗口 + 端点预检 fail-open。
2. 加固：闸门在线期对调用端点 host 做单次 DNS 预检（race 超时三态，
   fail 拒绝 / timeout 放行）——覆盖「连接在、DNS 坏」形态（历史日志
   单日午后一档 ENOTFOUND 十余次同源）。

## 实现要点

- waterfall 监听器必须同步返回 AsyncIterable（本 cordis waterfall 同步透传、
  消费方 `yield*` 直接委派）——预检住异步生成器内：首块前抛错 = 拒绝，
  dispatch 零执行。
- 预检只拒确定解析失败（fail）；timeout 放行——慢 DNS 不拖累调用，
  fetch 自会解析。
- 本地/私网端点与 IP 字面量 host 无 DNS 环节，不预检。
