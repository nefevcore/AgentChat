# cr-1158 网络状态监控（无网络禁止调用网络模型 API）

## 动机

无网络状态下定时唤醒照常投递，壳内模型调用挂协议超时（180s × 重试）才失败——白白烧预算、错误信息不可读。用户需求：监控网线/WiFi 连接状态，无连接时禁止调用网络模型 API。

## 用户裁决（2026-11-19）

1. 恢复后不自动重放积压唤醒（防调用风暴）。
2. 本地/私网豁免清单用缺省（localhost/127.0.0.1/::1/10.*/192.168.*/172.16-31.*/fe80/fc00::/7），无自定义网关。
3. DNS 探测不得影响使用体验——在线期零探测（判定只看网卡信号）；断网时的 DNS 兜底若持续超过 1s（EWMA）即停用，判定退回网卡单源。

## 设计要点

- **闸门位置**：llm/before-chat waterfall（契约三姿势之一「抛错 = 拒绝」）——不在 timers 行锁死定时器（探测循环本地纯函数零网络依赖），不侵入 ac-llm 内部。摘除本行即恢复现状（零改动可摘）。
- **在线期零 DNS**（裁决 3 落地形态）：两段式调度——上轮 verdict.wantDns 决定本轮是否发 DNS；在线恒 false。断网确认需「连续 2 轮网卡无信号 + DNS 失败」双证据。
- **EWMA 自适应停用**：断网期探测延迟指数平滑 >1000ms → dnsDisabled，此后不再发 DNS（防持续慢探测骚扰），判定退回网卡单源。恢复 online 时记账重置（换网环境给新 DNS 一次机会）。
- **失败语义**：闸门抛错 → chat() 首块前失败上抛 → loop 构造保真失败步，run 明确收束（毫秒级，替代 180s 挂起）。
