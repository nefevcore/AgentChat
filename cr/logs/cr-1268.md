# cr-1268 P1-2 签名滚动哈希

- 日期：2026-11-23 · 批次：session-render-pipeline-plan §四 P1-2 · 标签：#render-pipeline · 前置：cr-1267

## 动机

P1-1 收编后的已知盲区：strLen 词形只取长度——等长异容替换（'aa'→'bb'、消息整体重写）
签名不变 → buildTurnsIncremental 误判"无变化"复用过期 turns。计划 P1-2 = 长度身位升级
djb2 滚动哈希（O(1) 可增量），等长异容触发重建。

## 改动面

- `feed.ts` 串身位机制块（P1-1 词表架构内的纯替换）：
  - `djb2Fold(h, s, from)`：djb2 多项式滚动（h*33+c，Math.imul 32 位）——多项式形态使前缀
    扩展可从旧哈希续算尾段（增量性）；
  - `STR_SIG` WeakMap 值缓存：宿主对象 × 字段名 → { ref, h }——值相等（memcmp 级命中，
    免写回）/ 前缀扩展（流式追加 O(delta) 折叠）/ 全量重算（首算/替换/等长异容）三路径；
  - `strSig` 输出 `${len}:${hash}` 双身位——长度保旧灵敏度，哈希补等长异容；
  - 词形 sigFn 首参升为宿主对象（`(_host, v)`），strSig 缓存挂靠消息本体；toolCalls 深位
    的 result/label 同走 strSig（tc 宿主）；`SCALAR_APPLIER` 收窄（strLen 出队，msgSig 循环内
    特判走 strSig）。
- `tests/signature-single-source.test.ts` +3 用例：
  - 等长异容身位层（content/thinking/label/reasoning_content/toolCalls.result/toolCalls.label 六点）；
  - 等长异容拼装层（'answering'→'answered!' 末轮重建 + 内容刷新断言）；
  - 前缀扩展增量 == 全量重算对拍（djb2 增量性验证）。

## 裁决记录

1. 值缓存而非每帧全量哈希：全量 djb2 是 O(len)——流式追加每帧全算会把 P1 的 O(1) 性能
   核心打穿；缓存 + startsWith 前缀判定把追加场景压回 O(delta)。
2. WeakMap 挂宿主对象（消息/toolCall）：生命周期随宿主，不污染数据对象，无清理代码
  （注册中心代管同款哲学）。
3. `len:hash` 双身位而非纯哈希：长度变化零成本可检（哈希同长也可能巧合相等，双身位
   降碰撞）；输出仍是短串， TurnsMemo.sigs 体积可控。
4. TS2454 教训：settled 标志与 h 成对赋值的关联对定赋值分析不可见——三分支单出口
  （next !== c 指针判等免写回）后通过。
