## 发现与补缺

### 1.（严重）cr-1306 归一工具丢 session-header 头行——218 文件

**发现**：复扫新增「无头文件」口径后现身：218 个 messages.jsonl 首行直接是 run-end 行。
备份对照实证：cr-1306 备份原件 218 文件全部有 `session-header version:2` 头行。

**根因**：`normalize-segment-rows.mjs` L109 `const { rows } = readLedger(s.dir)` 只解构
rows——header 被丢弃；staging 只写 `finalRows`（L148）；原子 rename 后头行永失。丢失
内容 = version/createdAt/participants/kind + migrated 追溯标记。

**为何历轮测不出（三层盲区）**：
1. 对拍判据（foldStepsOf 投影恒等）不含头行——投影按 type 行级判别，头丢失投影不变；
2. 复扫口径只查 `version===1`——无头文件不是 v1、不报、静默漏过；
3. `domainFactsOf` 的 version 参数仅记录（行为按行 type 判别）——读路径无红。

**影响面**：投影恒等（行为无损，测试全绿的根因）；但三重契约破坏：migrate-sessions-v2
幂等键失效（无头 ≠ v2 头 → 会被重迁）；readDomainFacts 回落 version ?? 1；元数据永失
（备份在场可恢复）。218 文件全为僵尸会话（段行止于 2026-11-09），无活跃写面。

**修复（四件）**：
1. 工具保头根修：readLedger 解构 header + staging 首行写回（原样保真）；
2. 数据恢复：备份头行原样写回 218 文件首行（+ restoredBy:cr-1308 标记；行数守恒
   守卫防错配；staging+rename 原子写）；
3. 迁移工具无头防线：无头但行面为 v2 事件行 → 显式 residue 态 fail-loud（不再
   落回 version ?? 1 被误当 v1 重迁）；
4. 复扫口径修正：§六判据补「无头文件单独计」。

**验证**：复扫无头 = 0（1544 文件：v2 1543 + v1 1〔admin/_backup 手工副本非管线路径〕）；
migrate-sessions-v2 --dry 复证 1543 v2 跳过 / 0 可迁 / 0 错误（幂等恢复）；ledger-doctor
error 0 / warn 9687（seq-space 既有形态，全部未归一化会话——与 cr-1306 判读一致）。
