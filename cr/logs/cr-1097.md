## 第二轮：新增全局设置（用户需求）

### 架构裁决

壳内 config 是启动快照（无 watcher）——UI 保存走宿主进程内 ctx.config（热），壳不感知。故 dev 开关合成 = **宿主拉壳时读 config 注入 env**：

- 键：`settings.devMode`（config.json——`CONFIG_KEY_PREFIXES` 白名单 `settings` 前缀已在，UI 可写面零改动）。
- 宿主 boot 建 `devModeOf` 闭包（ctx.get('config') 现取）传入 createOrchestrator。
- 拉壳链：spawnInputOf 每次 ensureAgent 现取开关 → adoptShell 入参 `devEnv` → SpawnFn 第四参 → spawnOpts 显式合成 env（`{...process.env, AGENTCHAT_DEV_MODE:'1'}`）。
- 生效语义：**新拉壳即时生效；已活壳 env 已定不受影响**（UI 文案明示需重启后端）。子 Agent 与父同进程继承，不可逃逸。
- env 原生直启路径（`$env:AGENTCHAT_DEV_MODE='1'; pnpm dev`）继续有效——config 态与 env 态同值域，宿主注入不覆盖用户显式 env（合成方向 extraEnv 后置，显式 env 优先级等同）。

### 改动面

- `apps/host/orchestrate.ts`：SpawnFn 第四参 env + spawnOpts(extraEnv) + adoptShell input.devEnv + 调用点透传。
- `apps/host/orchestrator.ts`：OrchestratorOptions.devModeOf + spawnInputOf 合成 devEnv。
- `apps/host/boot.ts`：devModeOf 闭包（config 现取）+ createOrchestrator 传入。
- `packages/ac-client-ui-settings/client/`：新增 GeneralSection.vue（开关 + 保存 config/save settings 域 + 重启提示）；index.ts 注册「通用」节（settings:section，order 10 头位）。

## 第三轮：restart 快路 env 注入 bug（端到端验证发现）

### 现象

端到端验证：tester 壳（开关开后首拉）拿到 AGENTCHAT_DEV_MODE 警示行；本壳（宿主 boot 时首拉、开关开后 restart 重拉）未拿到——同一宿主前后行为不一。

### 根因

devEnv 原注入点在 spawnInputOf（input 快照）：ensureAgent 幂等快路 `existing.restart()` 复用**首拉时刻**的 input 快照，快照上 devEnv 停留首拉时的开关态（当时 false）——开关翻转后重拉不反映。

### 修复

注入点挪到 adopter 包装层（devTagged）：每次 adopt（首拉/respawn/restart 死态重拉）现取 devModeOf()，config 热更后任意重拉路径即时反映当前开关态。SuperviseSpawnInput 补 devEnv 字段（supervise.ts 接口面）。

### 测试

orchestrator.test.ts 新用例：首拉 false → 开关翻 true → 壳 exit(0) done 态 → ensureAgent 死态重拉 → 断言第二次 input.devEnv = {AGENTCHAT_DEV_MODE:'1'}（锁定快照停留 bug 形态）。21 用例全绿。

### 遗留

- GeneralSection 的 onToggle 先 getGlobalConfig 再整写 settings 域（防覆盖 permission-gate 等兄弟键）——config/save 白名单域 replace 语义下的防御性整写，若未来 settings 域键增多可考虑 config/set 单键写。
