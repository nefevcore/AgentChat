# cr-1201 vitest 测试时区显式收口为配置项

## 动机

cr-1198（ac-datetime 用例 UTC 硬编码对产线 DEFAULT_TZ 漂移）揭示的模式：
测试隐式继承宿主 TZ，dev 机（Asia/Shanghai）与 CI runner（缺省 UTC）各随环境，
日期窗口类用例随环境漂移而静默失效。TZ 在测试基建中无处显式声明——下一个
同类 bug 的培养基。

探查存量面（2026-11-22）：同构「测试复制产线口径」样本两处（pipeOf 复刻
socketPathFor win32 映射、usage-api 手写 UTC 日键）+ 轻度一处（timer-core
测试 TZ 字面量）——本 CR 只收口基建声明，不动用例；两活样本留待独立 CR。

## 裁决

- 挂点选 `vitest.config.ts` 的 `test.env`（与 AGENTCHAT_REPO_ROOT 同通道，
  序列化进各 worker），而非 run-tests.mjs——绕过编排器直接 `npx vitest`
  （定向跑的既定形态）也受保护。
- 缺省值不写字面量：`import { DEFAULT_TZ } from
  './packages/ac-core-utils/src/time-keys.ts'`——真单源，cr-1053 若改常量，
  测试基线自动跟随。
- 外部显式传 TZ 优先（`process.env.TZ || DEFAULT_TZ`）——保留「复现特定时区
  窗口」的口子（cr-1198 类 bug 恰需在真实窗口内验证）。
- 刻意不钉死唯一时区（如全局 UTC）：钉缺省 ≠ 关闭探测器——显式覆盖口子
  保留，而 CI 从「隐式 UTC」变「显式 Asia/Shanghai」后，CI 不再天然等价
  于 UTC 环境验证。

## 改动

`vitest.config.ts`：

1. 新增 import（DEFAULT_TZ 单源）；
2. `test.env` 新增 `TZ: process.env.TZ || DEFAULT_TZ`，附注释（cr-1201 +
   cr-1198 引用 + 为什么 worker 侧一致）。

## 验证

- Windows Node TZ 响应探针：TZ=UTC → GMT+0000；TZ=Asia/Shanghai →
  GMT+0800（本机完整响应，声明有牙齿）；
- 定向双探针（ac-datetime 12/12）：无外部 TZ → 钉 DEFAULT_TZ；显式 TZ=UTC
  → 外部优先。两路径皆绿；
- typecheck 全仓：0 错（4 个 TS18048 在未跟踪文件
  step-race-wipe.test.ts——他人在途工作，与本 CR 无关，未动）；
- 定向 lint：vitest.config.ts 不在 eslint 管辖（warning + exit 0，正常）；
- 全量 pnpm test：**466/466 文件、3453/3453 用例通过**（exit 0；报告头
  Start at 07:16 = 钉死后 Asia/Shanghai 时钟，真实 UTC 23:16——全量下
  声明确认生效）。
