# cr-1146 · 未读服务端权威源实施

日期：2026-11-17 · 状态：done · 标签：#session #webui · 前置：cr-1145（计划）/ cr-1144（计数收口）

## 动机

cr-1145 计划落地：未读从纯前端 live 帧计数态改为服务端权威源——读位持久化
（meta/unread.json）+ 计数恒派生 + 前端对账归一。修三类缺口：页面关闭期间的
产生不补计、多端读位不互通、计数与实际会话状态可漂移。

## 改动（四批）

1. **纯库** `ac-core-utils/src/unread.ts`：ReadMark 读位读写面（meta 域 JSON 单文件
   范式——损坏留档 + 原子写）+ `mergeMark` 水位单调取大 + `markRead` 写口 +
   `unreadOf` 未读派生纯函数（事实行谓词 role agent/assistant 双认、非 user 入站、
   非段/注入/空终稿、须有 message_id 锚；判重与 projectUserReplay 同源）。
2. **RPC** `ac-host-webui/src/web-api.ts`：`session/mark-read` 注册（水位单调落盘）；
   `session/history` 首屏（offset=0 全量）旁带 `unreadCount/readMark`（unchanged 短路
   与上翻不带——字段缺席 = 不对账）；新增 `session/unread` 批量对账（读位会话 ∪
   账本会话目录，群流键按 meta/groups 过滤）。
   `ac-host-rows/src/groups-row.ts`：`group/history` 首屏旁带同款（群行集 = 成员流
   合并去重行；读位键 = gid 群轴）。
3. **前端** `ac-client-ui-conversation`：feed-core 水合/写穿/watchUnreadSnapshot 整块
   退役，换 `reconcileUnread`（init 期批量对账水合）+ `clearUnread` 发 mark-read RPC
   （锚 = 分区已见行最新 seq/尾部 persistedMsgId；空分区无锚不发）+ 历史首屏响应
   消费 unreadCount 覆盖（requestHistoryPage 与 loadGroupHistory 双路）；
   `unreadStore.ts` 删除；persistUnread 选项退役。
4. **多端验证** e2e：A 端 mark-read → B 端新连接批量对账 0；后读带旧水位不回退先读。
