# cr-1285 P3-4 直播挂靠并轨（session-render-pipeline-plan §四 P3-4）

> 2026-11-24 · #render-pipeline · 前置：P3-3（cr-1283 转换器单源）

## 动机与根因

注入卡挂靠三路径（刷新/直播/上翻）不同构：
- 刷新路径：run 归口注入卡（journal-inject 落账带 run 键）由投影时间全序落位在归属轮内——键控；
- 直播路径：`session/context-injected` 帧**不带 run 键**（`recordContext` emit 在查 `currentRun` 之前），注入卡落进 rawMessages 后由 buildTurns 的 curOwner 位置启发猜挂靠——cur 为空/viewer 轮/归属不匹配即挂错轮或降级独立卡；
- 刷新侧投影 event 行还把投影携带的 `run` 键丢在 toHistoryMessages（steps 行透传、注入卡本体不透传）——刷新后 run 归口卡同样退化为位置启发。

根因：直播帧与投影行没有共享同一个挂靠键（run），挂靠语义散在「投影落位 + 前端窗口猜测」两处。

## 改动面（键族贯通八处）

服务端（帧带 run）：
- `ac-shell-conversation/src/service.ts`：recordContext 把 `currentRun` 查询提前到 emit 之前，帧 meta 带 `run`（run 死窗口缺席——降级直落分支行为不变）；
- `ac-shell-conversation/src/events.ts`：事件声明补 `run?: string`；
- `apps/shell/boot.ts`：B3 帧白名单透传 `run`；
- `ac-envelope-core/src/stream.ts`：context-injected 帧词汇补 `run?: string`；
- `ac-post-office/src/stream-bridge.ts`：主线帧 meta 恒等透传 run。

前端（run 键挂靠主机制）：
- `client/types.ts`：InjectCard 补 `runId`；
- `client/historyApi.ts`：toHistoryMessages event 分支透传投影 `run` → runId（run 归口卡刷新路径同键）；
- `client/feed-core.ts`：帧 case 提取 run、showEventNotice 第 8 参 → 直播行带 runId；
- `client/feed.ts`：toInjectCard 透传 runId；buildTurns 注入分支新增 **run 键挂靠主路径**——
  - 预扫 `runsInWindow`（只认轮承载域行 agent/user/tool 的 runId——卡自身键不参与，防自证在窗）；
  - `runStepIndex`（cur 内同 run 已积步数）+ `runTurnIndex`/`doneRunStep`（flush 快照 run→轮映射与步数终值）；
  - 挂靠优先级：run 键（flush 轮尾挂 / cur 步位挂 / 延迟卡挂头）> anchor（cr-1132）> 位置启发（curOwner，旧后端帧兜底）；
  - 修复真 bug：run 轮已 flush 后的迟到卡曾误挂 curInjects（穿插会话中的无关轮）——runTurnIndex 回挂正确轮；
- `client/fallback-probes.ts`：新探针键 `inject-run-miss`（run 键在场但目标 run 不在窗口——剥键走启发，观察窗归零即删）。

## 裁决

- 挂靠机制终态 = **三层显式降级链**（run 键 > anchor > 位置启发），与 P3-1「键控单机制 + 显式兜底」同构；位置启发仅服务旧后端帧（无键）与窗口边界态（剥键挂探针），不改删——等探针归零后再评估退役；
- 预扫 role 过滤：event 行自带的 runId 不计入 runsInWindow——否则卡恒自证在窗、剥键路径不可达；
- run 死窗口注入（run=''）：帧无 run 键，与直落投影行（同样无 run 键走 anchor 派生）同形——两路径本就同构，无需特殊处理。
