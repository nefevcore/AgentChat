# cr-1301 性能采集口径缺陷：hidden 页面读数不能代表帧投递

> 2026-11-24 · #render-pipeline · 触发：cr-1299/1300 修完后的运行时端到端核实。

## 发现路径

cr-1300 完成后做运行时验证：本地浏览器开 `http://127.0.0.1:3830/` 读探针读面——
`inject-heuristic: {hits: 255, rows: 5}`（双指标读面已在位 ✓）。对照手机页：
探针仍为纯数字 `{98, 3}`（旧 bundle，预期），且 4s 零增长（cr-1299 已记）。

两者差异不该这么大——本地**空页**在无操作下仍以 ~8 hits/s 增长。
→ 查手机页可见性：**`document.visibilityState === 'hidden'`, `document.hidden === true`**。

## 机制（为什么 hidden 页必然冻结）

| 观测 | 机制 |
|---|---|
| `frameStats` 冻结在 57/117/30 | hidden 页 rAF 不回调 → 调度器 tick 不跑 → frames/commits 不增长 |
| 探针冻结在 98/3 | 探针在 `buildTurns` 内命中——computed 只被渲染求值；不渲染 → 不求值 → 不计数 |
| async eval 等待 rAF 挂死 60s | 同上（rAF 永不回调，Promise 永驻） |
| 手机页 `setTimeout` 亦不可靠 | Chrome 后台页 intensive throttling（1/min 级） |

## 结论修正（推翻 §九 一处推断）

§九 原文：「frameStats 生产 commit 恒 0 与此耦合（帧根本没到前端）」——**作废**。
冻结的真实原因是被测页面在后台，与帧投递无关。

推论：cr-1296 所述「静置期归零（3s 零增长）」与 cr-1299 的「世代 D 零增长复核」
同样只证明「页面被置于后台」，**不构成本文档任何关于帧链路/探针行为的正面证据**。
（cr-1299 的零 turn-gap-fallback 读数仍有效——那是**实测时点**的累计值，不依赖后续增长。）

## 对照实验（本地可见页 × 同一宿主，双指标）

| 时点 | inject-heuristic |
|---|---|
| 重载后 3.5s | `{hits: 10, rows: 5}` |
| 再静置 2.5s | `{hits: 30, rows: 5}`（≈8/s，零用户操作） |
| 数分钟后 | `{hits: 4560, rows: 5}`（**912 倍虚增**） |

**rows 全程恒定 5，hits 线性增长**——直接实证双指标设计意图：rows 是行身份轴（判读用），
hits 是重扫次数轴（画像 derive 成本，不可作缺陷计数）。

## 处置

- §九 遗留疑点段增「采集口径修正」段（作废原推断 + 复测前置条件）；
- §九 观察窗判读段增对照实验数字；
- §八 新增开放项 10：遗留疑点定性**待页面置前台复测**，在此之前不作 tap 链归因（原 cr-1297
  的疑点收敛结论降级为「未定性假说」）；
- 采集纪律（后续所有真机采集）：**前置断言 `document.visibilityState === 'visible'`**，
  hidden 直接判无效并显式报错——`probe.mjs` 已实现该门（`pageVisible` 字段入报告 + 控制台红字警告），
  **实跑验证**：针对手机 hidden 页跑 `--seconds 2` → 正确输出「✗ 无效采集」、`pageVisible: false`、
  `raf.frames: 0`（rAF 确证不回调）、`probesDelta` 全 0 且 `rowsDelta: null`（旧读面形状兼容分支亦验证）。

测量 + 文档修正 + `probe.mjs` 采集门（工具脚本，`node --check` + 实跑验证；无包内测试面）。
探针实现与构建产物无改动（cr-1299/1300 的改动已在上一批验证并生效）。
