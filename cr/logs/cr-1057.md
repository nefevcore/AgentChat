# cr-1057 流式回复未读增量

- **日期**：2026-11-13
- **标签**：#webui
- **状态**：done

## 现象

前端部分位置没有显示未读数字：用户在会话 A 发消息后切到别处，Agent 的回复在后台流式完成，但 AgentList 行徽章 / SessionList 行徽章 / ActivityBar·MobileTabBar 聚合徽章都不亮。

## 根因

未读增量（`d.unread += 1`）只存在于三条路径（`feed-core.ts`）：

1. `showInbound`（router/message-received 私信入站）——仅 pair 分区（`viewerRelevant` 判定）；
2. `showEventNotice`（机制通知/注入行）；
3. `group/message-posted`（群分区）。

而 Agent 对用户消息的**正常回复走流式帧路径**（loop/run-started → llm/delta → run/settled），该路径全程没有未读增量——`run/settled` 处理段只做收尾/系统通知/重拉。cr-291 的注释明言设计意图「前台切走只看别的会话 = 未读徽章已足够，不弹（通知）」，但徽章增量从未落地——该前提不成立。私信与群路径正常，所以表现为「部分位置」缺失。

## 修复

`run/settled` 正常收束（finish=stop）时补未读增量，口径与 cr-291 通知门控同源：

- `finish === 'stop'`（错误/中断已有红条反馈，与通知口径一致）；
- `keys.dialogId !== activeDialogId.value`（正在看的会话直播可见，不计）；
- `isViewerDialog(keys.dialogId)`（群已被 isUserConversation 过滤；agent⇄agent 对分区无徽章消费面，与持久化投影 `persistUnreadNow` 口径一致）；
- 不以 `text` 门控（对账补投形缺席 = ''，终稿以重拉权威行为准）；
- `ensureById` 保证分区存在（冷启动/刷新窗口收束帧先到也不丢）；
- `persistUnreadNow()` 写穿 localStorage（刷新恢复，与既有未读持久化链路同源）。

名册 lastMessage bump 无需补——直播路径 `onMessageEnd`（行 1273）已有，唯独未读增量缺席。
