# cr-1179 auto-title 命名过滤补 uuid 形会话键闸

## 动机

tester 巡检发现（11/21 00:10 host 日志）：定时唤醒投递到 `tester~tester` 自会话的注入消息，
每条伴生一对 `[E]` 噪音——`service-desk 报「会话 id "tester~tester" 非法（须 uuid 形独立会话键）」
+ `[auto-title] 标题请求送达失败`。根因：壳侧 auto-title 行（cr-672）以 `source==='user'` 为过滤，
但定时注入到 agent~agent 自会话的 run 也是 user source；对桶键（`a~b`/`gid~member`）与
`sub_*` 键会话同样走完「LLM 生成 → title.set 投递」全链，被宿主 singles 行 cr-1120 词汇锁
（assertSingleId）拒收——生成白花一次 LLM 调用，投递白开一次 ipc 连接，两侧各产一条 [E]。

## 裁决

- 闸门归壳不归宿主：宿主拒收语义正确（词汇锁是身份防线），根因是壳行发送面越界——在
  `stage()` 挂账前加 `isSingleSessionId(sid)` 闸：非 uuid 形键不挂账、不生成、不投递。
- uuid 判词并源：`isSingleSessionId` 从 ac-host-rows/singles-row.ts 本地函数并源到
  `ac-ledger/src/user.ts` 导出（壳行与宿主行同源——两侧各持一份正则必走散，正是本次事故的
  结构性温床）。宿主行删本地实现改 import，行为分毫不变。
- 其余 5 处 uuid 局部正则（ac-client-ui-conversation client 面 / ac-wire-format /
  ac-session-index / envelope tests / llm-pool tests）分层定位正确（webui 前端与协议层
  不宜依赖宿主侧账本库），保持现状——它们是同形判词各自领域的单源，不属本次并源面。
- 会话标题需求的正确形态：singles 清单身份 = uuid 键；agent 域标题（对桶/自会话）归宿主
  派生面（读时投影），不经 title.set——与 cr-672 注释「agent↔agent / 机制触发会话的标题归
  宿主派生面」的既定口径一致。

## 改动面

- `packages/ac-ledger/src/user.ts`：+`isSingleSessionId`（uuid v4/v7 形，cr-1120 判词移驻）
- `packages/ac-host-rows/src/singles-row.ts`：删本地判词，import 自 ac-ledger
- `packages/ac-shell-rows/src/auto-title.ts`：`stage()` 挂账前加 `isSingleSessionId` 闸（cr-1179 注释）
