# cr-1248 预授权 full 倒挂：注入分级（知情通过即 full）

## 动机

测试反馈三项之一（pwsh 变量拼接绕过）排查出的深层机制：
预授权（会话键 approval=allow / Agent settings / 全局 config onAsk=allow）
把 risk=ask 的命令直接注入 full-access（cr-1082「通过即 full」），executor
按 full 档跳过命令扫描。组合效果 = **权限倒挂**：
- 坦白的字面量命令（get-content 在只读白名单 → risk allow → 直通）撞 bash-scan 被拦；
- 变量拼接命令（含 $ → 白名单失效 → ask）经设置链 allow 拿 full 免检通过。

## 裁决（修订 cr-1082 为「知情通过即 full」）

| 门路径 | 注入 | 依据 |
|---|---|---|
| 设置链 allow（预授权） | **sandbox-access** | 运营者预授权的是「类别的执行」，没看过具体命令；免弹卡但保留命令扫描/写白名单/readDeny |
| run 缓存命中 | **sandbox-access** | 缓存兑现「本轮免再问」，后续命令与首条不同、人未逐条看过 |
| 人工弹卡批准 | **full-access**（不变） | 弹卡 payload 含完整 command/args = 知情授权；cr-1071「批准后不撞沙箱墙」保留 |

先例：Claude Code「sandbox auto-allow」（沙箱内命令免弹窗——批准与边界解耦）、
Codex（--ask-for-approval 与 --sandbox 正交——never 只关弹窗不关沙箱）。
