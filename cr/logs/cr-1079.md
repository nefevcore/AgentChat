# cr-1079 权限门无人语义重构 + 设置链四层

## 动机

- 用户裁决（2026-11-14 会话）：①「无人」= 当前会话是否存在人类参与，非 self 词法形态；②新增全局权限配置层。
- 事故现场：news（30 分钟轮巡 Agent）机制 run 落 news~news 自会话，权限门 cr-1066 的 D7 实施把 self 判定前置到设置链之前——19 身份部署的 onAsk=allow 对机制 run 全部失效（写了个死配置）；agent~agent / 群会话这种真无人格反而走有人桶 → 弹卡 → 永挂（审批卡无超时，cr-1046 式泄漏面）。
- 溯源：D7 原文「无人桶恒拒 even 设置 allow」是 cr-1063 计划期裁决，cr-1066 实施时按字面义前置判定（关键裁决 #2 + V5 守护测试锁定）。设计语义「拒」正确（fail-closed 三选一最不坏），「恒」（不可预授权）超出业界惯例（Claude Code 等无人模式恒与预授权生效配对）。

## 改动面

- ac-agents/service.ts：新增 `humanPresentOf(conversationId)` 无人语义单源——恰两段且任一段 'user'（a~user 两向）或无 '~' singles sid = 有人；self / agent~agent / g-<gid>~member = 无人。**仅权限门 D7 消费**。
  - 交互裁剪轴（formDeniedBy/requiresInteraction）**保持原语义**（只裁 self 桶）：群聊/agent~agent 里用户可能在界面看着、ask_questions 是可回答的，与「审批卡审核风暴」不同轴——实施时曾误同时收紧，已收回并加断言锁定（cr-1079 实施中自我纠正）。`conversationFormOf` 保留（self 词法仍有消费语义），注释声明不再等价「无人」。
- ac-permission-gate/src/index.ts：决策序 5 重排——D7 无人桶判定从「设置链之前」还原到「s=ask 分支内」：设置链先行，allow = 运营者预授权（含无人桶——问不出的问题不问）；仅 s=ask（要弹卡）且无人 → fail-closed 拒，veto 文案指明三层解锁位。设置链四层：会话键 approval > Agent settings['permission-gate'].onAsk（settingsOf）> 全局 config settings['permission-gate'].onAsk（ctx.get('config') 软取——门行零硬依赖不变）> 缺省 'deny'（fail-closed，替代旧行 config 缺省 'ask'）。PermissionGateRowOptions.onAsk（行 config 层）退役。
  - **全局层为何门行自读**：壳侧 AgentsShim.settingsOf 只取 Agent 差异层（全局层参数传 undefined）——settingsOf 的全局合并只在宿主侧成立；全局设置必须门行直读 config 才能两侧同效。键路径与 Agent 侧文件（agents/<id>/permission-gate.json）同命名空间；'settings' 域本就在 config/save 白名单内，无需扩白名单。
- ac-conv-settings/contract.ts：approval 键 JSDoc 同步新语义。
- docs/design/session/permission-gate-plan.md：§一保留裁决行 + §二决策序更新（cr-1079 修订标注）。

## 语义对照

| 会话形态 | 旧 | 新 |
|---|---|---|
| a~user / user~a / singles sid | 有人（弹卡） | 有人（弹卡，不变） |
| a~a（机制 run） | 恒拒（even allow） | 无人：allow 预授权放行 / 缺省链尾 deny 拒 |
| a~b（Agent 间） | 有人（弹卡→永挂） | 无人：同上 |
| g-<gid>~member（群） | 有人（弹卡→永挂/审核风暴） | 无人：同上 |
| 全链缺省 | 'ask'（行 config 缺省） | 'deny'（fail-closed 第四层） |
