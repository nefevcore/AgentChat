# cr-1167 timer-v3 体验修补（预览诚实性 + v2 参数 fail-loud + 源缺位预警）

> 登记于 2026-11-20 · →cr-1161（timer-v3）→cr-1164（换轨）· 状态：done

## 动机

用户实测反馈三处体验缺口：① v2 写法 set({code}) 静默忽略——迁移者会误判生效；② previewFires 机械填满 3 条（once 同刻重复 / until.count 已截仍给 3 条）——预览不可当语义证据；③ test 对未安装源静默 fires:[]——无从区分「词汇错」与「源缺位」。

## 改动面

- **previewFires 三处诚实性**（ac-timer-core）：
  - once 单条去重（同刻不重复入列——once 推进无意义，首列即出局）；
  - until.count 截断 cap = min(n, count)——超出终结点的投递不存在；
  - 未来点过滤：过期 once（at ≤ now）不进预览（空列）；after-last 链式例外（链到期即投是运行语义）。
- **set 对 v2 遗留参数 fail-loud**（timer-face）：code/mode/time/hint/delay/delayMin/delayMax/repeatCount/activeHours 任一在场即报错——指明「本调用未生效」+ v3 用法 + test 预览指引。
- **test 源缺位预警**（timer-face + timers-row）：新 sourcePresent 查询面（物化 meta 在场判定，与 arm 的 dormant 判据同口径）；纯源触发器指向未就绪源时返回 warning「条目将 dormant，直到源行安装并产出数据」。

## 裁决

- 迁移不强求直译：v2 脚本条目在 boot 迁移时丢弃归档（timer.json.bak 留底）+ set 对 v2 参数报错指路——两道防线都把「Agent 重新用 v3 词汇设置」作为正路（用户明示接受）。
- 预览语义 = 诚实快照而非装饰：宁可给空列/短列，不说谎。
