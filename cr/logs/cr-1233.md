# cr-1233 · previewSystemPrompt 干跑泄漏（凭空 __pending__ 会话 + 水位吞噬）

## 现象（用户报告）
新会话还没发送消息，UI 上挂着两张注入卡：「日期」（日期锚）与「系统状态」（系统状态变化）。

## 根因
前端新会话是单例草稿态（哨兵 `__pending__`，首次发送才物化真实 uuid）。SystemPromptPanel 预览请求
在 single 上下文透传 `ctx.sessionId` —— 草稿态即哨兵键。链路：
  `agents/system-prompt` RPC（conversationId=__pending__）→ 宿主拉壳 → 控制帧 preview →
  壳 `previewSystemPrompt('__pending__')` → 真实过 `loop/before-run` waterfall。

waterfall 的副作用型订阅者不知道这是干跑：
- ac-datetime：recordContext 落日期锚 → **凭空创建会话目录**（哨兵键物化成真）；
- ac-env-pulse：水位初始化/推进 + delta 注入落账 → 同样凭空落行，且**吃掉真实 run 该收的注入**；
- ac-memory：快照注入 + 水位推进（同款泄漏，多会话记忆被预览消费）。

实测数据：`agents/__standard__/sessions/__pending__/messages.jsonl` 仅有 session-header + 两行 context
（05:51:22 日期锚 / 06:34:29 系统状态），零 user 行零 run 轨迹 —— 两次预览各落一行。

## 修法（根因：干跑面与副作用注入行的契约缺口）
`LoopRunRequest` 增 `dryRun?: boolean` 契约词；`previewSystemPrompt` 标记 dryRun: true；
datetime / env-pulse / memory 三个 before-run 注入行统一早退（装配链照常生效——预览语义不变）。

## 改动面
- packages/ac-agent-loop/src/contract.ts（dryRun 词）
- packages/ac-shell-conversation/src/service.ts（预览标记）
- packages/ac-datetime / ac-env-pulse / ac-memory src（早退）+ tests（回归锁：不落账/不写锚/不初始化水位，真实 run 照常注入）
