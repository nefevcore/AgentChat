# cr-1047 run-tests 新增 affected 档：git 变更反查受影响包定向跑测试

- 日期：2026-11-13
- 动机：项目扩大后全量测试随包数线性膨胀；不测又无法确定影响范围。把「跑哪些测试」从二选一变成按风险分档——affected 档用依赖图反查做测试选择（TIA），日常改动只付定向代价。
- 改动面：
  - `scripts/resolve-affected.mjs`（新）：变更集（工作树 vs upstream merge-base，`--base`/`AFFECTED_BASE` 可覆写）→ 包归属 → workspace 依赖图 BFS 反查 dependents → 含测试包目录（stdout，posix 相对路径）。结构域变更（scripts/、根测试配置、pnpm-workspace.yaml、apps/catalog/）exit 5 转全量——这些变更影响全测试面或须全量 + gen 校验（验证阶梯），不由依赖图推断。
  - `scripts/run-tests.mjs`：新增 affected 档——消费求解器输出作 vitest 路径过滤器，仍走根目录单进程 vitest（与全仓测试同一隔离模型；pnpm -r 并行在共享测试数据根上会踩踏，见原注释）。exit 5 → 全量；空面 → 跳过。
  - 根 `package.json` `test:affected` script；`README.md` 命令区；`.dsh/skills/agentchat-dev`（本地态技能同步）。
- 裁决：
  - affected 跑全档语义（含集成件）：定向面的测试全跑，避免「日常从不跑集成件」的盲区。
  - 验证阶梯不变——affected 是快门禁加速，不是全量替代；动了契约/行集/装配链仍须 `pnpm test` 全量（结构域 fail-loud 是它的自动兜底子集）。
  - 无测试包的变更（纯库无 tests/）跳过、风险沿 dependents 链传导到有测试的包；链条末端也无测试时打 stderr 提示。
