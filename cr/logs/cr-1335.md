# cr-1335 修 IM 视图两反馈（用户消息丢失 / 机制通知混入）

日期：2026-11-26
状态：doing

## 动机（用户实测反馈）

cr-1334 上线后用户切 IM 视图发现两个问题：
1. **用户消息丢失**——白名单只收 delivered:true，而入站打标是 cr-1332 起的新写面词汇，存量行缺标 = 全部漏投。
2. **事件行还在**（[系统通知] 后台任务 ×2）——机制信被误打 delivered:true 混进 IM。

## 根因（两个独立缺陷）

### A. steer 误打标（机制通知混入）

ac-ledger isUserParticipationInject（cr-1333）以 injectSource === "steer" 判用户插话——但 busy 时机制信（restart 唤醒 / job 完成回投 / goal 轮）同样走 driveRun steer 分支注入（message.role 恒 user），injectSource 缺省词也是 steer。**sender 才是唯一可靠判据**。现场：__creator__/01a2157f 会话两条 [系统通知] pwsh 行（injectSource=steer + delivered:true）。

同族缺陷 B：出站打标门（shell-conversation deliver）只看 mechanism/notice——goal 轮唤醒信（source:event、无 mechanism）出站照打 delivered:true。现场：mathematician/news/tester 自会话桶 8 条机制轮行。

### C. 存量用户消息缺标（消息丢失）

白名单「宁漏不误」对第三方写面是防御，但入站用户发言行恒是投递事实（消息进会话 = 被投递），缺标只因写面词汇新——全剔除是可用性缺陷。

## 修法（三处 + 一次迁移）

1. **isUserParticipationInject 加 sender 门**（ac-ledger/src/service.ts）：steer 仅 sender=user（或缺席——旧 emit 保守放行）判用户参与；订阅签名补顶层 sender 透传。
2. **deliver 的 source:event 归机制语义词**（ac-shell-conversation/src/service.ts 出站+壳内两分支）：payload 补 mechanism:true → 接收方按 context+event 行落账（事件分隔符、天然不进 IM 白名单）；出站打标门加 source:event 剔除。notice（回执转投）豁免——维持既定发言行形态（归属 sender）。
3. **fold im 白名单放行 user 入站行**（ac-ledger/src/fold.ts）：delivered === true 或 role === "user"——role:user 只派生自 agent_id="user" 的入站行（fold-core 225 行单源），agent⇄agent 对端行走 peer→assistant，零误投增量。
4. **存量迁移清洗**（sandbox/migrate-cr1335-strip-steer.ts + -selfbucket.ts）：剥误标 delivered 键——inject+delivered:true ×2（job 通知）、自会话桶自著 message+delivered:true ×8（goal/热点/巡检轮）。
