# cr-1093 conv-settings 批①：发送时写

承 cr-1087 裁决、cr-1090 交接档批①（④ cr-1091 / ② cr-1092 已先行）。核心语义落地：**设置随消息边界生效，进行中的 run 不受干扰**。

## 实现形状

ChatInput.vue：
- `convBaseline`（reactive）：读面已存值快照（''=无显式键），会话切换/回读时填充。
- `dirtyConvPatch()`：表单值 vs 基线 diff → 有变化的键一次 patch（值 / null 删键）；无变化返回 null（零写）。
- `flushConvSettings(conversationId)`：唯一写点。成功 → 基线追平 + bump 装配面快照（setConvToolMode/setConvBrowserTier，预览与估算面重取）；失败 → console.warn 不阻断、不回滚表单（下次发送重试）。
- `prepareSend()`：草稿位先 `dispatchDraft()` 拿签发 sid → flush；续聊位直接 flush 当前键。`send` / `sendNow` 共用，物化失败 = 消息不出门。
- 四控件（selectToolMode / selectBrowserTier / selectExtKey / selectModel 的 1v1 分支）只改表单 + 记组合偏好，删 RPC 与失败回滚/toast。
- 两个 watch（toolMode / browserTier+实验键）：删「无显式键回放偏好并落写」段——偏好只做表单初值（已存值 ?? 偏好），基线同步记录；草稿位跳过服务端回读（哨兵脏值不回显）。

## 蒸发物

- `setConvSetting` / `convSettingStored`（统一写口与暂存读口）删除；`onDraft` 保留（语义改为「草稿位」判定）。
- singles：`setConvOverride` / `convOverrideValue` / `PendingMeta.convOverrides` + 读侧 sanitize + `dispatchDraft` 逐键搬运段删除（存量草稿该字段读侧忽略）。
- `toolModeInherit.ts`（persistToolMode / settleToolMode / pendingToolModeCount）整文件删除 + 其测试；`chat-core` 的 `settleToolMode` 等待与 `toolModeKeyOf` 一并删除。

## model 例外（既有域名分流，本批复核保留）

singles 的 model 仍走 `updateSession`（session.json 域）**即时写**：单条消息的信封模型取自会话上下文（chat-core deliver 带 `ctx.model`），延迟写会造信封与 session.json 双源。1v1 的 model 已表单化（`dirtyConvPatch` 对 singles 形态剔除 model 键；deliver 侧 `storedModelOf` 读盘合并）。
