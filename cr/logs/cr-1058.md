# cr-1058：fresh 新会话未选工作区锁输入（点击直开工作区下拉）

日期：2026-11-13 · 标签：#webui · 状态：done

## 动机

用户新会话（fresh 草稿位）未选工作区即可直接输入发送——但工作区是开场身份（开始会话即固化、不可再改），先写后选容易落错位置。要求：未选择时锁输入，点击输入框下拉选择工作区，选择（含「未分组」）后解锁。

## 根因与修法

根因：草稿身份 `PendingMeta.workspaceId` 只有 `undefined | id` 两态，「未选择」与「显式未分组」不可区分，门禁无从判起。

修法（三处）：

1. **singles 草稿三态**（`ac-client-ui-singles/client/index.ts`）：`workspaceId` 升三态——`undefined` = 未选择（锁）、`''` = 显式未分组（解锁）、非空 = 挂指定工作区（解锁）。`loadPending` 不再过滤空串、`updateSession` 草稿分支不再把 `''` 塌缩成 `undefined`。`pendingView` 本就条件展开（`''` 带键），视图链零改动。
2. **ChatInput 门禁**（`ac-client-ui-conversation/client/ChatInput.vue`）：`freshWsGate` computed（fresh + 哨兵 id + isPending + workspaceId undefined）并入 `inputDisabled` 单源；placeholder 警示色引导；锁定期编辑区盖透明点击层（`.ws-gate-zone/.ws-gate-cover`）——点击直开工作区下拉（复用 `openFreshMenu('ws')`）；工作区按钮 warn 态。`selectWorkspace` 门禁期同值穿透（本地回落值与「未分组」同为 `''`，不穿透则门禁永远解不开）。
3. **跨包哨兵引用（环踩坑，两级）**（`ac-client-ui-singles/client/pending.ts` 新建）：ChatInput 需 `PENDING_SINGLE_ID` 值。第一级：从 singles 主面值导入 → conversation → singles → conversation 运行时环（vite/ESM 侧 namespace 快照取 undefined，seats-audit 装载失败）——拆独立小模块可解 ESM 侧。第二级：**bundle 模块系统（CJS factory）按行归一深路径**——pending.ts 属包内模块被内联进 bundle，但 conversation → singles 行物化 → require conversation 深路径（draftParking）→ 环检测 fail-loud（full-mount-regression / e2e-v3 抓到）。终解：conversation 侧字面量内联哨兵（零跨包值依赖），对拍防线住 singles 侧 draft-single.test.ts（静态读源断言内联副本与 pending.ts 本体一致）。

## 兼容口径

- 从工作区 + 号或带工作区上下文新建的草稿天然解锁（`workspaceId` 初值即非 undefined）。
- 旧留存草稿（无 workspaceId 键）刷新后回到锁定态——需点开下拉补选一次，符合「未选择」语义。
- `dispatchDraft` 物化语义不变：`undefined`/`''` 均不带 workspaceId 键（未分组），id 正常带。
