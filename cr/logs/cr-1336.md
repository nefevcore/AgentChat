# cr-1336 cr-1335 装载面补：host 侧投影需 restart_host

日期：2026-11-26
状态：doing

## 现象

cr-1335 修复 + restart_shell 后，用户切 IM 视图仍见旧行为（用户消息缺第一条、[系统通知] 混入）。

## 根因（装载面归属误判）

`session/history` 的投影（`assembleSessionView` → `foldViewRecords`）由 **宿主进程** `packages/ac-host-webui/src/web-api.ts` 注册的 RPC 直接调用——ac-ledger 的 fold 代码因此同时在**两侧装载面**：
- 壳侧（shell.yml 点名 ac-ledger）：写面打标（ledger service 的 inject-consumed 订阅）→ `restart_shell` 覆盖；
- **宿主侧**（web-api import assembleSessionView）：读面投影 → 必须 `restart_host` 才换代码。

cr-1335 只做了 `restart_shell`，宿主仍跑 cr-1334 版 fold（`delivered === true` 严判）→ 存量缺标 user 行被剔、steer 误标行照投。**直连 WS RPC 实测**（`sandbox/probe-cr1336-rpc.mjs`）：宿主返回 2 行（缺第一条 user、含 1 条误标系统通知）；同参数 node 直读 src 返回 3 行。

## 处置

1. 复跑幂等清洗脚本（`sandbox/migrate-cr1335-strip-steer.ts`）：剥重启窗口内新落的 1 条误标（[系统通知] pwsh-3）。
2. `restart_host` 使宿主侧 fold 换新。

## 经验（装载面归属判定）

改 ac-ledger / ac-ledger-core 一类**双面装载**包：写面改动看 shell.yml，读面投影改动看谁 import——`session/history` 在宿主 web-api，属宿主装载面。判据不是包在哪个 yml 里，而是**实际调用栈跑在哪个进程**。
