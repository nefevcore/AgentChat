# cr-1135 TokenGauge 上下文占用跳变根修（锚点校准比率）

## 动机

WebUI 会话头上下文占用仪表在续聊/收束时偶发跳变，观感不可靠。

## 根因

displayTotal 两套异构口径硬切换：

- run 进行中 = livePrompt（KV 步流最新步 usage.prompt，API 真实值，
  含系统提示/工具定义/chat 模板全部开销）；
- 收束后 = 盘读 session/tokens 回放估算（CJK 0.6/其他 0.3 系数）+
  前端固定开销估算（弹层未开过 = 0）。

估算器系统偏差在切换帧整体显现 → 跳变。续聊场景两个切换点都踩
（收束回落 + 新 run 首步回跳）。

## 修法（DSH token-meter 锚点思路的乘法形式）

- idle 采样拍（turnInProgress=false）将 cache.lastRunPrompt（API
  锚点 P）与 tokenCount（盘读估算 E）同拍配对，比率 r=P/E（钳
  [0.5,4]）吸收全部系统偏差；
- 盘读态显示 E×r——切换点按构造连续（E×r=P），增长沿校准估算器走；
- 加法投影（P + ΔE）需要持久化采样时刻表面，成本不成比例；乘法形式
  每拍自导出，数学一阶等价。
- lastRunSettledAt 信号（feed-core/chat-store 新增）：run 收束双拍
  重取（即时 + 800ms——usage 自报信经邮局异步入账，跨信封竞态），
  保证 fresh 配对；run 中 fetch 不采样（P 停在上一 run，配对失真）。
- 归档清锚（E 骤缩 P 停旧值，r 失真）——回落无锚口径，下次 run 重校准。
- contextTokens computed 共源：实时/锚点态 = 总量减固定开销估算，
  无锚点回落净估算（与旧口径恒等）；四段条/aria 同口径。
