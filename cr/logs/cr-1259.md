# cr-1259 approval 键选择即写（per-step 生效）

## 动机

用户诉求：会话进行中修改审批权限（conv-settings approval），下一 step 立即生效。

诊断：门（ac-permission-gate onAskOf）本就逐 tool call 实时读 effective（宿主服务与壳
垫片均现读不缓存）——消费面早已 per-step。真正瓶颈 = cr-1093「发送时写」把全部键
统一推迟到消息边界落盘。用户定案：给 approval 单键开「选择即写」例外（方案 B）。

## 裁决

写时机结构化为键 def 声明属性（`immediate: true`），而非控件各自决定：
- **判据**：只标给消费方逐调用读取的键（写落盘即被下一次消费看见——「写即生效」
  语义自洽）。approval（门逐 tool call 读）符合；toolMode（run 装配点读）禁标。
- 这是对 cr-1093「写时机 × 读时机正交组合」问题的结构化解，不是恢复旧涌现语义。

## 改动面

- `ac-conv-settings/src/service.ts`：ConvSettingsKeyDef 增 `immediate?: boolean`；
  approval 键标记。
- `ac-host-webui/src/web-api.ts`：ConvSettingsFace.listKeys 签名透传 immediate。
- `ac-client-ui-conversation/client/ChatInput.vue`：泛写口 selectExtKey 按 def.immediate
  分流——非草稿位即写（成功基线同步、失败回滚表单 + toastError）；dirtyConvPatch
  排除 immediate 键（不进发送边界 patch，防旧值当脏值重写）。
- 门（ac-permission-gate src）零改动：onAskOf 在 runApproved 缓存检查之前求值，
  mid-run 改 deny 立即压过已批准缓存。
- 测试：门 +3（deny 压缓存 / allow 免卡 sandbox-access / ask 与缓存正交）；前端回归
  锁更新（直写面 2 处 = flush + immediate 泛写口；控件断言按 def 分流）；e2e +1
  （keys RPC immediate 投影透传）。
