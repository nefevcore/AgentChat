# cr-1168 fs-source 配置写面收口（news 重建 timer 越界复盘修补）

> 登记于 2026-11-20 · →cr-1165（采集层）→cr-1166（视图授权）· 状态：done

## 动机

news 用 v3 重建 8 条定时任务后的自查报告暴露两处越界 + 一处平台缺口：
1. **auth.json 手写**（越界但内容合法）：写者面属 auth-registry 行，news 绕过直写 JSON——权宜可用但须转正；
2. **config.json 手写**（平台缺口）：fs-source 行读 `config?.get('source.fs')` 但 config 可写白名单（CONFIG_KEY_PREFIXES）不含 `source`——「平台自己规定的配置键，平台自己的写接口写不进去」，任何 Agent 配 fs-source 都得手改文件 + 重启。**这是 cr-1165 的实施遗漏**（加了读面没开写面）。

news 已实测排除两项风险：重启后内存配置含 source（config/save replace 不会写丢）；config/save 白名单外不动（手写域不会被 UI 抹掉）——但缺口本身存在。

## 改动面

- **CONFIG_KEY_PREFIXES 补 `source`**（ac-host-webui/config-face.ts）：白名单首段命中即放行——`source`/`source.fs`/`source.fs.roots` 均可经 config/set 与 config/save 正规写入；fs-source 行既有的 config/changed 热重载随即生效（改 roots 不重启）。
- **config-face 测试补 source 正例**：assertConfigKey 放行 + write 落盘。
- **news 手写 auth.json 转正**：经正规写者面 updateAgentAuth 幂等重写（grants 内容不变——两个 source-view grant 结构合法保留；落盘形态归写者面）。一次性脚本，跑完即删。
- **探针清理**：news 留的 4 个一次性探测脚本（cfg_source_probe / rpc_catalog_probe / rpc_catalog2 / cfg_mem_check——连宿主 WS 读配置）已删除。

## 裁决

- timer.json 走 timer(set) 正规写者面（news 报告确认）——零修补。
- auth 手写转正而非重录：写者面是 read-modify-write，手写内容本就兼容；转正 = 收敛「手写态」为「系统态」，不需要 UI 面板重操作。
- config 白名单是读面归属的镜像：读面在哪（config.get('source.fs')），写面就该在哪——本批是补漏不是扩权（source 域属用户配置数据，非 app 内部键）。
