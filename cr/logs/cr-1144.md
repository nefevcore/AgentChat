# cr-1144 · 未读计数收口（机制注入不计未读 + send_agent(to:user) 独立私信直播帧）

日期：2026-11-17 · 状态：done · 标签：#webui #fix

## 动机

两个用户反馈的未读缺陷：

1. **恒定两倍计数**：一轮后台 run 常态产生 2 个未读——`run/settled` 收束帧 +1
   （cr-1057）与 `session/context-injected` 机制注入行 +1 叠加。后者最常态化来源是
   ac-memory（`loop/before-run` 检测记忆水位增长即注入 delta，非活跃会话逐帧计数），
   其余同类：resume 续跑通知、技能注入、ask_questions 答案注入。cr-1139 锚幂等只防
   同一事实重投，不同事实源锚空间不相交（runId vs injectionId），无从去重。
2. **定时自会话私信零反馈**：timer 定时唤醒 → `news~news` 自会话 run →
   `send_agent(to:'user')` → 跨壳信封经邮局投 user 端点 → `UserStub.receive` 只触发
   `ledger/viewer-appended` 缓存失效，**零 WS 帧**——前端刷新前既看不到直播行也不计
   未读。`router/message-received` 的前端 case 仍在（feed-core 既有处理面），只是现行
   树无人发射它。

## 改动

1. `packages/ac-client-ui-conversation/client/feed-core.ts` `showEventNotice`：整条摘除
   `bumpUnread`——机制注入行一律不计未读（一轮回复 = 1 个未读，单源 = run/settled
   + 独立私信 + 群消息）；roster 活动刷新保留（列表预览仍反映会话动静）。
2. `apps/host/user-stub.ts`：UserStub 构造器新增 `onStandalone` 回调——`receive` 分流
   非回信信封（kind=message、payload.run 缺席、text 非空）即触发；回信信封跳过
   （run/settled 已计，再发即双计）。缺席 = 无直播面（CLI/测试形态零变化）。
3. `packages/ac-host-webui/src/host-web.ts` `attachWebSurface`：装配点注入 onStandalone →
   `ctx.webServer.broadcast('router/message-received', ...)`（message_id = requestId
   幂等锚；conversationId = 信封 uuid = pairKey(agent,user) viewer 对桶）。
