# cr-1141 · unread 后续一裁决：router/message-received 帧无发射点

## 背景

交接文档后续一假设「emit 源动态构造，帧面是否透传 message_id 静态无法确认」，
计划找到发射点把落账行 message_id 带进帧载荷，前端零改动自动升级幂等。

## 实证（双路）

1. **静态**：全仓 git 索引内 `message-received` 全部 10 个持有文件逐一核对——
   无一处 emit。发射词汇只存在于：
   - `ac-retired-types/src/index.ts:106`（注释明言「原 ac-router emit」——router 包已退役）
   - `ac-wire-format/src/bridge-events.ts:161`（桥接目录消费面，非发射面）
   - 前端消费点（feed-core case 'router/message-received'）与测试。
   事件名无动态拼接（无 `router/${` 模板、无 `emit(type/` 变量调用）。
2. **运行时**：连宿主 WS（port 3830）抓帧——
   - 空闲投递（conversation/deliver RPC → admin）：53 帧，类型全集中
     loop/run-started · step/journaled · run/settled · llm/delta-* · session/context-injected，
     **零 message-received 帧**。
   - busy 排队（lane next-turn 第二条消息，观察排队消费链）：44 帧
     （queue-changed ×2 + 两轮 run 全链），**仍零 message-received 帧**。

## 结论与裁决

cr-976 B 案直播管线重构后，入站消息的帧面收敛为 durable 事实投影
（run/settled 等）——`router/message-received` 是 ac-router 退役后的遗留词汇，
无发射点。后续一的「补 message_id 进帧」方案**作废**。

私信未读幂等现状即终态：
- run/settled 路径已有 runId 锚（cr-1139 bumpUnread(dialogId, '#r:'+run)）——覆盖
  流式收束增量。
- 直播入站路径（showInbound）在现代链路中不经 message-received 帧触发；
  用户自身消息本地已上屏不计未读；跨 tab 场景由 storage 事件对账
  （watchUnreadSnapshot，cr-1139）+ 重连重拉收敛。
