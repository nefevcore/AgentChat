# cr-1197 subagent list 缺省视图净化 + glob 跨锚点 path 基准修正

## 动机

用户反馈两点：
1. `subagent list` 缺省混入跨会话无键历史，要看本会话的需 query 过滤，不符直觉。
2. `glob` 的 `path` 参数不改变 `paths` 锚点——跨锚点使用时解析基准易踩坑。

## 根因

### list（cr-738 遗留）

`listOp` 会话域过滤对 `originConversation === undefined` 的条目恒放行
（保守显示防孤儿管理不到）。无键子 = 宿主直调 / 早期存量——它们是
跨会话的公共历史，混进**每个**会话的缺省视图。防孤儿不必进缺省面：
无键子仍可经 `all: true` 全量面或按 id 触达（stop/status/await——
`childOf()` 先 `noteOrigin` 懒回填）管理。

### glob（双缺陷，比反馈的现象更深一层）

`walkFiles` 恒以 `base: sandbox.workdir`（锚点）计算 rel：

1. **锚点外根静默漂移**：`rootRel` 以 `..` 开头时回退 `''`，输出静默变成
   「相对搜索根」——同一份 paths，锚点内是锚点相对、锚点外是搜索根相对，
   且后者 read 直连必断（描述却宣称「可直接作为 read 的相对路径参数」）。
   rg 路径（grep）在锚点外回退**绝对路径**，两引擎口径不一致。
2. **模式匹配空间矛盾**：`re.test(e.rel)` 在锚点空间匹配，但文件头注与
   参数描述都写着「含 / 锚定相对搜索根」。收窄搜索根 + 前缀模式
   （如 `path: 'sub', pattern: 'deep/*.ts'`）静默零命中；字面量前缀剪枝
   同样按锚点空间推导（litDirs[0] 对比搜索根第一层段——若模式第一段
   恰好等于搜索根名，根自身整树被剪，零命中）。

## 改动

### packages/ac-fs-search/src/index.ts（glob）

- `walkFiles` 不再传 `base`：rel 恒在搜索根空间。
- 模式匹配 / 剪枝 / matchBase 随之归位搜索根空间（与头注及参数描述一致）。
- 输出侧按 `rootRelPrefix` 拼回锚点前缀：锚点内根输出锚点相对路径
  （read 直连不变——既有行为保持）；锚点外根输出相对搜索根路径。
- description 同步新语义（锚点内/外两种 rel 基准明示）。

### packages/ac-shell-subagent/src/service.ts（list）

- `listOp` 过滤收紧为严格匹配：`originConversation === conversationId`，
  无键条目退出缺省面。`all` 参数描述同步。

## 归属裁决备注

- glob 的 rel 语义改动在 ac-fs-search 行内完成，未动 ac-glob-core 的
  `walkFiles`（其 `base` 参数是通用能力，grep 的 Node 回退路径仍在用）。
- grep（锚点外回退绝对路径）与 glob（锚点外回退搜索根相对）口径差异
  保持现状：grep 的 rg 主路径与 Node 回退两路同口径（绝对路径），
  glob 保持锚点前缀拼接（锚点内 read 直连是主场景）。统一与否另批。
