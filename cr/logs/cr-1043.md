# cr-1043 工具 v3 包化

## 动机

多任务并行下 cr-log.md 单文件尾部追加混进功能提交，每次 git 提交需手工拆行；讨论收敛（三轮）后裁决：问题根源在「行级共享追加 vs 文件级暂存」粒度错配，解法不是拆台账文件，而是**索引/内容分离**——索引保持单行紧凑（追加面三年验证安全），内容按 CR 独占文件（git 粒度天然隔离）。

## 改动面

- `packages/ac-cr/`：工具本体包化（src/cr.mjs 核心 + src/cr-git.mjs git 扩展 + skill/SKILL.md 源），仓库即分发源。
- 索引/内容分离：cr-log.md 纯索引不动；详情住 logs/cr-N.md（正本，无回写机制）。
- 命令面：核心组 init/append/get/set/grep/stats/selftest；grep 增 head|detail 双面；git 组 sync/check 拆 cr-git.mjs（无 git 项目不装不碍事）。
- check 锁⑤项目特定回退链（AgentChat docs/design 布局）与锁⑦（cr-1037 键面红线）从通用工具剥离，归项目守门面。

## 裁决

- 多文件全量切换否决（聚合视图悖论 + 迁移账不划算）；开源方案（git-bug/dstask/taskwarrior）无对口替代——「账本独立于功能提交」是行业标准解。
- apply 回写机制否决——「让危险操作消失」优于「让危险操作更安全」，副本即正本。
- 尾部块 v2 元数据语法原样保留（与内容分离正交）。

## 验证

selftest 九项全绿（init 闭环/append 首条/追加形态/set/get 聚合/grep 双面/纯维度/stats/幂等）；正式台账 append/get/set 冒烟通过；check 七锁 + sync 投影 485 号 715 引用无悬空。
