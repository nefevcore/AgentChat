# cr-1300 兜底探针模块实例分裂根修（入共享面）

> 2026-11-24 · #render-pipeline · 前序：cr-1299（探针双指标升级）——改动后的运行时产物侦察发现。

## 现象与发现路径

cr-1299 双指标改完后做产物核实（改了代码要确认运行时真的换了）：
`packages/ac-client-ui-conversation/client/dist/index.js` 含新读面（3 处 rowIds）；
`apps/ui/dist/assets/main-*.js` 也含 `__AC_FALLBACK_PROBES__` 挂载 + `rowIds.add` 实现。
→ **两 bundle 各内嵌一份 fallback-probes 实例**，而 `shared-modules.ts` 共享清单未列它。

## 根因

`fallback-probes.ts` 是**模块级计数器单例**（`const stats = new Map()`），被两个共享面模块引用：
`feed.ts`（探针命中点）、`feed-core.ts`（读面挂载点）。二者均在共享清单 → 运行时用宿主种子；
但 fallback-probes 自身不在清单 → 各自 bundle 内嵌一份副本。这与 cr-1296 实锤的
`frameScheduler` 分裂**同族**：被共享面引用的单例逻辑必须同列，否则单例语义失守。

当前未爆的侥幸：所有引用方恰都在共享面（feed / feed-core），运行时全部走种子，
窗口读面与写入恰同实例。**但是隐式前提**——任何非共享模块直接 import 探针即分裂
（计数分两份、读面只反映一份），且无任何对账锁会红。

## 修法

1. `apps/ui/client/shared-modules.ts`：增 `convFallbackProbes` import + 映射项
   （59 说明符，头注释同步）；
2. `apps/ui/scripts/host-module-table.ts`：冻结清单 `HOST_MODULE_SPECS` 同步增项
   （对账锁 host-module-table.test 由红转绿）；
3. 双构建（build:channel + webui:build）+ restart_host。

  彻底消除需 external 规则按解析后路径匹配，属构建机制改造，超出本批范围（已记录）。

## 根因与开放项（不做逐例打补丁）

三例（frameScheduler cr-1296 / feed-core cr-1296 / fallback-probes cr-1300）同根：
**build-channel 的 rollup `external` 按说明符字面匹配，共享面模块内部的相对引用链
（`feed-core.ts` → `./feed.ts` → `./fallback-probes.ts`）不被外部化 → 内联副本随 bundle 走**。

逐例入清单是治标（每新增一个单例模块都可能漏）；治本 = external 规则按**解析后路径**匹配
（共享面源文件绝对路径集合），一次收口全部相对引用链。属构建机制改造，超出本批（补缺）
范围 → 记入计划档 §八 开放项，待裁决。
