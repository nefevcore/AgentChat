# cr-1234 anchor 撞 seq 空间重叠死锁物理回收（admin~user 压缩循环）

## 现象
admin~user 频繁触发压缩请求（间隔递减 86→35→27→20 分钟），而 token 触发器未命中（118K << 500K）。

## 根因链（四环）
1. **seq 空间回退重叠**：11-17 物理回收重写主日志后，writer 从三文件种子（subcalls 尾 seq=649）重编号，新行 seq 与归档段内旧 seq（1..1323）重叠。
2. **anchor 双重身份欺骗**：`.archive-anchor.json`（seq=1323 / m1-4d7efa2b）在主日志 dedupCutoff 的 seq 锚命中 11-22 的无关新行（run-send 的 tool-call-result，恰好分到 seq 1323）——dedup 只比对 seq 不验身份。
3. **cutoff 锚死 → 雨量口径死锁**：每代 archive 集 = cutoff 后增量（~296 行 / 38K token < 回收闸 60K），历次 shadow 的 1167 行（3.63MB / 94% 字节）永踞主日志——cr-1229 的闸门按**本次雨量**（split.archive）计量，与**滞留存量**口径错位，物理回收永不开启。
4. **ledger-bytes 兜底循环**：5.74MB 恒超 4MB 阈值 → 每个 run 收束都触发完整归档编排（整理轮 LLM run + 事件 + 重写评估）。

## 修复（三处，archiveAndRebuild + writer.compact）
1. **anchor 双锚验证**：seq 命中行面但 messageId 不符 = 空间重叠，视为无锚（物理搬走的行按构造不在主日志，seq 不命中才是健康态）。
2. **boundary 地板换压缩事件**：`facts.compactions.at(-1)?.boundarySeq` 替代 anchor seq——compaction 事件永踞主日志，是逻辑 shadow 的 durable 事实源；anchor 无效或无雨量轮时 boundary 单调不回退。
3. **回收闸与搬移集改存量口径**：闸门 = 全量估算 − 活跃估算（token，含伪行轨迹——cr-1229 口径）；搬移集 = 事件后重读行面上被 shadow 的真行（rowShadowedBy 三级裁决 + 位置维 beforeEvent）；keep 同基准。原 split.archive 雨量口径退役。
4. **writer.compact late-merge 去重**（连带修）：keep 基准换事件后行面后，事件行已在 keep 内；seq 单调假设失效时（重写后种子重编号）late-merge 会同行双写（现场 compaction#10 两遍）。复合指纹（seq+type+run）去重。

## 验证
- 回归用例：cr-1234（anchor 撞 seq 重叠 + 两代滞留出清）17/17 绿；ac-shell-rows 59/59。
- 沙箱预演 admin~user 副本：5.74MB → 318KB（-94.4%），滞留全部入段，ledger-bytes 阈值脱离。
- typecheck / check:deps / 定向 lint 绿。
