# cr-1192 小会话归档边界恒 0（V3 逻辑边界失效）

## 现场（用户手工测试会话 01a1fe79）

三轮归档（两代 compaction）后 LLM 回放仍含全部旧会话信息。账本实证：两代 boundarySeq 均 = 0——0 边界在 rowShadowedBy 下不 shadow 任何行（seq≥1 恒放行）→ 回放全量。

## 根因

boundary 取自 `archivedOriginal.reduce(max seq)`（archive.ts L566-567），而 archivedOriginal 为空：

- 该会话仅 64KB/44 行（估算 ~15K token）< 尾部保留预算（1M × 3% = 30K token）
- `splitForArchive` 的 keep 覆盖全表 → archive 集为空 → `archivedOriginal.length === 0`
- L582 注释自认该形态「零移出（尾部水位未越）——只滚摘要」

这是 V2 物理归档时代的语义残留：V2 下「只搬超出水位部分」时零移出 = 无事发生，boundary 无意义；**V3 下摘要行已落、compaction 事件已落，逻辑边界即生效**——boundary=0 意味着「宣称归档了但什么都不出清」，且每归档一代，摘要行 + 请求行（376B）+ 确认 run 的全部行都在回放里堆积一代，越归档越臃肿。

## 修法（单点：archiveAndRebuild boundary 计算）

boundary 兜底——archivedOriginal 为空或其 max seq 不足时，取 **archive-summary 行 seq - 1**：

- 摘要行按 cr-1189 裁决永留主日志且不被 shadow（isCompactionRow 排除面）
- 边界盖到摘要行之前 = 出清摘要行之前的全部旧内容（含请求行、旧代摘要行、整理轮轨迹）
- 天然不 shadow 摘要行自身（seq-1 < 摘要行 seq）——回放头保住

无提交代（摘要行缺席）保持现行为（boundary=0 只滚事件）——无摘要可锚，强行出清会丢记忆。

模拟验证（现场数据）：第二代边界 = 35 → 回放 44 行 → 8 行（摘要 + 最新问答），开场白/两轮整理/技能注入全出清。
