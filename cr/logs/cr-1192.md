# cr-1192 小会话归档边界恒 0（V3 逻辑边界失效）

## 现场（用户手工测试会话 01a1fe79）

三轮归档（两代 compaction）后 LLM 回放仍含全部旧会话信息。账本实证：两代 boundarySeq 均 = 0——0 边界在 rowShadowedBy 下不 shadow 任何行（seq≥1 恒放行）→ 回放全量。

## 根因

boundary 取自 `archivedOriginal.reduce(max seq)`（archive.ts L566-567），而 archivedOriginal 为空：

- 该会话仅 64KB/44 行（估算 ~15K token）< 尾部保留预算（1M × 3% = 30K token）
- `splitForArchive` 的 keep 覆盖全表 → archive 集为空 → `archivedOriginal.length === 0`
- L582 注释自认该形态「零移出（尾部水位未越）——只滚摘要」

这是 V2 物理归档时代的语义残留：V2 下「只搬超出水位部分」时零移出 = 无事发生，boundary 无意义；**V3 下摘要行已落、compaction 事件已落，逻辑边界即生效**——boundary=0 意味着「宣称归档了但什么都不出清」，且每归档一代，摘要行 + 请求行（376B）+ 确认 run 的全部行都在回放里堆积一代，越归档越臃肿。

## 修法（单点：archiveAndRebuild boundary 计算）

boundary 兜底——archivedOriginal 为空或其 max seq 不足时，取 **archive-summary 行 seq - 1**：

- 摘要行按 cr-1189 裁决永留主日志且不被 shadow（isCompactionRow 排除面）
- 边界盖到摘要行之前 = 出清摘要行之前的全部旧内容（含请求行、旧代摘要行、整理轮轨迹）
- 天然不 shadow 摘要行自身（seq-1 < 摘要行 seq）——回放头保住

无提交代（摘要行缺席）保持现行为（boundary=0 只滚事件）——无摘要可锚，强行出清会丢记忆。

模拟验证（现场数据）：第二代边界 = 35 → 回放 44 行 → 8 行（摘要 + 最新问答），开场白/两轮整理/技能注入全出清。

## 同源补充：单事件 compaction 谓词漏判（实施中发现）

归档路径的机制行谓词 `isCompactionRow` / `compactionRuns` 只匹配 `compaction/` 前缀（三连旧形态 compaction/start|summary|end），**漏了 cr-1160 起的现行单事件形态 `type='compaction'`**（现场会话 seq=16/37 实证命中 False）。

后果两条：
1. 单事件行若落进 `archivedSet` → 被计入 `archivedOriginal` → 推高 `archivedMaxSeq` → 无提交代（summaryAnchor=0）时 boundary 盖过上一代摘要行 = 回放头蒸发；
2. `keepRows` 保护失效 → 事件行随归档段搬离主日志 → `fold.compactions` 少代，破坏 cr-1189「边界事件永留主日志」裁决。

修：谓词按词汇全族收口（`t === 'compaction' || t.startsWith('compaction/')`），两处（排除面 + run 集）同步。

测试：新增多代用例——两次归档后主日志须含**两代**单事件 compaction 且 fold.compactions.length=2（旧代码下第一代事件随归档段搬走 → 该断言失败）。

## 调序（用户复核反馈）：compaction 先落、摘要后落

原序（用户指出的语义瑕疵）：摘要行先落 → compaction 后落，而 boundary 回读摘要行位置取 seq-1——**分界线反向读取自己之后将要保留的行**。

新序：`compaction 事件（分界线，boundary = 事件落点前的全表 max seq）→ 摘要行（新代首行，seq 天然 > boundary）→ run-end`。

- boundary 不再回读任何事件之后的行——锚自身位置，语义自洽
- 摘要行获双保险：位置维（seq > boundary）+ 时刻维（ts > endTs 恒 kept——cr-1156 不变量）
- 无提交退化（V2 用例锁定的语义）不变：无摘要时 boundary 保持 archivedMaxSeq，回放头沿用上一代
- 摘要行落账从 requestArchive 编排外移入 archiveAndRebuild（事件落完紧接落账，同函数内保序）

## 续修：reviewPrompt 对话方称呼（single 会话裸键问题）

single 会话键 = uuid 形（无 `~`、不含 agentId），`uuid.split('~').find(p => p !== agentId)` 单元素命中自身 → 整段 uuid 被当「对方」嵌进文案（现场：你与「01a1fe79-…」的会话（会话键 01a1fe79-…）——同一串 uuid 出现两次）。修：无 `~` 键（single）对话方恒为用户，直称「用户」。测试从归档段 gzip 验文案（请求行随边界出清，主日志不再可见）。
