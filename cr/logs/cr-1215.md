## 裁决

- 修复面在 admin 脚本侧，宿主侧不动：RPC session/meta 的 coverage 本就是磁盘枚举（allConversationIds），是诚实的；自证只发生在脚本的 sql 回落路径（digest 主链路）。
- 分母单源 = 磁盘枚举，且精细化为「有实质记录行」口径：空/仅 header/撕裂尾目录 records 永远无行（宿主 session-header 不入账同判），算进分母会永久误报 degraded（狼来了）。它们单列 empty_conversations 可观测，不算缺口。
- hasRows 不数行只看「header 行结束后是否仍有字节」：归档会话 header 后是超大 summary 单行（实测 >8KB 超预读窗口），数行会误杀（真实数据 9 会话误判，admin~designer 2.3MB 在列）。
- degraded 判定 = indexed < total；digest activity/diving 双段落标（activity.degraded / diving.status="degraded" + anomalies 下限值提示），消费方可降级展示。
- 宿主侧后台全量 parse 不做：惰性回填终会收敛（1355 会话实证），标 degraded 后缺口可观测，需要更快收敛时另行立项。
- 顺带：死文件 session-meta-scan.cjs 删除（import 语法在 .cjs 不可运行，全仓无调用方）；两脚本加 SCAN_DATA_ROOT 环境变量覆盖（sandbox 验证/探针用）。
