# cr-1134 user 域正主回迁：agents/user 会话数据迁回对端 agent 域后清理

- **日期**：2026-11-16
- **标签**：#session
- **状态**：done
- **承接**：cr-1133（用户裁决：正主回迁后清理）

## 背景

cr-1133 审计发现 agents/user 域是 14 个会话的唯一/主要承载（7 会话无对端域、5 会话
对端覆盖不全——167 条 agent 正文只在 user 域）。物理删除不可行，做正主回迁。

## 迁移规则

- 目标域 = header participants 中非 'user' 端点（对桶 → agent 域；uuid singles →
  __standard__ 域；sub_*~user 对桶键保留全名）
- 账本：message_id 不在对端的行追加尾部（header 仅对端缺席时迁）；
- journal：对端缺 run 的行随迁；migrated-* 伪 run 不迁（清理对象）；
- subcalls.jsonl：对端缺席时整体拷贝；
- 全量备份：sandbox/backup-user-domain-20261116-201900.zip（3.8MB）。

## 验证（迁移前后投影对拍）

- 14 会话 445 条正文行：**零丢失、零归属翻转**；
- 修复两处迁移缺口：sub 会话目录键名（对桶键需保留 ~user 后缀）、直发行漏迁
  （从备份补回）；
- LLM 回放（foldLlmReplay）五会话抽样正常——各 agent 域独立承载。

## 迁移中发现的既有投影缺口（顺手修复）

硬判据（备份原始行逐条核对，367 条）暴露 2 条 context 行（admin/news 的 memory-delta）
投影缺席：**带 run 键的 context 行进 run 归口桶后，只在「该 run 的主投影行」出现时随行
投出**——run 有 run-end 却无终稿行（机制 run / 死窗口）时桶内容永不可见（memory-delta
等注入卡整类缺席的根因，cr-1132 计划 §1.4 边缘形态的实锤）。

修复：归并前做**残留回落**——已消费 run 集（终稿层 run ∪ 活投影 run ∪ 盲区投出的 run）
之外的归口桶，其卡按直落卡投出（role/source/label/bytes 数据面完整）。契约测试锁定
（fold.test.ts「run 归口注入卡残留回落」）。
