# cr-1177 plugin/grant 回投链 R-1 冲突（存量缺陷——探针实锤）

## 发现（cr-1175 回顾时探针验证）

场景：uuid=会话键（如 user~creator-1）的信封，sender=agent、to=host → routeEnvelope 的
R-1 participants 近似算 [agent, host]，与该桶已登记的 [user, agent] 撞集外端点 → conflict
fail-loud → 信进 outbox 滞留（回执永不进会话，静默）。

**新旧链同撞**（旧信封链与新服务帧回投链均实测复现）——非 cr-1175 迁移引入的回归，
是 R-1 participants 近似对 host 域信的存量缺陷。cr-641 曾为 restart-host 请求补过
「host 域子会话键」，plugin/grant 未获同款处理。

## 影响面

- plugin.request 回执 + 续跑信：用户会话先有直投信时，install/uninstall 回执滞留（壳侧
  工具回执仍如实——「已投递宿主受理」为真；宿主受理也真完成；只有回会话的回执信丢失）。
- grant.apply 回执同构。

## 修复（2026-11-21 用户拍板：基础设施不算近似——按 uuid 严格定位会话）

裁决 = 候选 B 精确化：`routeEnvelope` 对保留端点 sender（host）的信，**已登记 uuid 直接按
登记集放行**（uuid 是会话键权威事实，participants 不重算）；未登记 uuid 仍走正常登记面
（fail-loud 保真）；普通参与者冒用已登记键照旧 conflict。改动面 = `ac-post-office/src/router.ts`
+ 依赖声明 ac-agents-core（isReservedEndpointId 单源）。

单测：post-office.test.ts 补「保留端点回投放行 / 未登记走登记面 / 冒用照旧 conflict」三断言。
