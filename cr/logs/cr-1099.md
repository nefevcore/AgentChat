# cr-1099 restart_host 完成通知机制

- 性质：feature（→cr-1097 用户反馈：Agent 需自己调 API 查宿主换代，闭环断裂）
- 日期：2026-11-15

## 动机

restart_host 的回执只承诺「壳侧送达确认」，复活验证要 Agent 自查 healthz/host-facts（回执 note 里的指引）——实测重启后 Agent 盲等/自查轮回。restart_shell 已有「已重启」通知注入（cr-658 marker 模式），restart_host 缺同款闭环。

## 设计

通知链（restart_shell marker 模式同构）：

1. 宿主 inbox.on 收 restartHost 信 → 落盘 `.runtime/restart-host-notify.json`（sender + conversationId；8s 优雅退出窗内完成）。
2. 新宿主 bootHost 尾部（host-facts 落盘后）读标记 → 删标记 → `po.dispatch` 向请求方会话投机制信（mechanism: true，cr-946 语义——非会话发言，事件分隔符形态；带新代 pid + web 端口）。
3. 工具回执换文案：healthzUrl/事实源自查指引退役，改「重启完成后会收到通知消息」。oldPid/webuiPort 仍随附（排查用）。

标记读后即删：换代一次一兑现；重启失败（boot 不达 return）不误投。

## 改动面

- `apps/host/boot.ts`：收信面落盘标记（payload 类型补 conversationId）+ boot 尾部投通知。
- `packages/ac-shell-rows/src/restart.ts`：restart_host 回执与 description 文案（healthzUrl 变量退役）。
- `packages/ac-shell-rows/tests/restart.test.ts`：用例锚更新（healthzUrl 断言 → 通知文案断言 + not.toContain('healthz')）。
