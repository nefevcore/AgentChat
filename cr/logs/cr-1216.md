# cr-1216 子调用参数侧可克隆前置校验（run-code）

## 动机（实测）

run_code 程序体内 `tools.<name>(args)` 传不可结构化克隆的值（BigInt / function /
Symbol / 循环引用）时：

- `worker.ts invokeTool` → `send(msg)` → `port.postMessage(msg)` 同步抛 Node 原文
  `$ => script could not be cloned`——异常在程序体内 reject，收束为程序级失败，
  错误面无工具名、无字段名、无自修指引；
- return 面已有降级链（serializeValue，0d55714a 复盘产物），参数面零护栏。

## 根因

出口序列化约束只装在 return 侧；参数传输边界（worker → 主线程 postMessage）
无任何前置检查，Node 深拷贝错误原文直透模型阅读面。

## 修复

- worker `invokeTool` 发送前逐字段探测（JSON.stringify → TypeError 捕获，与
  serializeValue 降级链同源——BigInt/循环引用入口；函数/Symbol 值字段单独探测）；
- 检出即本地拒绝：resolve `{ ok:false, error }`（不发消息，不消耗桥接层
  summary 计数——被拒调用未发生传输），错误含工具名 + 字段路径 + 值类型 +
  转换指引（BigInt→String(v)，函数/Symbol→源码串/描述串）；
- 裁决：参数侧**拒绝优于降级**——与 return 面相反：工具参数常含写路径
  （edit/write/子代理），静默改写值可能制造非预期副作用；明确拒绝 + 自修
  指引把修正权交给模型。
- 不动主线程侧（tool.ts）：传输错误只在 worker 发送边界发生，主线程收不到
  坏消息（postMessage 同步抛，消息从未发出）。

## 实现

- ac-run-code-core：precheckInvokeArgs + findUnclonable + describeValue
  （纯库导出，可单测——cr-950 先例：worker.ts 顶层 parentPort null 即抛，
  无法直接单测）；栈式 seen 循环检测先于容器分支（自循环 Map/Set 同拦），
  数组/Set 下标渲染 [i]，Map 渲染 .get(k)/.keys[k]，深度上限 10。
- worker invokeTool：预检拦截（探索失败静默放行交 postMessage 仲裁）+
  send 兜底 catch（pending 清理 + 计数回退 + 含工具名的错误）。
- 运行时生效面：worker per-run 从磁盘 spawn——下次 run_code 调用自动
  载新码，无需 restart_shell；主线程 tool.ts 未动。
