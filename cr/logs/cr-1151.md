# cr-1151 · 未读批量对账改索引 SQL 聚合（启动期事件循环阻塞根修）

> 性质：性能缺陷根修（读面）｜状态：doing→done｜2026-11-17
> 关联：cr-1146（引入 session/unread）、cr-1150（位置锚口径）、cr-973/cr-1138（session-index 聚合读面约束）

## 现象

系统重启后页面加载明显变慢：`boot-wire` 10ms 正常，随后 interaction/list、
session/unread、agents/list、runs/snapshot… **全部 10–12s 且几乎同时完成**——
事件循环被独占的排队特征。实测（宿主 WS 直连）：`session/unread` 单次
**10.0–11.4s**，且期间连 `system/version` 都要等 11.3s。

## 根因

cr-1146 的 `session/unread` 批量对账在 RPC 同步段对**每个会话**调
`assembleSessionView`（全量装配 messages+journal+subcalls）：
本机 1335 个会话目录、13654 行投影、subcalls.jsonl 526MB → 实测 **11.6s**，
单线程宿主整段事件循环被占。前端 `feed-core.init()` → `reconcileUnread()`
每次启动必发——启动期全部 RPC 被饿死。与 cr-1138 的「高频面只读聚合、
零盘读」约束相悖（session/meta 走索引，session/unread 却反着走）。

## 修法（方向 1：sessionIndex SQL 聚合）

### ac-session-index

- records 表增 `speech` / `claim` / `fact` / `anchor` 四列（journal_lines 增
  `anchor`）——入账时按 unreadOf/foldUserReplay 同源谓词落值：
  - `speech`：进 fold.speech 的行（v2 `type:'message'` / v1 非 context 非段/注入行）；
  - `claim`：参与判重（speech 且 user 发言或正文非空——foldUserReplay 先跳空正文再记 seen）；
  - `fact`：事实行（claim 之上再排除 viewer 入站 `agent_id:'user'`、空 message_id、`seg-`）；
  - `anchor`：读位锚查找键（inject 行 = `injectionId ?? jinj-<run>-<seq>`，其余 = message_id）。
- 旧库**不整库弃重建**：构造期只 `ALTER TABLE ADD COLUMN`；`fact IS NULL` /
  journal-inject `anchor IS NULL` = 未回填哨兵，`refreshUnread` 按会话整段
  重建两源（`rebuildUnreadSources`——删域行 + files 锚后重读，仍是单文件事务）。
- `refreshUnread`：只对账 records+journal（subcalls 与未读无关，不得为它读
  526MB）；`refreshConversation` 增 `kinds` 过滤。
- `unreadCount(convId, mark)`：SQL 复刻 unreadOf 语义——
  - 判重存活 = claim 行按判重键（非空 requestId 优先，否则 message_id）首次出现（域, 行偏移序）；
  - 事实行 + run 单行；位置锚 = 命中读位 messageId 的最后一行（records 与
    journal-inject 合并查，claim 行只认存活副本）；
  - 有效行序 =（时标, 域, 行偏移）：inject 事件无 ts 时投影取 now（恒末位），
    其余缺 ts 行排最前——与 foldViewRecords 的排序语义对齐；
  - 锚缺席 / 读位无 messageId → 回落 seq 比较（isNewerThanMark 同判据）。

### ac-host-webui（session/unread）

- 计数改 `index.refreshUnread(cid)` + `index.unreadCount(cid, mark)`，按 12ms
  时间片 `setImmediate` 让出（单线程宿主不被整批对账独占）。
- 索引行缺席回落全量装配（插槽-插头降级——慢但同构）；坏会话跳过不炸整批。

## 验收

- 等价性：`ac-session-index/tests/cr1151-unread.test.ts`——每个投影行都作
  读位锚，`unreadCount` ≡ `unreadOf(assembleSessionView)`；覆盖裸 seq 回落、
  无 seq 存量行、跨域镜像副本判重、run 单行、空正文/上下文排除、journal-inject
  合成锚、增量落账。
- 真实数据根全量对拍（1335 会话）：12 个真实读位 + 988 个合成读位锚
  （每会话 50%/90% 位置）→ **0 差异**；7 个会话 `assembleSessionView` 自身抛错
  （`r.content.trim()` 既有缺陷，与本条无关）跳过。
- 运行时（重启宿主后实测，1335 会话 / 1328 会话轴）：`session/unread`
  **1.26–2.09s**（原 11.4s），期间每 300–500ms 打一发 `system/version` 全部
  **1–14ms**（原 11.3s）——事件循环不再被独占。同一 tick 人工突发 11 个
  RPC 时兄弟调用 0.3–1s（基线 60ms）：12ms 分片下其余调用的公平调度成本，
  仍非阻塞；真实页面 RPC 分散在各组件挂载期，实测无 `rpc-slow`。
- 验证阶梯：`pnpm typecheck` / `pnpm test:unit`（442 文件 3254 用例全绿）/
  `pnpm check:deps` / 定向 eslint（仅测试文件命中既定 ignore）/ 定向 vitest
  （session-index 7 文件 32 用例 + host-webui unread 5 用例）。

## 已知边界

- 群成员流键（`g-…~m`）不在会话轴，batch 不触达 → 其索引行保持
  `fact IS NULL`（不被本路径消费，无影响）。
- journal-inject 锚 = 投影合成 id（`jinj-<run>-<seq>`）；无 ts 的 inject 行
  投影时标取 now（恒末位），SQL 用固定大常数表达——两次读取之间不会有行
  越过它（append-only 语义）。
- 判重存活按（域, 行偏移）首现近似 foldUserReplay 的 seen 序；跨域同名键
  的极端形态（同键多域且时间交错）未产生实测差异。
- 批量仍逐会话 stat 对账（每会话 ~0.4ms，1335 会话 ~500ms）——增量新鲜度
  所需；如需再降，可把 RPC 枚举得到的目录表下推给 refreshUnread。
