# cr-1211 测试根轮次隔离（多会话并发测试 EPERM 根治）

- 日期：2026-11-22
- 状态：done

## 动机

多会话并行开发时，各会话最后验证步骤（pnpm test / test:unit / 定向 vitest）几乎同时触发，
共享测试根 workspace/test 被 globalSetup 每轮整树 rmSync——一边 worker/子进程 cwd 驻留树内，
另一边清树即 EPERM（Windows 句柄）。历史实锤：cr-1181（双轮互踩）、cr-1197/1199（detached 壳残留句柄）。
定向跑同样触发 globalSetup，非全量独有。

## 设计

- **每轮专属根**：vitest.config.ts 求值期（主进程，与 globalSetup 同 pid——探针实证）直写
  `process.env.AGENTCHAT_TEST_ROOT = workspace/test-run-<pid>`。不放进 test.env：探针实证 test.env
  只达 worker，globalSetup 主进程不可见。worker 经 env 继承拿到同根。watch 同 pid 复用同根。
- **不做 teardown 清理**（用户裁决）：detached 壳/防病毒残留句柄会让已全绿轮次在收尾挂掉；
  改为下一轮 globalSetup 开工时 GC。
- **死轮 GC**：globalSetup 扫 workspace/test-run-*，`process.kill(pid, 0)` 探活——成功/EPERM = 在场跳过，
  ESRCH = 已死回收。pid 复用只致漏清（保守跳过），无跨根误删路径。best-effort：单根失败 warn 留下轮。
- **护栏泛化**：只放行 <repo>/workspace/test（回落兼容）与 <repo>/workspace/test-run-<pid>（正则），
  env 被污染指向任意路径即拒绝（原 endsWith 护栏语义保留并收紧）。
- worker 分桶（wN）、maxWorkers 8、cr-705 重试诊断、TEMP 锚定、子进程 cwd 隔离等单轮内缓解全部不动。
