# cr-1280 —— 媒体物化器能力缺口告警（静默降级可观测化）

> 状态：done（2026-11-24）｜前置：cr-1279（WorkspaceShim.resolveFile 补齐）

## 动机

cr-1278/1279 三步排查的共同特征是**软依赖 + 静默降级**：链上任一段缺失只表现为
「看不到图」，无错误、无日志。最典型的一处：

```ts
const ws = ctx.get('workspace', false) as { resolveFile?(p: string): string } | undefined;
if (typeof ws?.resolveFile !== 'function') return undefined;   // 静默 return
```

「服务缺方法」（装配缺陷）与「文件不可物化」（数据问题）在这里同形——用户报障前
无任何线索。

## 改动

`packages/ac-llm-pool/src/index.ts` `workspaceMediaResolver`：缺 `resolveFile` 能力时
`ctx.logger.warn` 一次（resolver 实例级去重——每连接一个实例，随 provider 生命周期），
文案指出「workspace 媒体引用一律不可物化」与壳侧补齐方向。

为何只报能力缺口、不逐 ref 报文件缺失：前者是装配缺陷（一旦发生全量失效，必须显眼）；
后者是常态（`_tmp` 清理后旧引用自然失效，逐条报会刷屏）。MIME 表外扩展名同理留待
需要时再议。
