# cr-1255 activation 锁 pid 复用致永久锁死

## 现场与根因

Windows pid 复用激进（writer 实测 12h 内即可复用）：壳崩溃不跑 exit handler
→ 锁文件残留（设计内——靠接管方清理）→ 无关进程占用旧 pid → 新壳 boot 时
isAlive(旧pid) 恒真 → 永远 refused，陈锁接管机制被废，Agent 永久无法启动。

根因：pid 存活被当作持有者存活的单证。pid 只能证明「这个 pid 上有个进程」，
证明不了「是当年持锁的那个壳」——pid 复用后判活面整体失效。

## 修法（结构性：接管权威与诊断分离）

接管权威 = 任一证死因子（lock.ts judgeHolder）：
1. pid 已死（内核裁决，不可骗）
2. 心跳租约超限：锁 mtime 超过 LOCK_DEADLINE_MS（4×30s）未刷新——pid 复用
   现场真壳死后无人 touch，租约必然超限，此类问题整类关死；锁文件创建即
   起租（O_EXCL 的 mtime），心跳自锁获取即 touch（覆盖装配窗——装配中的壳
   不会被误判死）

诊断定谳（不授权接管）：refused 时 manage 探针（probeActivationHolder）connect
transportHint 发 { ctrl: 'probe' } 帧核对 bootId——应答匹配 = 真活壳（错误消息
附凭据）；无应答 = 近期崩溃的租约残温（≤4 周期，重试即接管）。探针不授权
接管的裁决：装配窗口的真壳尚无 socket，探针无应答 ≠ 死——授权即双壳
split-brain。
