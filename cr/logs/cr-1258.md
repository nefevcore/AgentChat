# cr-1258 沙箱漏检：规则2 token 边界不含引号（ISSUE-31 后续）

## 复现（用户 2026-11-23 报告，直调沙箱函数绕开 gate/会话）
- `Get-Content /etc/passwd` → BLOCK；`Get-Content '/etc/passwd'` / `"/etc/passwd"` → ALLOW
- 同会话无引号形被拦、引号形放行 → 差异只可能来自逐条命令的沙箱判定，非会话放行。

## 根因
`bash-scan.ts` 规则 2 的 token 边界 `(?:^|\s)\/` 不含引号：`'/etc/passwd'` 的 `/` 前是
引号非空白 → token 不成立 → 整条 Unix 路径检查被跳过。规则 1（盘符，负 lookbehind
只排字母数字下划线）与规则 4（`..`，ISSUE-28 缺口①恰为引号包覆）都把引号当 token
边界——三条规则边界语义不一致，引号包裹的路径漏检。

## 修法（根因 = 边界语义不一致；不能用 cr-1257 前的形状启发式套路）
- 边界类加引号：`[\s'"\`]`。真路径的 `/` 是**原文就有的**。
- token 在**反斜杠归一化前的原文轨（raw）**上取：正则转义 `\d` `\[` 形 token 的 `/`
  只存在于归一化之后（`'\d+'` 原文没有 `/`），原文层天然不中——无需形状启发式，
  cr-1257（引号感知切段）与 cr-1224（裸 `/` 豁免）两修复不回退。为此 norm 双轨化：
  raw（剥 octal 转义后）+ norm（再归一反斜杠），splitSegments 平行切两轨，循环按索引对齐。
- token 前导引号剥除后再判：否则 `'/etc/passwd` 被 isAllowed 当相对路径 resolve 进根内
  误放行（探针实测第一版即栽在此——trim 只剥空白）。

## 验证
- 用户四例：引号双形 BLOCK、无引号基线 BLOCK、管道拼接 `a|Get-Content /etc/passwd` BLOCK。
- cr-1257 七组探针无回退；cr-1258 四断言新增（引号双形拦/根内放/越界拦/交替载荷放）。
- 阶梯：typecheck ✓ / test:unit 3504 全绿 ✓ / check:deps ✓ / 定向 eslint 0 error ✓。

## 语义净变化
取消对**无空白前导的 `/` token**（`cat 'a|\w+/x'` 形）的拦截——该拦截是旧切段事故
的产物而非设计目标（cr-1257 已记录）；引号边界进入规则 2 后，此类 token 若真为路径
（引号后紧跟 `/`）在原文轨被拦。

## 附带发现（未修，记档）
- 单字符引号内开关假串逃逸（`-In ' /x'`）——现实写法（`-In /x`）有空白前导必拦，
  引号包开关极罕见；记 ISSUE-29 档案同款语义（能力上限问题）。
- `isWindowsSwitch` 豁免新串不紧贴引号（`sls 'a' /etc/x`）——同上，罕见形态。
