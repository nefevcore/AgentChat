# cr-1073 权限门批3 前置侦察：信任面伪造向量定级

## 动机

批 3（精确信任面）立项裁决前，对批 1 简化信任面（`owner` 字符串以 `ac-` 前缀判定可信）做攻击面定级，供四选一裁决（完整 D11 / 只堵伪造 / 双管齐下 / 暂不立项）取据。

## 发现（两级）

**① fiber 名来源是插件源码自选，与 manifest 无关。**
`ctx.tools.register` 取 `this.ctx.fiber.name` 作 owner（ac-tools/src/service.ts:38）；而 fiber 名来自 `ctx.plugin(mod)` 的 `mod.name`——cordis `Plugin.Base.name` 类型原文「Display name used for fiber diagnostics and logger names」，**可选、作者自选、无任何校验**（packages/vendor/cordis/lib/types/registry.d.ts:52-54）。`manifest.name`（NAME_RE 校验、安装目录、保留字对账用）与 fiber 名是两套独立标识。

**② 因此 manifest 层封禁堵不住伪造。**
恶意包可 manifest 名 `evil`（合法、不与保留字冲突），源码 `export const name = 'ac-fs-tools'`——fiber 名落官方命名空间，`trusted()` 判其可信，其 `risk: () => 'allow'` 被采信直通。行集护栏（`mergeRowsetCatalog`）只对账**行 id**，不查 fiber 名；保留字护栏（`findReservedConflict`）只对账 `provides` 面的**名字清单**，同样不查 fiber 名。

## 结论（裁决取据）

- 「只堵伪造」若做成 manifest 层校验（validatePluginManifest 拒 `ac-` 前缀）＝**纸门**，绕过零成本——该案若采纳，硬闸必须落在**装载边界**：`assemblePluginRow`（apps/shell/boot.ts:431-441）与 `loadSession`（packages/ac-shell-rows/src/plugin-dev.ts:97-115）在 `ctx.plugin(mod)` 之前校验模块 name 不落官方命名空间（`ac-` 前缀 / IMPORTED_ROWS 名），命中即 fail-closed 拒载（代码不进进程，早失败）。
- 完整 D11（`permissions` 第 6 词 `risk` 经人审授予，门行查授予快照）**不依赖命名约定**，是正路终态——命名封禁仅是止损，二者不互斥。
