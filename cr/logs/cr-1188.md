# cr-1188 session-archive 受理语义 + archive/completed 发射链补齐 + archive-review 透传

## 动机（三个连环缺陷）

用户反馈「归档触发失败:ipc回帧超时(15000ms)——对端未应答」。排查发现三个连环缺陷：

1. **admin 帧 await 全流程**：`admin-frame.ts` `session-archive` 处理 `requestArchive(...).then(...)` ——等分钟级整理 run 完成（REVIEW_TIMEOUT 10min）才回帧，撞宿主 ipc 控制帧缺省 15s 超时。前端 catch 出「归档触发失败」，但壳侧流程照跑——功能「实际正常」的假象。测试用例名「受理回执」与实现语义错位，mock 立即 resolve 掩盖。
2. **archive/completed 全链断头**：前端 `chat-core.ts` `onSessionArchived` 等 `archive/completed` 广播收口（pendingArchiveConv 复位 + 重载会话）——但 D11 迁移后壳侧 `archive.ts` 从不 emit 该事件，ws-bridge 桥接目录有条目、前端有消费，中间没人发。即使不超时，pending 也永不复位。
3. **archive-review 旗标透传断裂**：`reviewRun` 的 run 带 `meta:{'archive-review':true}`，但 boot.ts run-started 旁带帧只透传五键（丢 meta）→ 宿主 stream-bridge 转发又只透传四键 → 前端 `feed-core:2159` 判 `meta['archive-review']` 恒 false → 归档整理 run 被当普通 run 点亮 busy + 状态卡（cr-1187「40 小时」问题的直接触发链）。且壳链路 llm/delta 发射无隐藏过滤——主线 ws-bridge 有 isHiddenRun 查表（archive-review + 自会话桶），新架构壳侧等价物缺失，整理 run 的流式内容直接泄进用户会话。

## 修复

受理语义 + 发射链 + 旗标透传 + 隐藏过滤，四层一次补齐：

| 层 | 文件 | 改动 |
|---|---|---|
| 帧协议 | `ac-envelope-core/src/stream.ts` | StreamMeta 增 `runMeta?: Record<string, unknown>`（run 机制旗标透传位）；新增 `event` 帧变体（低频机制事件直通：name + payload）；isStreamFrame 对应判别 |
| 壳发射 | `apps/shell/boot.ts` | run-started 帧 meta 携带 runMeta（LoopRunRequest.meta 全程）；llm/delta 发射前按 hiddenReviewRuns 查表（run-started 登记 archive-review、after-run 清表）过滤整理 run 流；archive/completed 监听 → event 帧上行 |
| 宿主桥接 | `ac-post-office/src/stream-bridge.ts` | run-started 转发 args[0] 附 meta（runMeta→meta）；event 帧分支直转同名前端帧（args=[payload]） |
| 受理语义 | `apps/shell/admin-frame.ts` | session-archive 改受理即回帧：requestArchive 后台执行（catch 落日志），立即返回 { triggered, conversationId } |
| 完成广播 | `ac-shell-rows/src/archive.ts` | 事件目录声明 archive/completed（emit）；requestArchive 两收束点（正常 + conversation 缺席降级）emit completedOf；archiveAndRebuild 返回归档条数（载荷） |

前端零改动——`onSessionCompressed`（受理反馈）与 `onSessionArchived`（完成收口）两段式早已就位，等的就是壳侧这条链。

## 验证

## 残留（后续候选）

- hiddenReviewRuns 只盖 archive-review——自会话桶（a~a）机制 run 的隐藏（主线 isHiddenRun 第二分支）在壳链路仍缺等价物；feed-core 前端有 `isSelfPairConversation` 早退兜底（run-started case），风险低，与主线语义对齐可后续单开 CR。
- run-started 前端帧只透传路由四键 + meta——前端如需消费更多 run 级旗标，同法扩展。
