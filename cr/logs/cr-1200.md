# cr-1200 live 会话步边界乱序丢段根修

日期：2026-11-22 · 状态：doing → done · 标签：#webui #fix

## 症状

前端会话 live 流式期间，偶尔出现思考与正文整段消失、只剩一列工具卡片；刷新/收束重拉后自愈。

## 根因（三环叠加，缺一不病）

1. **两帧不同赛道，物理可乱序/丢失**：`llm/delta` 零 IO 直播快路；`step/journaled` 走 durable 慢路
   （after-step → `void journalStep()` fire-and-forget → 写队列 → 逐行 fsync → onAppend → 旁带帧）。
   B3 旁带瞬态语义（不重发、断连即丢）+ Windows fsync 偶发停顿 → 上一步收束帧可迟到甚至整帧丢失。
2. **载体冒领**（feed-core `carrierOf`）：步1 delta 到达时惰性建卡条件查「无 lastStreaming」——步0 载体
   还在流（等它迟到的收束帧）→ 条件不满足 → 回落路径把步0 载体无条件登记为步1 carrier
   （只防了 stepId 盖写，没防索引冒领）→ 两步内容并轨一个气泡。
3. **终值全量替换抹空**（`onMessageEnd`）：`asst.content = data.content ?? asst.content` —— 空串非 nullish
   照样覆盖。纯工具步（rows 只有 tool-call）的终值把并轨内容一并抹空；工具结果走独立 `tool/result` 帧
   幸存 → 「只剩工具卡」。settlement 重拉历史完整 → 自愈 → 症状偶发难记录。

探针复现：sandbox/probe-live-wipe{,2,3}.ts（修复前精确复现症状：链内步思考/正文长度 0 + 工具卡幸存）。

## 修复（三处，均在 feed-core.ts 前端状态机——乱序到达在 B3 语义下合法，前端必须自洽）

- **A** `carrierOf` 跨步冒领防护：回落命中驻留【别步 stepId】的载体 → 返回 null（不冒领不登记）；
  无驻留键的载体（旧式流）仍可认领。
- **B** `llm/delta` 前沿（惰性建卡处）：lastStreaming 驻留别步 stepId = 残留载体 → 定格收口
  （isStreaming=false，内容原样保留——步事实在账本，settlement 重拉对账补权威行）+ 建本步新载体。
- **C** `step/journaled` 兜底建卡处：同款收口+建卡（迟到收束帧补投到已流一步的分区即此形态）。

裁决：B/C 收口的是「收束帧已丢失」的确定残留——后端不会重发（B3 瞬态），分区 streaming 仍在
（后续 delta 会重点亮），权威内容由 settlement 重拉/收敛对账补齐，收口不丢内容只停转圈。
