# cr-1323 后台 job 完成通知附带输出尾部（免 Agent 二跳查日志）

## 动机
后台 job 收束后只回投一行 status + detail（exit code），Agent 需再调 job logs 才能拿到
输出——收束判定（成败/产出）大概率都要二跳。反馈回路里多一跳 = 全量使用每任务多一次工具调用。

## 根因
ac-jobs 契约早有终态输出通道（JobOutcome.output → settle 回写 meta.output——webui jobs 预览
消费面已存在），但 shell producer 从未填它，wakeup 通知也只消费 detail——通道在、供源缺。

## 改动面
- executor.ts：background/handoff 两处 jobs.start 的 done promise 收敛为 doneFromClose 工厂
  （原两块逐字重复）：close → 终态 + outcomeTail（日志尾读 30 行/2000 字 + ANSI 清理）
  作为 JobOutcome.output；全文恒在日志文件，job logs 独立预算不受影响。
- wakeup.ts：noticeText/digestText 消费 meta.output——通知正文附「输出尾部：」预览
  （TAIL_MAX 1000 字）；无 output 时保留原兜底文案（行为不变）。digest 逐条附带。
- index.ts：GUIDELINES_JOBS 段更新——通知自带尾部预览，需要完整/更早输出才用 job logs。

## 裁决
- 实现住宿主侧（meta.output 单点供源），非 wakeup 私读 logFile：服务归位（wakeup 是投递
  面不是读取面）；全局快照复用 500 字预览已有语义（subagent/宿主 producer 可自然跟进）。
- 在 close（而非 exit）尾读：进程退出 + 写端关闭，日志内容完整；killed 路径也携带尾部
  （诊断价值 > 通知体积）。同步 fs 尾读（close 时进程已死无阻塞风险）。
- 通知预算克制：正文 1000 字预览、meta.output 全量 2000 字上限，其余走 job logs。

## 验证
- wakeup 单测 9/9（新增 cr-1323 用例：单条/digest/截断/无 output 兜底）。
- 集成 8/8（shell-jobs + shell-timeout-handoff——含 meta.output 断言）。
- pnpm typecheck / check:deps / 定向 eslint 全绿；test:unit 482/483 文件，唯一失败
  ac-host-rows/timers-row（与本改动无依赖交集，单跑 26/26 过——全量并行负载 flake）。

壳侧装载行（shell.yml 点名 ac-jobs/ac-shell-tools——注意 jobs 是骨架行而 shell-tools 走
Agent 菜单）→ restart_shell 后生效。

## 验证中发现的两处修正
1. 文案「输出尾部预览如上」与实排布（尾部在下方）矛盾 → 删该句。
2. tailText 截断原取**前** max 字——这是尾部预览，结论/报错在最末几行，
   从头截恰好裁掉最该看的部分。改为保留末段（前导 '…'），测试加
   HEAD/TAIL 标记断言锁定该语义。
