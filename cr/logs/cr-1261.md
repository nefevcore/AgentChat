# cr-1261 approval 键四档化（会话层 allow-full）

## 动机

mathematician 会话实证 cr-1248 遗留死角：设置链 s=allow 免卡注 sandbox-access，而弹卡
（唯一 full 注入点）被 allow 关闭——越沙箱命令在 allow 会话成为无声死胡同（不弹卡、
不通、无 in-band 授权出口），诱发 Agent 挖 update_agent_profile 提权（cr-1262）。

用户裁决：前端四档（deny / ask / allow-sandbox / allow-full），把「预授权」与「全权」
两个都有道理的语义并存，选择权交用户。

## 裁决

- **会话键 approval 四值**：allow-full 免卡注 full-access（越沙箱自动生效——跳过
  write 白名单/命令级扫描/readDeny 默认表；恒拦闸〔防自杀/授权工件写/accessDeny〕不随
  full 跳过）；allow-sandbox 免卡注 sandbox-access（= 原 allow 语义）。
- **第二/三层不动**：Agent settings / 全局 config onAsk 维持三值（allow = sandbox 档
  强度）——持久预授权没看过具体命令，不给静默全权。授权范围与知情强度对齐：会话键
  是唯一「用户此刻显式选择」的层。
- **存量兼容（零迁移，cr-947 access/elevation 先例）**：存量 'allow' 读侧映射
  allow-sandbox（保守——已有会话行为不变）；写恒新词（UI enum 四值）。

## 改动面

- ac-permission-gate/src/index.ts：OnAsk 增 AllowStrength；onAskOf 会话层四值读取
  （allow-full → {allow, full}；allow-sandbox/'allow' → {allow, sandbox}）；s=allow
  分支按 strength 注 full-access/sandbox-access；头注决策序同步。
- ac-conv-settings：BUILTIN_KEYS approval enum 四值 + options 文案（allow-full 标注
  「含沙箱外路径/机密文件，慎用」）；contract.ts 值域类型 + 头注。
- 测试：gate +1 用例（四档三态：full 无卡 full / 新词 sandbox / 存量 allow 映射
  sandbox）；规约 §五登记表更新。

## 验证

typecheck / check:deps / 定向 lint / 定向 64 测（gate 37 + conv-settings 9 + host-face
11 + client-row 7）/ 全仓 465 文件 3517 测全绿。

## 运行时生效

宿主侧装载行改动（ac-permission-gate 门 + ac-conv-settings 键面 + ac-host-face）→
restart_host。生效后 mathematician 会话由用户点 allow-full 即可全权（配合 cr-1262 转正
白名单不必需——白名单是持久授权，四档是会话级）。
