# cr-1315 越面拦截结果 durable 化（tool/after-execute emit）

- 日期：2026-11-25 · 状态：done
- 分析基线：会话 01a21179-d79f-7db1-87ca-44a5e451ae02（`__creator__` 域）

## 现象

程序化模式下模型直调面外工具（read / load_skill / 幻觉名 todo_await_helper），
step/tool-call 行落盘但无 step/tool-call-result 行：
- 跨 run 回放前缀不一致：live 喂 `{ok:false, error:'工具…不在本 run 工具面…'}`，
  回放合成 `{ok:true}`（foldStepsOf finish=completed 合成空成功）——语义反转，
  会强化模型继续幻觉直调；违反 replay-contract 原则 1。
- 前端工具卡「无输出」：被拦调用无任何帧（started/after-execute），占位卡
  running 恒真直到 run 收束强收，content 空命中 noOutput 判定。

## 根因

ac-agent-loop service.ts cr-5 请求面硬闸的拦截分支直接 return 合成错误，
不经 ctx.tools.execute → tool/after-execute 不 emit → ledger 无 result 行。
正常路径两行事件的分工：tool-call 行由 loop/after-step journalStep 落（副作用前
durable），result 行由 ledger 监听 tool/after-execute 落——拦截路径撕开了这个对。

## 修

拦截分支 emit tool/after-execute（call 携带 name/args/agentId/conversationId/
runId/toolCallId 执行身份 + denied 结果）。ledger 落 result 行 / ws-bridge 前端帧
全自动接通，读侧 synthNullResults 合成路径对新数据根退化为兜底。

归位说明：after-execute 是观察通知位（emit）。与 before-execute veto 不 emit 的
区分：veto 无模型侧调用对（无 step/tool-call 行）；本拦截发生在步内、
tool-call 行已落，缺终值行才是断链。不传 durationMs（未执行，无耗时事实）。
