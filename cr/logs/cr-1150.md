# cr-1150 · 前端点击会话 unread 计数不消

> 性质：缺陷修复（未读读位/计数链路）｜状态：done｜2026-11-17

## 现象

前端点击会话（Agent 会话/独立会话/群聊），列表徽章的 unread 计数点了也不消；刷新后照旧。

## 根因（三层，同一处结构性缺陷：读位锚定能力 ≠ 行锚定能力）

1. **读位对无 seq 存量行无解**（`ac-core-utils/unread.ts`）：未读派生按「行 seq 新于水位 seq」判读，mark 只有 seq 时无 seq 行恒判未读；只按 messageId 恒等性判读时锚行以外全部计。实测本机数据：`news~user` 已有读位 seq=861 仍报 101 条未读（101 条存量行无 seq）；`admin~user` 33 行全无 seq——即「写了读位也消不掉」。
2. **进入会话的已读只发生在本地**（`ac-client-ui-conversation/feed-core.ts`）：清未读锚 = 分区已见行，刷新后首次点开分区无已见行 → 无锚不发 `session/mark-read` → 服务端读位永不推进；随后首屏旁带按磁盘读位算出的旧未读覆盖本地清零 → 徽章复活（且刷新永久复发）。本机 `meta/unread.json` 只 3 条读位即为佐证（只有被反复访问过的会话写进过读位）。
3. **群未读无锚可写**：`group/history` 行 id（群读位键）在客户端投影中被丢弃（`groupMessageToChatMessage` 无 persistedMsgId），群分区清未读永远发不出读位 → 群徽章点了不消。

附带发现并修：`toHistoryMessages` 的行级 seq 打标语句写在 loop 末尾 context 分支，agent/user/tool/error 分支各自 continue 早退 → 客户端水位从未见过真实回复行的 seq（历史行 seq 恒缺）。

## 修法

读位语义改为**位置锚**（读到行集的哪一行）：

- `unreadOf(rows, mark)`：行集 = 会话**全行集**（账本序）；messageId 在行集中的行号之后的才计未读；锚行缺席/读位无 messageId 才回落 seq 比较。宿主 `session/history`/`session/unread` 不再预过滤 assistant 行（锚行可能非事实行）。
- `mergeMark`：位置锚优先——异锚以「后读」ts 定先后、同锚幂等；裸 seq 单调取大、升格位置锚恒接受、不被裸 seq 降格。
- 客户端：读位锚 = 尾部已见行 persistedMsgId（位置锚）+ 已见行最大 seq（记录面）同发；无已见行时登记**读位意图**，首屏行到达（`session/history` / `group/history` 合并）后补发；意图未落定/活跃分区的权威旁带不覆盖本地清零。
- 群历史行透传 id → persistedMsgId，群读位可按位置锚消读。
- `toHistoryMessages`：行级 seq 打标改 pushRow 内联（全分支可达）。

## 已知边界

- 多端并发读：位置锚以 ts 判先后（服务端不解析行号），滞后端点的旧位置可能回退（与 cr-1146 既有 messageId 口径同风险；单用户多端可接受）。
- 读位落定失败（RPC 失败）静默降级为旧行为：本地已清、刷新后由服务端水位恢复。
