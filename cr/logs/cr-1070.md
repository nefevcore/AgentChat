# cr-1070 回滚 cr-1069 的 4.5 档位免审环（旧框架回潮）

## 动机（用户裁决）

- cr-1069 把旧 ac-security 的「base 档审批、sandbox+ 档自由」语义当遗漏补进决策序（4.5 环）——但权限门控方案的本意就是替换该机制：免审正路是 risk 自评（§五「根治位」）与设置链，不是环境按调用方档位一刀切。
- 语义冲突实锤：4.5 在设置链之前，sandbox 档 Agent 的会话键 approval=deny 被档位跳过——用户否决权被架空，违反「设置链是 ask 归宿的唯一裁判」。

## 改动面

- 源码回滚：`packages/ac-permission-gate/src/index.ts`（tierExempt 函数 / 主链调用 / 头注释 / import 四处）。
- 测试固化：4.5 三例改写为守护测试——sandbox/full 档 ask 建议仍走设置链（弹卡）+ 会话键 deny 对任意档位生效。18 用例绿。
- 文档：计划档决策序回滚 + 新旧框架差异表补「base 档审批、sandbox+ 档自由 = 已废」行；交接档关键事实 #1 更新为 cr-1070 裁决。

## 轴分工（修正后终态）

- access 轴（权限栏/Agent 档位）：只管执行边界（full 跳路径复检/命令扫描；sandbox 的白名单照旧）——不参与审批决策。
- approval 轴（会话键/Agent settings onAsk/行 config）：ask 建议的唯一归宿裁判。
- 免审三正路：risk 声明（可信工具自评 allow）、设置链 allow、run 级批准缓存。
