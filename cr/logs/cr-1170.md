# cr-1170 timer set 补 conversationId 参数（v1 语义回归 + 归属闸）

> 登记于 2026-11-20 · →cr-1164（换轨参数面回退）· 状态：done

## 动机（用户反馈）

set 的 conversationId 当前无条件烘焙发起会话（identity.conversationId），模型无法指定其他键。实际需求：定时任务常指向 agent~agent 自会话（与用户聊天线程解耦——v1 时代 news 即如此），应允许 agent~* 任意归属对象。**这是 cr-1164 换轨的参数面回退**：契约层 TimerAction.conversationId 与 dispatch 管线一直支持，只是 set 参数面没暴露（v1 有此参数）。

## 改动面

- **timer-face**：set 接受 `conversationId` 参数（显式指定优先，缺省仍 = 发起会话——回归兼容）；schema 与工具描述补词汇；返回体带终值。
- **归属闸（timers-row mayAddress）**：显式指定时校验键归属本 owner——
  - `a~b` 键 owner 须为任一侧（含 owner~owner 对角线自会话，会话线程按需物化不要求已存在）；
  - 单段键（用户会话/群 gid）须已存在于 owner 的 sessions 目录；
  - 全局条目（GLOBAL_OWNER）恒过——扇出面是 target 白名单。
  防跨 Agent 注入：news 指定 `nana~user` = 向 nana 的会话线程投信，拒。
- **测试**：face 行为四断言（越界拒 / a1~a1 过 / a1~other 过 / 缺省烘焙不变）。

## 裁决

- dispatch 侧不改：`convId = action.conversationId ?? 对角线缺省` 与 `sender = conversationId ? 'user' : target` 既有语义已正确——本批只开参数面 + 加归属闸。
- 自会话（owner~owner）不要求已存在：会话线程由邮局按需物化（v1 语义——news 的自会话定时先于会话建立）。
- 单段键要求已存在：防猜测他人会话键（无 ~ 的用户会话键归壳侧生成，宿主无归属校验依据，以存在性代归属）。
