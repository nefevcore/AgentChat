# cr-1187 状态卡计时锚钉陈旧 viewer 消息修复

## 动机

用户反馈（news~user 长会话）：发起压缩请求后状态卡显示「正在等待模型响应… 40 小时 3 分 29 秒」——计时从非 0 开始。定位为通病：`deriveRunStatus` 计时锚 = `lastViewerTs`（末条 `agent_id==='user'` 消息 ts），timer 唤醒 / 归档整理 run（reviewRun）/ agent 互信等**机制触发 run 不产生新 viewer 消息行**，锚点钉在用户上次真人发言（数十小时前）。

## 根因链

- `runStatus.ts` 计时锚单源 `lastViewerTs`——2026-10-28 用户裁决「整体耗时从用户发送那一刻起算」只覆盖用户消息触发场景，机制 run 场景从未被覆盖；
- feed 分区态已有 `runStartAt`（run-started 帧到达时刻，每轮 run 重置）——锚定它即可，无需新状态。

## 修复

- `packages/ac-client-ui-conversation/client/runStatus.ts`：`sinceMs = Math.max(lastViewerTs(d), d.runStartAt ?? 0)`。用户 run 两者几乎同刻（语义不变）；机制 run 锚定 run 启动时刻，从 ~0 起算。注释同步更新裁决语义（2026-10-28 裁决推广而非推翻）。
- 测试：`run-status-dock.test.ts` 两新用例（机制 run 锚 runStartAt / 用户后到消息仍锚 viewer ts）+ 一处既有断言更新（runStartAt=100 > viewer ts=42 → sinceMs=100）。

## 验证

- 定向 `npx vitest run packages/ac-client-ui-conversation`（63 文件 326 用例全绿）；全量 unit/test:unit、typecheck、check:deps、定向 eslint、`pnpm build:frontend` 全绿。
