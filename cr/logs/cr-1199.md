# cr-1199 config 写面注册化：CONFIG_KEY_PREFIXES 退役 → 包级 ac.configDomains 声明聚合

> 指令来源：2026-11-22 用户两点指令（①config/merge ②消除静态白名单改注册式）。
> ① 经查已由 cr-1173（done）完成——mergeConfigDomains + config/merge RPC 在档；
> 本 CR 只做 ②。→cr-1168（白名单补 source 的补漏先行）→cr-1173（merge 面）。

## 动机

CONFIG_KEY_PREFIXES 是 ac-host-webui 里的静态 Set——「平台自己规定的配置键，
平台自己的写接口写不进去」的 cr-1168 事故根因就在这：新域（source）要写面时
得改宿主侧包源码。注册化后：**读面在哪，写面就归谁注册**——每个域由其
owning 包在 package.json 声明，聚合进 row-catalog，白名单随目录走。

## 设计裁决

1. **词汇新设 `ac.configDomains`（包级）**，不复用 ac.rows[].configKeys——
   后者是行内配置键面（patch.yml 校验词汇，cr-1037），语义正交；域是全局
   config.json 顶层键，是包级关切（llm-pool 行属包）。
2. **聚合走 row-catalog 顶层**：gen-row-catalog 并入 `configDomains:
   {域: 声明包}`，运行时零扫描（readCatalog 双读透传——disk.ts 同步修）。
3. **白名单 = 目录全集（静态）**，不跟装载行走——与改动前行为完全等价：
   改动前静态 Set 也是九域全量（不随行集裁剪变化），注册化只换事实源。
4. **域 → 包分配**（按 config.get 读面证据）：
   - llmProviders → ac-llm-pool（index.ts:359 读）
   - searchProviders + tool → ac-web-tools（index.ts:132 读 searchProviders；
     tool.web_search 由其 web_search 工具消费，存量在 web-tools 时代积累）
   - source → ac-source-core（index.ts:115 读 source.fs）
   - timer → ac-host-rows（timers-row.ts:364 全局条目落 config timer.tasks）
   - llm + settings + ui + session → ac-client-ui-settings（设置页域：
     llm 顶层池形态存量、settings.devMode/fileSnapshots/mcp/security 多家读、
     ui/session 设置页遗产域——写面归设置面板 owning）
5. **config-face 五函数参数化**：assertConfigKey/writeConfigKey/removeConfigKey/
   saveConfigDomains/mergeConfigDomains 加 ConfigDomains 参数（ReadonlySet）；
   CONFIG_KEY_PREFIXES 常量删除。缺席 = 空集 fail-closed（未注册即不可写）。
6. **web-api 接线**：域集合在 RPC 注册时从 readCatalog(deps.catalogFile ??
   DEFAULT_CATALOG_FILE) 派生一次；DEFAULT_CATALOG_FILE 从 face-ops.ts export
   （原为模块私有）。
