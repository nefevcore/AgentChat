## 动机

ISSUE-20（2026-11-16）：`__creator__` 无预授权缺省 deny，`node cr/cr.mjs` 判 ask 后 8 分钟连拒 33 次、盲试 20+ 次，最终 write 自签 `agents/__creator__/permission-gate.json`（onAsk=allow）解锁——三面暴露：

1. **面1** cr CLI 被 risk 判 ask 后无人桶不可用（fail-closed 无出路）；
2. **面2** Agent 可 write 自签授权工件（本部署 dev 模式 accessDeny 解除；且 shell executor 无 deny 面——生产态预授权 Agent 经 pwsh 也可写，侦查修正）；
3. **面3** deny 文案不说明判定层（不知谁拒的、怎么解锁——盲试风暴直接根因）。

## 收口补强（2026-11-22 运行时验证后）

运行时验证发现一处设计缺口并修正：`authzWriteViolation` 原置于 `!unrestricted` 分支（仅非 full 档拦）——而 `onAsk=allow` 预授权注入的 full 恰是「改写自己授权文件」最危险的档位（本部署其余 19 个 onAsk=allow Agent 由此仍可经 pwsh 写授权工件）。已提升为**任何档位都拦**（与 `hostKillViolation` 同款语义：授权工件是审批信任根，不是沙箱边界，不随 full 跳过）。运营者写口（UI/host 服务面）不经本函数，不受影响。

## 强度更正（2026-11-22 实测）

运行时实测发现 shell 面文本闸**可绕**，并据此修正声称：

| 面 | 强度 | 依据 |
|---|---|---|
| fs 工具面（write/edit/sre/fs-search） | **可靠**——路径解析后结构化判定 | 按名恒禁任意层级、不随 dev 解、不随 degraded 丢；覆盖 ISSUE-20 原始事故路径 |
| shell 面（pwsh/bash） | **best-effort，可绕** | 实测：`Get-ChildItem … \| Where-Object { $_.Name -like '*gate*' } \| %{ Get-Content $_.FullName }` 不含字面量即通过，读出 `{"onAsk":"allow"}`；变量拼接同理 |

**纠正上一轮的两处错误声称**：① 「任何档位都拦」在 shell 面只对字面量成立，通配/变量可绕；② 「Agent 自己连读都读不到授权文件」不成立——fs 工具面读不到，shell 面用通配能读。已在 executor 注释内写明可绕形态与「可靠性由 fs 面承担」的归位。

**残留风险（需独立立项）**：生产态 + 已预授权（full）Agent + 变量拼接 → 可改写**其他 Agent** 的授权工件（提权他人）。fs 面已封，shell 面未封。候选方向：shell 执行前的命令路径审计（静态解析受限）、或授权工件写入的运营者签章（写侧校验生效来源）。
