# cr-1180：timer-v3「停用但保留」语义补全（enabled:false 条目面蒸发修复）

> 2026-11-21 · #timer · 状态：done

## 动机

用户反馈：timer-v3 没有「停用但保留」状态。排查发现设计文档 §三字段表确实缺席 `enabled` 语义（示例 JSON 出现 `enabled` 但字段表、排程语义、list 展示均未定义），且**实现面有实质病灶**——UI（TimerPane 暂停开关 / TimersPanel「X/Y 启用」计数）与 LLM 面（update 的 enabled 参数）都按「停用但保留」设计，行实现掉了链子：

- `entriesByAgent` 装载时 `filter(e => e.enabled !== false)` 后只留启用条目——停用条目从条目面蒸发：list 不可见、update/cancel 报「条目不存在」；
- face `set` 用 `[...entries(owner), entry]` 整表写回，盘上停用条目被**静默丢弃**（save 拒不了也感知不到）；
- `save()` 把停用条目的记账 `forget`（armedAt/lastSeq/诊断全清）——恢复即失忆。

## 裁决（设计补全）

| 语义 | 裁决 |
|---|---|
| 停用（enabled:false） | 条目留在 timer.json 与条目面（list 可见、update/cancel 可达），不参与排程与分发（不投递不计时） |
| 停用记号 | state.json 记 `pausedAt`（时刻——诊断面「何时停的」） |
| 重新启用（恢复） | 基点快进：`armedAt` 抬到恢复时刻（停用期间刻度**不回补**——catchup 下界与 after-last 锚都从恢复点起算）；`lastSeq` 快进到各订阅源现值（停用期间事件**不补投**）；清 pausedAt |
| 与 cancel 的边界 | cancel = 撤销归档（条目删除进 timer-archive）；停用 = 保留在表。工具描述与指南段明示区别，防 LLM 误用 cancel |
| once 过期 + skip | 恢复时刻已过 at 且 missed:skip → arm 归档（expired 语义不变——不是停用病灶，是条目本身寿命尽了） |
| 手动 triggerNow | 停用条目仍可手动触发（诊断面语义——「我现在就想测这条」） |

## 实施中发现并修复的次生问题

1. 翻转检测时序 bug（自纠）：初版 `wasEnabled` 在 `entriesByAgent.set` 之后查——查到的恒为新状态，翻转永远检测不到。改为覆盖前取内存表快照。
2. arm 停用兜底两轮修复：无 persisted 记录也建（首次装载的停用条目）；set 后补 saveState（reload 的 saveState 在 arm 循环之前）。
