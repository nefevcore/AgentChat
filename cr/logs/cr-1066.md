## 关键裁决（实施中发现）

- approval 会话键进 BUILTIN_KEYS 而非门行 registerKey：壳/宿主分树下垫片注册的键宿主 set 面不认识（readSettings 回读校验滤掉 + UI 写键被静默清除），内置注册打通宿主读写链全链。harnessTier 先例正受害于此（宿主 UI 设不进去）。
- D7 无人桶判定先于设置链：plan 伪码把 self 判定放 s=ask 分支内，但 D7 原文是「无人桶恒拒，even 设置 allow」——判定前置才不违字面义（V5 同口径）。
- 批准 = 单次按 full 执行：不只过门——变异 execution.call.access = full-access（契约合法来源第 3 处），否则 base 档审批后仍撞工具内沙箱墙（effectiveAccessOfCall 读 call.access），审批失去意义。
- 信任面简化版：owner = tools.getWithOwner 的注册 fiber 名；官方行恒 ac- 前缀；动态插件 fiber 名 = manifest.name（非 ac- = 不可信恒 ask）。精确信任面（permissions 第 6 词）批 3。
