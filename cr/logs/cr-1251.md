# cr-1251 注入消费点贯通：落账对齐模型消息序

- 性质：fix + refactor（方案 D——注入词汇收口）
- 关联：cr-971（消费点落账原则，只兑现了 steer 通道）/ cr-1101（消费点中央包裹——字节收口先例，本 CR 补位置）/ cr-1182（datetime before-run 通道）/ cr-1249（skill 目录 before-run 通道）/ cr-1191（台账曾误判「收束落账=既有设计」——webui run 键归口掩盖，resume 前缀重建暴露）

## 现象

messages.jsonl 中 inject 行落盘 seq 倒挂：日期锚/技能目录真实 ts 在 run 起始（用户消息后 50ms），
却落盘在全部 steps 之后（seq 9/10 vs steps 2-8）。四条注入通道中三条倒挂，仅 steer 队列正确。

## 根因

壳侧 ConversationService.recordContext 把全部注入挂 pendingSteerInjects，
等 loop/steer-consumed（步边界 splice steerQueue）落账——但消费点事件只覆盖 steer 通道：

| 通道 | 消息进数组点 | 消费点事件 | 现状落账 |
|---|---|---|---|
| steer 队列（busy 插话/ask 忙步作答） | 步边界 splice | ✓ | 消费点落账（正确） |
| durable 队列（injectDurable/load_skill） | step() 内 before-step 后 | ✗ | 收束兜底（差 1-N 步） |
| before-run 改写（datetime/skill/env-pulse/memory） | waterfall 内 append | ✗ | 收束兜底（倒整个 run） |
| run-idle 尾注（ask 挂起作答） | 自然停点后 push | ✗ | 收束兜底（差续走步长） |

抽象根因：「注入消息」与「注入落账」两套词汇无贯通因果链——loop 知道消息进数组的全部时刻，
落账方却在受理时点挂 pending 凭事件猜消费点。生产方双写（append messages + recordContext）
的元数据半边与消息半边无位置关联。

## 方案（用户裁决：落盘位置与实际消费位置对齐 + 统一事件签名）

注入成为 loop 一等词汇，生产方只声明「注什么」，loop 在消息实际进数组处统一发射消费事件，
ac-ledger 订阅落账（与 journalStep 订阅 loop/after-step 同构先例，service.ts:90）：

1. `loop/inject-consumed` 统一事件（@mode emit @scope run）：四消费点统一发射，
   载荷 = { agent, conversationId, runId, messages, metas }——steer-consumed 并入退役。
2. before-run / run-idle waterfall call 增设 `inject(msg, meta)` 注入面（LoopRunCall 扩展），
   生产方不再直接 append request.messages。
3. steer() / injectDurable() 元数据参数扩展（meta 随队列 item 走，消费点随行发射）。
4. ac-ledger 构造器订阅 inject-consumed → journalInject 落账 + session/context-injected 帧。
5. 壳侧 pendingSteerInjects 全机制退役（Map/订阅/flushPendingInjects/收束兜底）。
6. 生产方五方双写改单写：datetime（含新增 timeInfoLine 落账——用户裁决：进入 LLM 消息都必须落账）、
   skill（目录+手势+load_skill）、env-pulse、memory、ask-questions（忙步 steer 带 meta + idle 半边）。

## run-idle 返回形状裁决（用户问询①）

「返回 LlmMessage[]」是 2026-02-00 ask 挂起重构立的契约，全仓消费者唯一（ac-ask-questions），
契约注：「持有注入：等待材料就绪后返回 LlmMessage[]——循环注入工作数组并继续步循环（同 run 续走）」。
设计动机（events.ts:151-170 契约注）：waterfall 语义自然——「系统是否有待注入材料」的裁决权交给领域行，
返回即注入；尾部追加是为 KV 前缀缓存（头部注入使已缓存前缀整体后移，实测 miss 30→425）。
改造：返回形状退役，元数据经 call.inject 携带——ask-idle 半边改注入面，返回空数组；
继续条件从「返回非空」改「call 注入面有写入」（loop 可观测）。
用户裁决③：统一事件签名（不保留旧 steer-consumed 别名过渡——全仓仅壳侧一个消费者，无兼容包袱）。

## 不变量（本 CR 立法）

「凡进入 LLM 消息数组的注入体必须落账，落位=消费点真序」（用户裁决②的通用化）。
live 与回放恒等（replay-contract 原则 2）由此从「包裹字节」扩展到「位置」。

  before-run/run-idle call.inject 注入面 + steer/injectDurable meta 扩展 + durable 消费点发射。

  过渡直落（生产方已全量迁移，待后续清理）；steer 受理登记删除、消费点 inbox 对账保留。
- 生产方五方双写改单写：datetime（含 timeInfoLine 落账——裁决②不变量）、skill（目录/手势/load_skill
  驻留 meta）、env-pulse、memory、ask-questions（忙步 steer injectMeta + idle 注入面）。
- 行为变更（正向裁决）：datetime 注入不再寄生 session 门控——精简树（无 ledger/session）与子壳
  有会话键即注入（防重由 .day-anchor 私有状态独立承担，不再依赖落账面在场）。
- 测试迁移：datetime/skill/catalog/env-pulse/memory/ask 的 session 替身改消费点桥
  （订阅 inject-consumed 模拟 ledger）；host 四 e2e 断言更新（mock 回显日期锚——同日幂等）。
