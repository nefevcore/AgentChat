# cr-1213 R-1 登记制根除：participants 键形权威反演

## 背景（三连点修后的根除裁决）

用户诉求：uuid 登记冲突永久阻断会话对（registry 只在内存、无 TTL、一条错误登记
一直阻断通信、只有重启宿主才清空）。摸底发现 cr-1175（A 案宿主服务通道）与
cr-1177（infra sender 旁路）**均已实现落地**——但结构性风险属实：registry 仍是
「首见近似登记制」，participants 由首封信封 sender/to 推导。同一根因历史三次点修：

| CR | 事故形态 | 当时修法 |
|---|---|---|
| cr-641 | restart_host 控制信封复用会话键撞子集判定 | uuid 换独立机制域键 |
| cr-1046 | done-reply 投 user 撞 conflict + ipc 吞错 | 壳侧换对桶键 + ipc 超时 |
| cr-1177 | plugin/grant 回投撞 [agent,host] vs [user,agent] | infra sender 已登记放行旁路 |

三次都在症状面点修。用户给三条路径（①uuid/conversationId 解耦 ②participants 键反解
③TTL/降级），裁决走②（根除向）：

- ③否决——TTL 到期重登记还会被下一封毒化、降级会放宽防线，都是补丁。
- ①在机制域已由 cr-1175 完成（六类控制信迁服务帧）；会话域 uuid=会话键是 M19
  对桶模型承重特性（sessions/<uuid> 对桶目录、runAddress 寻址、双方账本同址域），
  全量解耦成本远超收益且无必要——键本身携带权威名册信息。

## 根因

R-1 登记制的名册来源错误：participants 从「首封信封的 sender/to」近似推导。首见
登记即定终身（内存无 TTL）→ 任何非典型首封信（机制回投先至/乱序/群名册演化后
新成员发言）都会写入错误名册，之后所有正常信撞 conflict → 永久阻断。cr-1177 的
infra 旁路只修了「infra sender + 已登记」组合，反序案例（host 回执先于 user 首信
到达 → 首见登记 [agent, host] 反向毒化 → user 首信后至撞 conflict）未覆盖。

## 修复（键形权威制）

**键即权威**——名册从会话键反解，不从信封推导：

| 键形 | 名册 | 语义 |
|---|---|---|
| `a~b`（两段） | `[a, b]` 键反演 | 1v1 对键（pairKey 产物）——**键即权威**，唯一可反演键形 |
| UUIDv7 形 / 单段 / 三段+ | 首见 `[sender, to]` | 对话两端（A3 双向对话语义——e2e-user 实测收敛：UUIDv7 形首封 user 信后 agent 回信须放行） |
| `gid~member` | 群行 authoritative 注入 | 群成员流键——与 1v1 键**词法同形不可辨**，权威归群行（lookup-first：登记集优先于键反演） |
| 机制域 sender 首见（host/@） | defer 不登记 | 回执先于真实首信不毒化；已登记恒放行 |

- `participantsOfKey` 单源住 ac-core-utils（紧邻 pairKey/memberStreamKey 词法族）——只反演两段对键（其余键形 undefined，防止单段路径吃掉 UUIDv7 形）。
- `ConversationRegistry`：`setRoster`（群行 boot/join 重放——无条件覆盖支持名册
  演化，并矫正 boot 窗口反演误登）/ `register(uuid, sender)`（来信校验面：名册
  miss 键形反演建立，hit 则 sender 名册成员判定，集外 conflict fail-loud）。
- **机制域豁免收窄**：`isMechanismEndpointId`（host/@ 群地址）——比 cr-1175 保留字
  窄，`user` 不豁免（真会话参与者，cr-1046 防线保真）。
- **to 退出校验面**：投递目标由路由可达性裁决；多播展开后逐成员独立投递，非名册语义。
- 群行 `syncRegistry` 改 `setRoster`——**顺修存量隐患**：旧制下群 join 后新成员
  扇出会被陈旧登记集拦截（register 返回 conflict 被忽略），新制 authoritative 覆盖。
- router 多播臂（membersOf 注入面）：成员表 = 宿主注入的权威拓扑，同走 setRoster。

## 根除效果

1. 任何一封信（机制回投/乱序首达/群名册演化后发言）都无法毒化会话键登记。
2. 「永久阻断 + 重启才清空」事故类整体消灭；内存态重启自愈（1v1 键反演恒等重建，
   群流键群行 boot 重放重建）。
3. cr-1177 反序案例（host 回执先到反向毒化）顺带根除。
4. user 保留字不豁免——cr-1046 防线（[designer,news] 后 [news,user] 判 conflict）
   语义保真（单测锁定）。
