# cr-1143 · live 会话 todo/goal dock 卡不刷新（cr-976 帧族迁移补漏）

## 现象

前端会话 live 期间（Agent 正在跑 run），任务清单 dock 卡与长期目标 dock 条不更新；
只有切换会话（watch 兜底）或 run 收束后（goal 半边）才恢复——用户报告「live 的时候没有展示 todo 清单和 goal 目标」。

## 根因（两层）

cr-976 B 案 D3-3 一步切换把前端帧族从 `tool/after-execute` · `loop/after-run` 换成
`tool/result` · `run/settled`（bridge-events 目录注释 + e2e 断言旧帧零出现），迁移漏了两处：

1. **TodoDockCard.vue 仍监听已退役旧帧**——live 期间刷新链完全死透（事件名不存在，
   永不匹配；唯一兜底 = 会话切换 watch）。
2. **useGoalTracking.ts 迁了新帧但匹配条件次生缺陷**——`subcall === true && name === 'goal'`。
   `ac-ledger` 落账 `step/tool-call-result` 行时只在 run_code 子调用时写 name（顶层模型
   直调不落），而 `tool/result` 帧的 name 源自落账行——直调模式（绝大多数会话）下 goal
   工具的帧无 name，永不匹配；live 期间只剩 run/settled 收束后一次性刷新。

## 修复

- `ac-ledger/src/service.ts`：工具名恒落（name 是 ToolCall 契约必填位，事件族消费方
  按名路由不区分直调/子调用；子调用档案只追加 subcall 标记与名参全文）。
- `ac-client-ui-todo/client/TodoDockCard.vue`：刷新帧迁 `tool/result` · `run/settled`；
  判定抽纯函数 `todoRefreshTrigger` 进 tasks.ts（数据管线 owning 文件，可单测）。
- `ac-client-ui-goal/client/useGoalTracking.ts`：tool/result 匹配去 subcall 条件。

## 测试

- `ac-ledger/tests/p3-event-appended.test.ts`：工具结果行断言补 name 恒落。
- `ac-client-ui-todo/tests/todo-card.test.ts`：todoRefreshTrigger 四例（含旧帧族不触发的回归锚）。
- `ac-client-ui-goal/tests/goal-tracking.test.ts`（新）：直调帧（无 subcall）触发刷新、
  run/settled 兜底、他人桶不触发。composable 测试姿势 = renderToString 驱动 setup。
