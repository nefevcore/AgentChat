# cr-1149 timer 脚本契约硬化（判定脚本易错点）

- 日期：2026-11-17
- 状态：doing → 本批收口
- 关联：cr-1147（timer 脚本化重做，本条基线）

## 动机（回归里暴露的四个坑）

1. **set 落盘即首探**：脚本「无 state 分支直接 return action」会在设置后立刻投递一次
   唤醒信（回归 A 实际触发）。`firstCheck` 只是干跑预测，没把「运行期会立刻投」讲清。
2. **utils 易错点**：`u.after(iv, from)` 第二参传 ISO 串（a.now）崩 `getTime is not a function`；
   `u.ms(iv)` 返回毫秒数不是 Date，容易直接当 next。
3. **`active: false` 首检仍落盘**：要等首轮探测才归档，期间 list 可见，测试残留得手工 cancel。
4. **next 类型未校验**：干跑返回字符串 `'2027-01-01'` 或 `new Date(0)` 都通过——前者运行期才炸，
   后者静默钳地板且无提示。

## 改动面

### packages/ac-timer-core/src/index.ts
- `u.after(iv, from?)`：from 收 Date 或 ISO 串（a.now 可直传）；锚点/间隔串解析不出**一律抛错**
  （此前静默退化为 now / 间隔归零）。
- `u.at(spec)`：解析不出或已过 → 抛错（此前静默返回 now）。
- 新增 `inspectVerdict(verdict, now)`：error = 类型层不合法（verdict 非对象 / next 非 Date 或 NaN /
  action 非串 / active 非布 / 缺 next）；notes = 可运行但可疑（next 在过去 → 钳 10s 地板提示）。
  active:false 是完成态，不校验 next。
- 删 `DEFAULT_RECHECK_MS`：无消费方的死常量（缺 next 实为脚本错误路径，未改语义）。

### packages/ac-host-rows/src/timers-row.ts
- `check()`：verdict 先过 inspectVerdict——error 整轮不处置 + 退避（fail-loud）；notes 经 noteVerdict
  记诊断面（同文本不刷屏）。
- `dryRun()`：返回 `notes`，判据与运行期同一份。
- 新增 lastNote 诊断面（list 字段 lastNoteAt/lastNote）+ `retryAfterError` / `noteVerdict` / `forget`
  三个单点（三处重复的清理循环收敛到 forget）。

### packages/ac-host-face/src/timer-face.ts
- set：首检 `active: false` → 直接拒落盘（这类脚本不会产生任何探测轮次）；首检带 action → 返回体
  notes 明示「落盘即首探、会立刻投一次，脚本须以 a.state 初判」。
- test：支持 `state` 参数（验 a.state 分支两态）；返回 notes（含 active:false 提示）。
- 工具描述 + GUIDELINES_TIMER：补易错点（state 初判 / u.after 第二参形态 / u.ms 返回毫秒 /
  next 非 Date 当场拒 / lastNote 诊断面）。

### docs/design/archive/session/timer-scripting.md（cr-1161 归档后路径）
契约注释与 §四/§六补注（判据单源 / 首探即投递 / 首检 active:false 拒落盘 / lastNote）。

## v2（同日复测反馈：两条实测咬人）

复测反馈（2026-11-17 重启后实测）：

1. **set 首轮仍立刻投递**：v1 只加告警不改行为，Agent 视角「脚本必须以 a.state 初判」不构成防线。
2. **过期 next + action = 每 ~10s 一条刷屏**：v1 把过去 next 钳地板且放行 action，地板 10s 就成了投递周期。

### 根因与修法（v2）

- 首轮投递根因不在脚本纪律，在宿主：新条目无断点 → arm() wait 0 → 立即 check →
  带 action 就投。而 set 本来已经干跑了首检（结果此前只用于提示，白白浪费）。
  → **干跑即首检**：save(owner, entries, seed?) 新增 seed，set 把首检
  state + next 落为初值（scriptState + persistNextAt），arm 见未来断点直排——
  **set 不再投递**，首条唤醒信由下一次真实探测（返回体 scheduledAt）发出。
  脚本首个真实轮次看到的 a.state 已是首检 state。
- 刷屏根因：过期 next 被当作正常节奏。→ inspectVerdict 过期分档：
  过期 ≤ CHECK_FLOOR_MS(10s) = 刚到期（执行耗时/边界竞态）按到期排地板；
  更久 → **error 整轮不处置 + 退避**（不投递），list 见 lastError。

### 改动面（v2）

- ac-timer-core：inspectVerdict 过期分档（LATE_TOLERANCE_MS = CHECK_FLOOR_MS）。
- ac-host-rows：save 增 seed 参数（初值落盘，arm 前生效）；check/dryRun 语义不变。
- ac-host-face：set 传 seed、返回体增 scheduledAt，notes 改为「本次不投递，
  下次真实探测在 X」；工具描述与 GUIDELINES_TIMER 同步（首检时机 + 过期即错）。
- 测试：core 过期两档 2 例；row 增 save seed 用例、过期超容差改判为「错误退避不投递」。
- 文档：timer-scripting.md（现 archive/session/）§二/§四/§六 同步 v2 口径。

### 验证（v2）

- pnpm typecheck 通过；定向 vitest（timer-core / timers-row / host-face）4 文件 59 用例全绿。
- 含新增用例：save seed → 2s 窗口零投递且 nextAt 已排未来；过期超容差 → 零投递 + lastError。

## 有意不做

- 没把首探改成「set 后不立即探测」：探测循环定位下首检就是节奏起点（自检与首检预测都依赖它），
  改为告警 + 文档引导 state 初判，避免第二套语义。
- 没加 next 的时间上限校验（远未来是合法排期）。
