## 动机

P4-1 收口时 turn-gap-fallback 探针被【直播侧无键】锁死恒命中——观察窗
「归零即删」不可达；同时 cr-1276 预留的读面接线（readFallbackProbes 接
控制台）从未落地，观察窗实际未启动。附带发现：直播步行只驻留 stepId
（runId 前缀）、不驻留 runId——纯直播窗口里 buildTurns 的 runsInWindow
扫不到 run 键，cr-1285 的 run 键挂靠与 sameRun 豁免在【未经历历史合并
的直播窗口】同样不命中（隐藏缺口，测试族用「历史展开形」行遮蔽了它）。

## 改动面

- `client/feed-core.ts`：
  · onStepStart：stepKeys.runId 在场 → 载体驻留 runId + turnId（= runId
    ——fold 投影同语义：run 承载行 turnId = run）；
  · onMessageEnd：步终值补驻（journal 兜底建卡 / 旧载体复用场景）；
  · createFeedCore 装配点挂 window.__AC_FALLBACK_PROBES__ = 
    readFallbackProbes（浏览器 dev 读面——对齐 __AC_HOST__ 命名风格；
    typeof window 守卫，Node 测试进程跳过）。
- `client/fallback-probes.ts` / `client/types.ts`：注释校准
  （turn-gap-fallback 剩余缺席面、turnId 直播语义）。
- `tests/live-turn-keys.test.ts`（新增 4 用例）：delta 惰性建卡驻留 /
  journal 终值驻留 / 纯直播窗口注入卡 run 键挂靠（inject-run-miss 不计）/
  Node 守卫契约。
