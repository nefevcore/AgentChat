## 后续三-A：roster 预览权威化（已落地）

### 痛点

runs/snapshot 的会话尾部摘要（last）取 replay **任意末行**——真实数据里末行常是
run-end/step 事件行（无 role），被当成「最后谁说了话」喂给 roster 前端
（AgentList formatLastMessage / bumpAgentById 对账基准）→ 预览身份漂移。

### 改动（packages/ac-host-webui/src/face-ops.ts）

- `SessionIndexStatsFace` 窄接口增 `sessionMeta(convId)`（use-time 软取，行摘除 = 旧形态回落）。
- computeSnapshot 展开阶段（memo miss 会话）：last 的 **身份/时标改发言口径**
  （sessionMeta.lastRole/lastAgent/lastSpeechAt——SQL 单源）；**正文与 messageCount
  仍取 replay**（SQL 不载正文；投影口径计数不变）。
- 索引缺席 → 任意末行兜底（旧行为，良定义降级）。

### 架构修正：只读聚合（初版违规）

初版直接调 `sessionMeta(convId)`——它内部 `refreshConversation`（给未入账会话
读全文件 + 写 records 行）。runs/snapshot 是高频面（60s 轮询 + 事件驱动，每拍
对多个 memo-miss 会话取元数据），索引库重建/迁移后的冷启动会被隐式触发成
全量预热——与 cr-1138「full:true 才是显式预热、首次代价高」的裁决相悖。

修正：`sessionMeta(dataRoot, convId, { refresh?: boolean })`——`refresh:false`
= 只读聚合（不建索引行，未入账返回 null，调用方回落）。runs/snapshot 用只读
模式；索引仍由显式读面（session/meta RPC、historyView）按需建立。

稳态实测：runs/snapshot 65ms / 1312 会话（索引已建，memo 命中，零额外成本）。

### 测试

face-runs.test.ts 新增两例（各自独立 root，避免多个 registerOpsFace 的 boot
预热航班与 cleanup 竞态）：
1. **cold**：索引未入账 → 只读聚合 null → 回落 replay 末行；探针断言
   `sessionMeta(refresh:false)` 仍为 null（高频面没偷建索引）。
2. **warm**：显式建索引后 → last 身份/时标走发言口径（run-end 不占位）；
   用户末发言（原形 role:'agent'+agent_id:'user'）→ role 'user'、无 agent_id。

（假 sessionIndex 包装须忠实代理 refreshStats——写成 refreshConversation 会让
「不隐式建索引」的断言失去意义。）
（ac-host-webui devDependencies 增 ac-session-index——仅测试用真实现，生产面仍是窄接口零依赖。）

## 后续三-B：singles 摘要改道 session-index（裁决：不做，理由如下）

交接原设想「computeLedgerSummary 改走 session-index 聚合面——性能面也赚（盘读转 SQL）」。
实施前审计发现两处前提不成立：

1. **语义不可无损替换**：LedgerSummary.count = projectUserReplay 投影行数
   （幂等去重/run 单行/空终稿剔除后的终稿层），session-index records.total = 原始
   行数（含 step/inject/run-end）——两者数值不同。count===0 是前端 isSingleFresh
   （新会话开场态）与 agentId 清空拒绝的判据，换源即行为变化。title/agentId 派生
   需要首条发言正文——SQL 不载正文，盘读省不掉。
2. **性能痛点不成立**：singles-row 已有 stale 惰性重算 + 指纹 memo 体系
   （cr-870/978/981），replay 读只在指纹变化时发生一次；冷对账一次性。

「两处重复实现走散」的实指（face-ops convSummaryMemo 与 singles computeLedgerSummary
两处读 replay 派生摘要）已由后续三-A 收敛掉一半：身份面统一走 sessionMeta SQL 单源。
若未来要完全收敛，正解是给 session-index 加「终稿层投影行」表（新功能，另行立项）。
