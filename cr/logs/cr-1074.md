# cr-1074 权限门批3：精确信任面 D11 落地

## 动机

- 批 1 简化信任面（fiber 名 ac- 前缀）存在伪造向量（cr-1073 定级）：fiber 名是插件源码自选字段（cordis Plugin.Base.name——display name，无校验），与 manifest.name 独立；恶意插件源码 export const name = 'ac-fs-tools' 即骗过前缀判定，risk 自评恒 allow 直通。
- D11 裁决（cr-1062）：信任位 = manifest permissions 第 6词 risk（REVIEW 面人审授予）——安装时人审显式授予，未授予即不可信（建议覆盖恒 ask，还能用）。

## 改动面（四切片）

1. **装载边界硬闸 + fiber 名钉死**（`packages/ac-shell-rows/src/plugin-guard.ts` 新文件）：`guardPluginModule(mod, manifestName)`——模块 name 落官方命名空间（ac- 前缀 / 6 个官方特例行名 / IMPORTED_ROWS 键 / root）即 throw 拒载（fail-closed，代码不进进程）；否则钉名 manifest.name（函数插件包装为 Object 形态）。接线：`apps/shell/boot.ts` assemblePluginRow + `plugin-dev.ts` loadSession（两条装载通道全覆盖）。
2. **manifest 第 6 词**（`packages/ac-plugin-core/src/manifest.ts`）：KNOWN_PERMISSIONS 增 `risk`；REVIEW_EXPLICIT_REQUIRED 增 `risk`（与 process/shell/ui 同级人审强制）。EXECUTION_EXPLICIT_REQUIRED 不含（risk 非执行边界——是信任位，未授予不拒载只降为不可信）。前端 shim `apps/ui/src/shims/@agentchat/protocol.ts` PluginPermission 同步。
3. **门行信任面双臂**（`packages/ac-permission-gate/src/index.ts`）：`trusted()` = 官方 fiber 名（ac- 前缀 / shell-tools-gate）∪ `options.riskGranted?.(owner) === true`（回调注入，缺席 = 查无 fail-closed）。`apps/shell/boot.ts` 装配注入 `makeRiskGranted`（boot 期读 plugins/registry.json 授予快照一次——插件重装需重启壳才装载，快照与装载面同步；fail-soft：registry 损坏 = 空集全不可信）。
4. **测试**：plugin-guard.test.ts 6 例（命名空间判定 + 拒载 + 钉名 + 函数包装）；gate.test.ts 补 2 例（grants 含 risk 采信直通 / 不含覆盖弹卡）。

## 关键裁决

- **EXECUTION vs REVIEW 分轨**：risk 只进 REVIEW_EXPLICIT_REQUIRED（人审面显式勾选），不进 EXECUTION_EXPLICIT_REQUIRED（装载 fail-closed）——risk 是信任位不是执行边界，未授予 = 插件还能用（建议被覆盖恒 ask，每次过审），符合 D11「不可信还能用」语义。
- **免审通道自动授予**：installFromDir grants = manifest permissions 全集（既有语义）——插件声明 risk 即在免审快照内，A7「装载 = 授权动作」信任归位安装审，无需改安装器。
- **fiber 名钉死是 D11 前提**：cordis 无名 fiber 继承最近命名祖先（Fiber.name getter）——无名插件（技能教的最小形态）owner 会错挂 shell-plugin-dev-row / root；钉死后 owner = manifest.name 恒成立，registry grants 查询有稳定键，且装载边界硬闸保证官方命名空间不可冒充——前缀臂自此可信。
- **riskGranted 经回调注入而非门行直读 registry**：门行（域行）不 import ac-plugin-core（宿主安装器域），保持行零安装器耦合；boot（编排层）读快照注入——机制归位。
