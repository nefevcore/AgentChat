# cr-1139 · unread 读位换血：锚定计数 + 快照 v2 多 tab 收敛

日期：2026-11-16 · 状态：done · 前序：cr-1137（词法闸，症状根因修）

## 根因（承 cr-1137 分析）

计数制的三缺陷：① at-least-once 帧面（重连对账补投 / remote-link 双链）重投同事件超计；② 多 tab 全量覆写 localStorage——后写者胜，他 tab 已清未读被复活；③ 无对账轴（丢了/多了永远错了）。

## 方案裁决：锚定计数（非读位 diff）

原设想读位锚定制（head/lastRead 锚 diff）。实施前实证否决：message 私信帧面 message_id 是否透传未证实（emit 源动态构造，静态无法确认）、群帧无任何单调锚、inject 锚 58% 缺席（真实数据 265/450）——纯读位 diff 需补后端帧面，超出前端换血边界。改锚定计数：

- **增量幂等**：bumpUnread(id, anchor)——锚在场查 `_unreadAnchors` 集合去重（有界 500，超限弃置重建）；锚缺席退化计数 +1（现状语义，零回归）。四写点锚：run/settled→runId（对账补投幂等的核心收益）；message-received→message_id；context-injected→injectionId；群→message_id ?? from+content 组合。
- **快照 v2**：{version:2, entries:{dialogId:{n,ts}}}——ts = 计数落定时刻。读写穿按 ts 合并（mergeUnreadSnapshots max-ts 语义）：他 tab 新计数采纳、旧写穿不覆盖新清除。v1 纯计数快照按既有脏数据语义丢弃。
- **storage 事件多 tab 收敛**：他 tab 写穿 → 本 tab 内存对账（watchUnreadSnapshot；node 无 window 幂等 no-op）。

## 改动面

- `unreadStore.ts` 重写：UnreadEntry {n,ts} + v2 解析 + mergeUnreadSnapshots + watchUnreadSnapshot + __setUnreadSnapshotRaw（测试面保持）。
- `feed-core.ts`：DialogFeed.unreadTs + bumpUnread 原语（锚登记表）+ 四增量写点改造 + clearUnread 带 ts + 水合 v2 + 多 tab 对账订阅。
- 测试：unread-anchor.test.ts（8 例——runId/message_id/injectionId/群锚幂等、退化语义、v1 迁移、多 tab 合并）；unread-restore.test.ts 更新至 v2 形态。
