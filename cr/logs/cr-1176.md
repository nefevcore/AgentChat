# cr-1176 修复 interaction/reply 无活壳即抛错：按盘上归属拉壳后重投

> 性质：缺陷修复 / 状态：doing→done / 读者：宿主 web 面与 ask_questions 链路维护者

## 反馈现象（2026-11-20）

宿主/壳重启后，WebUI 里的 ask_questions 问答卡仍在，点「回答」无法提交（无声失败）；
先新发起一条会话（消息）让 Agent 壳起来，再去回复同一张卡片即成功。

## 根因

`interaction/reply` RPC（`packages/ac-host-webui/src/face-shell.ts`）只在**活壳**中
枚举持有该 interaction id 的壳；一只都不在场时直接抛「未找到待答条目」。
而壳是按需拉起形态（宿主重启后壳不在场是常态，见 apps/host/boot.ts cr-734 注释），
所以重启后回复必然失败；发一条新消息经 `ensureAgent` 把壳拉起来后，同一回复自然成功。

cr-824 批一把 `interaction/list` 改成盘直读（壳不在场 100% 可读），但同族的写面
`interaction/reply` 没有同步补拉起语义——读得到、答不了。

## 改动

- `face-shell.ts`：新增 `interactionTopOwnerOf` 盘上定位（`agents/<id>/interactions.jsonl`
  命中即返回该 agent；children 域不进本面，子域 pending 归 cr-734 boot 扫描拉父、
  父壳代答走 subagents.answer）。
- `interaction/reply`：活壳枚举落空后按盘上归属 `ensureAgent(owner)` 拉起再投帧；
  拉起失败 fail-loud 带归属与原因；枚举段逐壳容错（单壳 boot 窗口不应答不拖垮回复，
  reply 幂等——duplicate 回原回答）。

## 链路核实

- 壳内 durable 落 per-agent 域（apps/shell/boot.ts 行选项锚定 agent 目录；
  apps/shell/tests/rows-import.test.ts 断言 `agents/eta/interactions.jsonl`）。
- 壳 boot 时 jsonl store 从盘加载 pending 记录，拉起后 reply 必命中；
  run 已死时 `durable-interaction/replied` → ac-ask-questions late-reply deliver 唤醒新 run。

  拉起重投、拉起失败带归属）+ 既有 21 例全绿。
