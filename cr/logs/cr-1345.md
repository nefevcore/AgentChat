# cr-1345 busy 用户排队信消费点落账（三轨闭合）

- 性质：fix（对称补全 cr-971/cr-1119 落账原则第三轨；伴生前端排队 dock 断连对账）
- 日期：2026-11-27

## 现场（01a21543 会话 messages.jsonl）

走查 09:27:45/09:27:54 两条 busy 排队用户消息（lane=next-turn）收信即落账（L998/L1001），
物理位置插在占门 run（run-send-…-8ixn，09:19–09:31:58）的 step 39–64 步流中间；09:32 链跑
消费后各生成一条回复。账本时序 ≠ 真实轮序：落账时刻 09:27、消费时刻 09:32——按 cr-1119 同款
标准衡量即「账本时序错」；双视图/回放按文件序渲染时排队消息混进他轮输出流（用户报告的
「队列 dock 不真实反馈 + 混杂其他会话消息」观感的结构性成分）。

## 根因

cr-971 为 busy-steer 立「受理不落账、消费点落账」原则时，注释写「run/queue 路径不受影响」
——queue 路径当时未被审视，是豁免而非裁决。三轨不对称：steer 信消费点落（cr-713）、
机制信消费点落（cr-1119）、用户排队信收信即落。到达序落账唯一刚性消费方是「消费时行必在场」
（historyFor 复读 + 恢复面补行门），不是「何时落」。

## 修复（对称化：第三轨并入既有原则）

1. `ac-shell-conversation/src/service.ts` receiveEnvelope：mechQueued 门泛化为 queued 门
（plan=queue 一律收信不落账）；deliverQueuedMechRow → deliverQueuedRow（判据去掉 mechanism
限定，行形态 = inboundRowOf 单源——机制信 context / 用户信发言行 delivered）。链跑消费点
（runSettled→takeFromInbox）与 drainQueuedTurn 两个调用点同改。
2. `ac-ledger/src/fold.ts`：注入行回放档按 delivered 判——用户参与注入（steer 插话/ask 作答，
delivered:true）原文回放（original），其余维持词表注册档（wrapper/none）。原因：queue→steer
路径的入站 message 行退役后注入行成为该消息唯一落账，wrapper 包壳会让模型失明用户发言原文
（且 KV 前缀不保真）。timeline notice（context 行）与 trajectory inject slot 两处消费面同判据。
   - 中途方案废弃记录：曾把 injectSource='steer'（通道词）预置为 original 档——通道词不表语义
（回执转投通知同走 steer 通道，cr-1317 防自激引导须 wrapper），改按 delivered（cr-1333 用户
参与判据的落盘投影）判档。
3. `ac-client-ui-conversation`：useQueuedMessages 增 busySource 可选参数（busy→false 翻转触发
refresh）；QueueDockHost 接线 chatStore.contextBusy——堵 WS 断连窗口丢 queue-changed 帧后
dock 恒陈旧（帧是唯一增量推送面，refresh 原只在会话切换触发）。

## 语义影响（显式声明）

- busy 排队用户行的文件序从「到达序（插在途 run 步流中间）」改为「消费序（新 run 轨迹之前）」
——账本时序对齐真实轮序，双视图/回放不再交错。
- queue→steer 路径：入站 message 行退役，注入行单源承载（回放原文档 + IM 白名单 delivered 同行）。
- queue-remove 删除：账本从未落过行，无需回滚——语义变干净。
- 崩溃安全链不变：inbox durable + 恢复面 run 路径（cr-639 补行门收敛）；QueueDock 数据面
（内存队列权威快照）与落账时序解耦，零变化。

## 测试

- 新增：cr-1345 镜像用例（busy 排队用户信不抢跑——收信 0 行、消费点落账晚于占门 run 终稿、
回放含当前消息、续跑轮终稿照常）。
- 重锚三处：队列产品面（q2 断言 message+inject → inject 单源 + 回放原文）；同会话链跑交接
（行序改为消费序）；链跑死信跳过（b1 死信无消费点 = 无行——收信不落后死信天然无痕，旧断言
的「第一封」行不再存在）。
