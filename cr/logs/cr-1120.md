# cr-1120 会话列表污染：singles 会话键词汇锁（uuid 形）

- **日期**：2026-11-16
- **标签**：#session #webui
- **状态**：done

## 现象（三问同根）

1. 会话列表「未分组」挂出 agent~agent 长会话与 sub_ 子Agent 会话；
2. unread 未命中对应 Agent 会话，命中了未分组里的幻影行；
3. unread 数量异常（增长/不可清除）。

## 根因

服务端 `singles-row.ts` 的 `listIds`（清单注册表装载对账入口）把
`agents/*/sessions/` 下**所有**目录无差别并入 singles 身份集——agents 域
sessions/ 混住三类键：uuid（用户独立会话）、`a~b` 对桶键（agent⇄agent 对话
与群成员流 gid~member）、`sub_*`（run_code 子Agent 编排会话）。实测数据根
注册表 1220 条中 118 条脏（161 个对桶目录 + 56 个 sub_ 目录 + 11 个 meta 层
title-request 误写残留）。

污染扩散链（问题 2/3 的机制）：前端 `singlesBoard` 每次 refresh 对 list 返回
的每条会话调 `sessions.trackKnownSingle(id)` 灌入 `chatPresence.knownSingles`。
`chatOps.routeDialog` 的路由优先级第一档就是 knownSingles——对桶帧
（message-received / run/settled 等，conversationId = 'a~b'）本应路由到
`pair:a|b` 分区，被污染后误路由到 `single:a~b` 分区；增量挂到幻影分区后
unread 也随行（run/settled 路径 isViewerDialog 对 single 分区恒 true）。
用户点开任何真实会话都清不掉（clearUnread 只清激活分区）——表现为「unread
命中错误对象 + 数量异常」。agent~agent 对话在后台定时器/自主社交中持续产生
新帧 → 幻影行持续累积未读。

另：meta 层还有 11 个非 uuid 键残留——`title-request` 受理面历史上对对桶键
也会落 meta/sessions/<a~b>.json（viewOf 对 agents 域对桶目录返回非 null 视图）。

## 修复（会话键词汇锁）

singles 会话键的完整词汇 = uuid 形（v4/v7 兼容，`issueConversationId`
= uuidv7、前端 `issueLocalConversationId` 同构）。词法即身份，四处收口：

1. **服务端谓词**（`singles-row.ts`）：`isSingleSessionId`（uuid 正则）+
   `assertSingleId`（原 assertId 升级——非 uuid 形 fail-loud）。全部 RPC
   受理面（create 指定 id / update / fork / archive / delete）+ title-request
   受理面统一换用。
2. **listIds 词汇锁**：meta/sessions 层与 agents 域两处目录枚举均按谓词过滤——
   对桶键 / sub_ 键 / meta 残留一并不进 diskIds；装载对账 reconcile 按新
   diskIds 剔除历史脏条目（自愈，无需数据迁移）。
3. **前端 presence 守卫**（`ac-client-ui-conversation/client/index.ts`）：
   `trackKnownSingle` 只收 uuid 形键——knownSingles 是 routeDialog 第一优先级
   路由表，第二道闸（幂等双保险）。
4. **存量自愈**：前端 `pruneSingleUnread(activeIds)` 在每次 singles refresh 后
   清不在列表内的 single 分区未读（既有原语，本次修复后列表不再含幻影行，
   幻影分区未读随之清除写穿）。
