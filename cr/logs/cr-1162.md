# cr-1162 TokenGauge 会话切换读数不跟随（固定开销面归属判定）

> 承接 cr-1160（压缩+概要 V2）首轮诊断遗留问题 3。

## 现象

切换会话时 Token 占用占比不跟随变化，只有点开弹层才更新。

## 根因

`systemPromptContent` / `toolDefs` 住 chatStore **全局单例**（还与 SystemPromptPanel 共用），
而 TokenGauge 无锚点态分子 = `tokenCount + 系统提示 + 工具定义`。二者叠加：

- `refetchOverhead()` 只在 `toggleTokenPanel()`（打开弹层）与装配面变化时调用；
  切换 watch（agentId / single.id）只重拉 `session/tokens`，**不碰开销面**；
- 于是切换后分子 = 新会话 tokenCount + **旧会话**系统提示/工具定义 →
  ①占比不跟随（旧开销量级盖住 tokenCount 变化）②读数系统性偏高；
- 点开弹层 → refetchOverhead → 开销换新 → 数字跳变（用户观察到的「点开才更新」）。

## 修法（两次返工的产物，记录以备后鉴）

### 第一版（已否决）：切换时 clearOverhead 清全局状态

在 chat-core 加 `clearOverhead()`，切换 watch 调用。**否决理由**：SystemPromptPanel
已有自己的切换清空+重取（SystemPromptPanel.vue L83-88）。两个 watch 并发时若
TokenGauge 后执行，会作废旧面板正在飞的响应 → 面板空白且不重试（它的兜底 watch
只在 panel/visible/agentId 变化时触发，agentId 已变过）。**教训：共享单例状态不做
就地清空，各消费方只判自己的读数。**

### 最终版：归属键判定（不碰全局状态）

| 改动 | 内容 |
|---|---|
| `tokens.ts` | 新增纯函数 `gaugeViewKeyOf(data)`：group→gid / single→sid / direct→`direct:<agentId>`（前缀防与 sid 撞键）；null = 无视图 |
| `TokenGauge.vue` | `overheadKey`（本组件最近一次取开销时的视图键）+ `overheadFresh = overheadKey === viewKey`；`systemPromptTokens`/`toolDefsTokens`/`overheadLoading` 全部按 `overheadFresh` 过滤——不属于当前视图的开销视为 0（回落既有「弹层从未打开 = 比例维持会话净占用」口径） |
| `chat-core.ts` | 两个 request 加 `overheadSeq` 竞态守卫：发起新请求抬号，迟到响应按号丢弃（TokenGauge 与 SystemPromptPanel 共用这对状态，防旧响应覆盖新视图） |

行为链路：首挂载 overheadKey=null → 开销 0（与旧口径等价）；开弹层记录当前键 → 取实值；
切会话 viewKey 变 → fresh=false → 开销 0（**修复点**）；再开弹层 → 记录新键 → 实值。
