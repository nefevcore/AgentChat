# cr-1084 approval 等会话键草稿期写哨兵键未物化进真实 sid

## 主诉

前端新会话发送消息，但会话上的 approval 会话键没有物化进 run 中——草稿位选「工具审批=本会话自动放行」后发消息，权限门仍回落 deny（弹卡或缺省拒）。

## 根因链

1. 新会话 = 草稿位（cr-847 延迟落盘 / cr-894 单例草稿态）：id 是哨兵 `__pending__`（PENDING_SINGLE_ID），真实 sid 首条消息 `dispatchDraft()` 才签发。
2. ChatInput 会话键写口（toolModeConvKey = props.single.id）在草稿位 = 哨兵词。实验性菜单 approval 走 selectExtKey 泛写 → `conv-settings/set { conversationId: '__pending__' }`。
3. 宿主写面 `humanPresentOf('__pending__')` 单段词法按 singles sid 判有人 → 放行落盘 `meta/conv-settings/__pending__.json`（修复前实锤在盘：{toolMode, browserTier, approval}）。
4. 发送时 dispatchDraft 签发真实 sid 物化，无任何机制把哨兵键搬到真实 sid。
5. run 的 conversationId = 真实 sid；权限门 onAskOf 第一层 convSettings.effective(sid) 落空 → 回落 Agent/全局/缺省 deny。toolMode/browserTier 因「跟随上次选择」偏好在会话切换 watch 重放时写真键自愈（但草稿期照样写脏哨兵）；approval 无偏好面、无重放——不自愈，即主诉。

## 修复（三层）

1. **前端正路**：ChatInput 增 `setConvSetting`/`convSettingStored`/`onDraft` 统一边界——草稿位五个会话键写口（model 1v1 / toolMode 继承+选择 / browserTier 继承+选择 / extKey 泛写含 approval）暂存进 board（PendingMeta.convOverrides，localStorage 随草稿留存）；两个读侧 watch 草稿分支回显暂存值、偏好回放也写暂存。
2. **物化搬运**：SingleBoard.dispatchDraft 在 singles/create 成功后把暂存键逐个 `conv-settings/set` 写到真实 sid（失败 warn 不阻断发送——同 model 覆盖尽力语义）。取入口快照（create 内 created 帧先触发 retireDraft，现值已空）。
3. **服务端防线**：web-api conv-settings/set 对哨兵词 fail-loud 拒收（与 cr-1083 无人桶拒收同姿态）——旧前端/其他写面再造哨兵残值即显性报错。

数据根 `meta/conv-settings/__pending__.json` 残留已物理清除。
