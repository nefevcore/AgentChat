# cr-1292 冻结消息 reactive invariant 崩溃根修

> 2026-11-24 · #render-pipeline · 现场来源：restart_host 后 553801ms 处
> 视角宿主崩溃退位（TypeError: 'get' on proxy: property 'toolCalls' is
> a read-only and non-configurable data property...expected '[object Array]'
> but got '[object Object]'，buildTurns empty 判定读 msg.toolCalls）。

## 根因（最小复现已锁）

复现链（sandbox/proxy-repro3.cjs，5 行核心）：

1. 直播行（普通对象）写入 dialogs 深层 reactive（ref 深包装）→ Vue 包
   reactive proxy；
2. `mergeHistory` 写回 `d.rawMessages = nextRaw.map(freezeMsg)`——
   nextRaw 含来自 reactive 的引用（streamingTail/吸收换身新身）→
   **freezeMsg 冻结的是 vue proxy 而非 raw 对象**；
3. Object.freeze(proxy) 把属性变只读不可配置，但 proxy 的 get trap 仍返回
   深层包装值 ≠ invariant 要求返回原值；
4. 后续经 reactive 容器读 toolCalls（buildTurns empty 判定）→ Proxy
   invariant TypeError → 整个视角宿主崩溃退位。

触发面 = restart_host → converge/settlement 首屏重拉（merge 非首屏混合
reactive 引用 + 既有直播行）——用户报「restart_host 时会话刷新报错」即此。

Vue 对 frozen target 本不包 proxy（防炸设计）——本 bug 是**反序冻结**：
先包 proxy 再 freeze，绕过了 Vue 的防护。

## 修复

`freezeMsg`（feed.ts）：剥 reactive 壳再冻结——
`Object.freeze((m as { __v_raw?: ChatMessage }).__v_raw ?? m)`。
`__v_raw` 是 vue reactive proxy 的公开内部约定（get trap 特判直回
target；普通对象无此键恒等通过）。feed.ts 零 vue 依赖纪律不破（鸭子法
不 import）。11 处调用点（全部在 feed-core）自动获益。
