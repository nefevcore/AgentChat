# cr-1293 冻结不变量收口补修（closeAllStreaming/closeRunningToolCalls 经 freezeMsg）

> 2026-11-24 · #render-pipeline · 前置：cr-1292（freezeMsg 剥壳——症状侧）。
> 根因定位与复现脚本由外部 Agent 会话完成（A/B 对照 + 真链复现），
> 本批采纳其修复方案并补测试。

## 根因（比 cr-1292 记录更前一步的真入口）

`closeAllStreaming`（feed.ts）用索引赋值换身：
`msgs[i] = { ...msgs[i], isStreaming: false }` —— 换出来的新对象是
【未冻结普通对象】，不经 freezeMsg。cr-1282「入位即冻结、漏改必抛」的
构造性防线在每次 run 收束/步界收口时被撕开（外部 Agent 实测：

    入位后: 写入被拒（不变量守住）: TypeError
    收口后: 写入成功（不变量未守住）| isFrozen: false

此后该未冻结对象经深层 reactive 被包 proxy（cr-1292 崩溃链的入参形态）。
cr-1292 剥壳修复掐断了链尾（喂进 freeze 的 proxy 被剥壳），故线上已不炸
——但那是症状侧兜底；收口绕过入位冻结面这一根因未修。

同款写口共三处：closeAllStreaming L800 / closeRunningToolCalls L818+L831。

## 修复

三处换身产物全部经 `freezeMsg`（函数声明提升使前向引用无碍）。
修复后外部复现脚本（freeze-invariant-gap.mjs）翻转：

    收口后: 写入被拒（不变量守住）: TypeError | isFrozen: true
