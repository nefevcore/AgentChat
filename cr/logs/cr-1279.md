# cr-1279 —— 工作区垫片补 resolveFile（媒体物化最后断点）+ 附件行路径回退

> 状态：done（2026-11-24）｜前置：cr-1278（消息链路附件旁路 + 视觉门控配置）

## 现场（cr-1278 修完后的第一次真实发图）

用户发图（`628b5dee…jpg`），链路前五段全部打通、账本已落附件：

```json
{"role":"agent","agent_id":"user","content":"早上好，看得到我吗？\n[附件] …",
 "attachments":[{"kind":"image",
   "ref":"C:\\…\\workspace\\home\\files\\__creator__\\_tmp\\bfc2d08abd91.jpg",
   "filename":"628b5deead8f11cf4c3f5eeef668547c.jpg"}]}
```

但模型收到的仍是文本占位 `[图片无法加载: 628b5dee….jpg]`——该文案唯一出处
`ac-openai-completions/src/index.ts:412`（`materializeAttachment` 的 `resolveMediaRef`
返回 undefined 时降级）。即：**引用已到位，物化失败**。

## 根因

`ac-llm-pool` 的 `workspaceMediaResolver`（`src/index.ts:246`）按主线 ac-workspace 语义调
`ctx.get('workspace').resolveFile(ref)`；壳侧该服务由**垫片** `WorkspaceShim`
（`ac-shell-rows/src/shims.ts`）提供，而它只有 `root` / `sandboxWorkdir` /
`agentWorkdir` / `sandboxAllowedPaths` / `conversationWorkspaceRoot`——**没有 `resolveFile`**。

```ts
const ws = ctx.get('workspace', false) as { resolveFile?(relPath: string): string } | undefined;
if (typeof ws?.resolveFile !== 'function') return undefined;   // ← 恒落此分支
```

`typeof` 软判把「服务缺方法」静默降级成「文件不可物化」：全链最末一跳断在类型断言上，
既不抛错也不日志，症状只有「图片看不到」。

## 改动

**`packages/ac-shell-rows/src/shims.ts`**（壳侧垫片）：

- 新增 `resolveFile(ref)`：
  - 词形两形态并存——workspace 相对（`files/<id>/_tmp/x.png`）与**绝对路径**
    （cr-22 上传 `absPath` 主形态，前端 `imageAttachmentsOf` 也以它为 ref）；
  - 包含判定基准 = 数据根 ∪ 已登记工作区根（`meta/workspaces.json`，兼容旧
    根级位置与 `{workspaces:[…]}` 包装形态）；越界/缺失/非文件一律抛（调用方降级占位，
    媒体读面不得成为任意读口）；
  - 自足实现 `isUnderRoot`（词法 relative + win32 大小写不敏感），不引 `ac-sandbox-core`
    的 fs 身份回退——媒体引用均由上传/工作区登记产出，词法足用。

**`packages/ac-client-ui-conversation/client/chat-core.ts`**（附带修观察到的降级行）：

- `composeContent` 的附件行路径解析补第三层回退 `f.text`：此前只有
  `uploadPaths.get(hash) ?? uploadPaths.get(filename)`，页面刷新后内存登记丢失即输出
  `[附件] xxx.jpg（已上传，路径未记录）`——连 read 工具的路径都断（与同文件
  `imageAttachmentsOf` 的三层回退口径走散）。

## 端到端终局验证（壳重启后）

重启后本会话历史重派生，该用户行（`attachments` 携带绝对路径 ref）经 `foldLlmReplay`
还原为 `LlmMessage.attachments` → 池 resolver `resolveFile` → MIME(`.jpg`→`image/jpeg`)
→ base64 物化 → `image_url` 块进请求体。**模型直接看到图片内容**（无需用户重发），
实物链路实测：`bfc2d08abd91.jpg` 77,728 B → data URL 103,663 字符。

复盘点到此收束：三处断点全部闭合，且**重发不是必要条件**——账本行已持久化 ref，
重启/刷新/跨代重派生都会重新物化。

## 复盘点

三次断点（消息链路 / 视觉门控配置 / 物化读面）都是**同一类**退化：软依赖 + 静默降级，
缺任一段只表现为「看不到图」。cr-1278 已把附件旁路补齐；本 CR 收掉最后一跳。若要
根治「静默」，可考虑 `workspaceMediaResolver` 在服务缺方法时 `logger.warn` 一次——
留作后续，不在本次改动面内。
