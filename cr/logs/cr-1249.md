# cr-1249 技能目录注入改造：<available_skills> 移出 system prompt

日期：2026-11-22 · 状态：doing

## 动机（用户裁决）

「available skill 改为如日期那样的注入形式，移出 system prompt」——对齐 cr-1182 批式（datetime 全形态统一 / env-pulse）：system prompt 全静态化，会话动态材料一律走消息流注入。

## 改造前形态

- `<available_skills>` 以 SKILLS 段（SECTION_ORDER 30）常驻 system prompt；
- 技能增删/白名单修改/工作区变化 = invalidate-from-X（该桶一次 system 重置）；
- 每 run 前缀重复携带目录（无技能会话亦然）。

## 改造后形态（datetime/env-pulse 同构）

- loop/before-run：三源（本 Agent 专属 > 会话工作区 > 全局白名单）合成目录指纹（sha256 前 16 hex，输入 = 前缀+全名序列）；
- 指纹变化（或锚缺席）→ buildSkillsBlock 渲染 → recordContext 落 context 行（source=skill，label=技能目录，跨 run 永久回放）+ wrapSystemReminder 同字节 user 行双写（当前 run 即刻可见）；
- 判重 = 私有状态 files/<agentId>/skill/.anchors.json（per-agent×会话；tmp+rename 原子写，fail-soft）——回放行可能被归档压缩出清，扫描判重不可靠（cr-1182 同结论）；
- 指纹未变 → 零注入零落账；三源全空 → 不注入（load_skill 空态线索兜底）；
- 门控：无 conversationId/agent、session 行未装、dryRun（cr-1233 干跑）均跳过。

## KV 账

- system prompt 对技能行全静态：技能变更不再击穿 system 前缀（旧形态 invalidate-from-X 退役）；
- 代价 = 目录随会话历史占 token（会话内首注后若技能集不变则零追加；变化时追加新行——旧行仍占位）；归档压缩周期内出清旧行，触发指纹重注 → 目录回卷尾（自然自愈，受归档间隔约束）。

## 行为变更（显式签收）

1. 目录不再每 run 在场：仅首注与变化时注入（系统提醒：load_skill 工具描述不变——目录缺位的场景模型可用 load_skill 空态线索自查）。
2. 子 Agent（无会话键）不再收目录——旧 SKILLS 段对子 Agent 会话亦渲染；现与 datetime 同口径（子 Agent 技能可见性沿 load_skill 前的 listForAgent 面，若父任务需要则父在任务中指路）。
3. 技能变更的感知时机从「下一 run system 重置」改为「下一 run 目录行注入」。
