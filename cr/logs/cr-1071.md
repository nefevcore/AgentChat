# cr-1071 权限门批1补丁：run 缓存命中补 full-access 注入

## 动机（批2 前置侦察发现）

- 决策序 5 的 run 级缓存命中路径（scope=run 批准后本轮第二次 ask 免问）原直接 `return next()`，与首批准路径（变异 `execution.call.access = 'full-access'`）不同权——base/sandbox 档 Agent 免问调用仍按原档撞工具内沙箱墙（比首调用更严），违背「批准一次，本轮后续 ask 全免」语义。

## 改动面

- `packages/ac-permission-gate/src/index.ts`：缓存命中分支同权注入 `access: 'full-access'`（+3 行含注释）。
- `packages/ac-permission-gate/tests/gate.test.ts`：新锚「run 缓存命中 = 与首批准同权 full-access」——探针工具两次调用 access 断言 `['full-access', 'full-access']` + 免问无新卡。19 用例绿。

## 裁决

- 免问 ≠ 降权：run 级批准的人已为「本轮 ask 面」背书，缓存命中是同一授权的后续兑现，不是新的一次性放行。与 cr-1066「批准 = 单次按 full 执行」裁决同源——该语义覆盖整个批准生命周期（首次 + 缓存兑现），非仅首次。
