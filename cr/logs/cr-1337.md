# cr-1337 IM 视图前端面：切档请求竞态 + 直播过程帧门控

日期：2026-11-26
状态：doing

## 动机

cr-1335 落地后浏览器实测 IM 视图，暴露两处前端缺陷（服务端投影已正确）：

### A. 切档请求竞态（可用性 bug）

`_historyReq` 以 `session ?? to` 单槽为键、**不含视图档**。切档时旧档在途请求会顶掉新档 reqId → 新档响应被 stale 守卫丢弃（分区卡 loading）；反过来旧档响应合并进新档分区 → 轨迹行污染 IM 分区（实测出现分区清空为 0 行、status 永 loading）。

### B. 直播面与历史面口径不一致（闪变）

服务端 im 投影剔掉轨迹族，但前端直播帧未同步门控：`step/journaled`（步相位→「思考过程 · N 步」链栏）、`llm/delta-end`（工具卡）、`tool/progress`、`tool/result`、`session/context-injected`（注入卡）、`llm/chat-error`（error 红条）在 IM 档照建行——活跃 run 期间看得到，收束重拉即消失。

## 修法

1. **请求身份并入视图档**：`slotKey(to, view)` = IM 档加 `#im` 后缀；`loadHistory` / `loadMoreHistory` / `isStaleHistoryResponse` 统一走槽键。
2. **档位校验**：`histReqView: Map<reqId, view>` 记录请求时档位，响应到达先比对分区现档，不符整响应弃用（覆盖「切走再切回」的同档旧请求迟到）。
3. **直播帧 IM 门控**：`step/journaled` / `llm/delta-end` / `tool/progress` / `tool/result` / `llm/chat-error` / `session/context-injected` 各加 `viewOf(dialogId) === 'im'` 早退；`llm/delta`、`tool/started`、`onChatEnd` 的门在 cr-1331/cr-1334 已就位。
4. **pair 路径同款档位校验**：`loadPairHistory` / `loadOlderPairHistory` 不走 `requestHistoryPage`（独立 `fetchPairHistory`），首屏是整体替换——补「请求时档位快照 + 落地前比对」，异档响应直接弃用。
5. **判定单源**：散落的 `dialogs.value[id]?.viewMode === 'im'` 统一收拢到 `viewOf(dialogId)`。
