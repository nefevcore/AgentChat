# cr-1091 conv-settings 批④：值域校验退役

承 cr-1087/1088 调查、cr-1090 交接档批④。语义裁决：**落盘即真相**——键域校验三层（pattern / isValid / 回读过滤）整体退役，垃圾值由消费方天然回落兜底（approval 落缺省 deny、toolMode 未知词回退 baseFace + warn、browserTier/issueSubmit 不命中即跟随 Agent；壳侧 Shim 从不校验已运行数月零事故）。

## 改动面

- `packages/ac-conv-settings/src/service.ts`：
  - 删 `ConvSettingsKeyDef.pattern` 字段 + toolMode def 的 pattern 行（唯一消费者）。
  - 删 `isValid` 方法（全仓消费面清查：无外部 import——ac-plugin-core 同名函数无关、apps/ui 命中为 vendor 产物）。
  - `set()`：`typeof value === 'string'` 即写（键域过滤分支删）；删键只剩 null/undefined 显式语义。
  - `readSettings()`：回读只留类型闸（typeof string）——未注册键/存量垃圾值不再被清。
  - `enum` 语义改注：UI 选项列表（泛写口渲染数据源），不承担值域校验。
  - registerKey doc：回收语义改实况——卸载后键不再出现在目录/UI，已落盘值保留（消费方天然回落）。
- `packages/ac-conv-settings/tests/conv-settings.test.ts`：7 处用例按新语义重锁（非法枚举落盘、未注册键落盘、回收后存量值可读、损坏值原样透出、access/elevation 存量透出〔物理清理由 cr-1082 脚本负责〕）。

## 有意的行为变化

- 非法枚举值/未注册键：写面从「静默清」改「原样落盘」；读面从「过滤」改「透出」。
- 注册回收语义「存量值回读被清」消失——壳侧 Shim 本就同读法（typeof string 即透出），双树读面从此同形。
