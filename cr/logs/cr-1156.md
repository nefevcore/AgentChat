# cr-1156 回放压缩边界过滤修复（seq 空间倒挂遮蔽当前会话）

> 2026-11-18 · 独立既有 bug，cr-1154/1155 落地后首次用户消息触发暴露（与记忆重构无关——git diff 证实 fold/writer 零改动）

## 现象

用户向 admin~user 发送「晚上好~」：消息正常落账（seq=754），但 admin 的回复完全无视用户消息、只响应记忆注入——模型上下文里没有这条消息。

## 根因（现场数据重演）

1. 11-17 08:44 admin~user 触发 compaction，落 boundarySeq=1323（当时 seq 空间）。
2. compaction 物理重写 messages.jsonl 后，writer 的 B1 播种（尾 32KB 三文件取 max seq）错过已归档的高 seq 行——subcalls.jsonl 尾 seq=649 主导，新行从小 seq 空间（650+）重启。**seq 空间倒挂**：boundary=1323 > 当前全部新行。
3. foldLlmReplay 的压缩边界过滤 seq > boundarySeq 把 compaction 之后落账的全部行（含用户消息）静默滤出——回放只剩摘要 system 头 + 无 seq 放行的注入行。

受损面（判据：compaction 事件后落账、seq ≤ boundary 的行数）：admin~user 丢 9 行、news~user 丢 8 行。两处均自 11-17 起对回放盲，11-18 用户首次发消息才暴露。

## 修复（双维度判定）

- CompactionFacts 增 endTs（compaction/end 时刻；缺省 0 = 旧档不生效，回落纯 seq 判定）。
- foldLlmReplay 边界过滤：落账时刻晚于 compaction 收束时刻的行恒放行——物理重写后追加的行天然在事件后；seq 比较只对事件前的 shadowed 前缀负责。

## 验证

- 真实副本（admin~user 现场数据）：修复前回放 197 条无「晚上好」；修复后 248 条含「晚上好」。endTs=1794905053979 正确填充。
- 回归用例：fold.test.ts cr-1156（现场形态夹具：高 boundary + 倒挂小 seq 新行 → 新行恒进回放）。
- ledger 89/89 · 消费方三包 155/155 · typecheck · lint 通过 · 全仓单测见收口。

## 遗留观察

seq 空间倒挂本身（B1 尾窗播种错过归档高 seq 行）未修——writer 注释已声明单调口径对 append-only 成立，倒挂只伤「按 seq 判新旧」的读面；本修复后 ledger 读面已无该依赖（recordsFor 已在 cr-1155 归位 v1 行；foldLlmReplay 双维度兜底）。若后续新增 seq 序依赖读面，需先修播种。
