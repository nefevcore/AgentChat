# cr-1250 browser 首启 EPERM 与 steps 批量整批 veto

- 日期：2026-11-22
- 范围：#browser #ac-web-tools #ac-cdp-core
- 状态：done

## 问题（用户反馈两条）

1. **browser 首次启动偶发 EPERM**（workspace/home/browser-profile 占用），同进程重试即成功。
2. **steps 批量中单步被权限拒绝时 continue_on_error=true 未能续跑后续步骤**（整批返回失败）。

## 根因

**#1**（browser.ts + launch.ts）：idle 回收/启动失败的 teardown 是 fire-and-forget（Browser.close → 树杀 → 清 profile 异步进行），下一次 boot 的 profile 清理用**裸 rmSync（无重试）**——上代浏览器句柄未释放时直接 EPERM。带重试的 removeProfile 只在容忍路径（teardown）使用，单步 boot 开路通道反而无重试。「同进程重试即成功」= 第二次调用时上代清理已落定，恰好印证竞态窗口。

**#2**（index.ts）：before-execute 门禁对整次调用取动作最大层级需求（steps 逐动作取 max），一步越权（如 eval）→ 整批 veto——工具体从未执行，continue_on_error 形同虚设；语义过宽（越权的是 eval，open/read 合法却被拒）。

## 修法

- **#1**：
  - teardown 清理链记账（teardownPromise），doBoot 开新代前 await 落定——断竞态根；
  - 清理单源化：clearProfile（rmSync 重试 10×200ms 后仍锁即抛，fail-loud 可读错误）供 boot 开路；removeProfile（容忍包装，告警不抛）供 teardown 收尾。裸 rmSync 删除。
- **#2**：批量 steps 步级门禁——越权步就地标 __denied（改写 execution.call.args.steps 后放行），合法步照跑；executor 的 runOne 把 __denied 落为普通步级失败，停批/续跑统一归 continue_on_error。仅整批全越权（或单动作越权）才整批 veto（拒绝面语义不变）。

## 行为锁

tests/browser-gate.test.ts 增「steps 批量步级门禁」三臂：observe+eval 越权步续跑（denied 条目落 results）/ continue_on_error=false 停批 / 整批全越权整批 veto。
