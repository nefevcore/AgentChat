## 匹配语义改进（原设计缺陷）

cr-1217 的 `hitsAllowlist` 是**全文精确匹配**——而只读子命令必须能带参数才有意义（`grep detail ISSUE-20`、`get 1217`、`list -n 10`），全文匹配会让它们全部失效。改为三条闸：

1. **首部词边界**——白名单项之后必须空白或结尾（`list` 不命中 `liste`）；
2. **危险字符闸**——命令含 `; | & < > { } $` 反引号或换行即不收（与 `isLowRiskCommand` 同字符集）；
3. **首部匹配**——必须从命令开头起（`echo x && node cr/cr.mjs list` 不收）。

## 实测发现（重要运行时事实）

**AgentConfig 是内存快照，文件改动不自动重载**：`AgentsService.settingsOf` 读 `this.configs`（Map，L453-459），该 Map 在 boot/register 时写入。删/加 `agents/<id>/*.json` 后，内存仍是旧值——平台行为符合预期（配置装载不热更新），但与 cr-1217「装载不热更新」同款纪律：**改配置后需重启壳才生效**。

实测证据：删除授权文件后 `node cr/cr.mjs append` 仍放行——因内存里仍是旧的 allow；白名单 `stats` 放行同理，不是新配置生效。两项均待重启验证。

## ⚠️ 结论纠正（本轮实测——上一轮判断有误）

上一轮我写「删除 Agent 层设置 + 重启 → `__creator__` 回到缺省 deny」。**这是错的**：漏了设置链**第一层**。

实测：本会话 `meta/conv-settings/01a20161-6eff-7675-9673-5b1170a11771.json` 含 `"approval": "allow"`——会话键层压过 Agent 设置层与缺省 deny。因此：

| 观察 | 真相 |
|---|---|
| 删掉 Agent 层授权文件后 `append` 仍放行 | 不是「内存快照未重载」，而是**会话键 allow** 在起作用 |
| `node -e "…"`、`write` 绝对路径（均 risk=ask）也放行 | 同上——权限门工作正常，设置链第一层判 allow → 注入 full-access |
| 白名单 `stats` 放行 | **不是空转**（已实证）：白名单命中走 risk=allow **直通（沙箱态）**，未命中的命令走 ask→会话键 allow→**注入 full-access**。两者对越界路径处置不同（见下），只是「能不能执行」的用户观感相同 |

**诊断手法（可复用）**：用 `write` 绝对路径（risk 必为 ask）做二分探针——放行则问题在设置链/门，拒绝则问题在具体工具的 risk 分类器。本轮据此一路定位到会话键。

**白名单有效性对照实验**（同 cwd、同越界目标 `C:/Windows/win.ini`）：

| 命令 | 命中的层 | 结果 |
|---|---|---|
| `node cr/cr.mjs grep x C:/Windows/win.ini` | 白名单 → risk=allow **直通**（沙箱态） | ✅ 被 bashCommandViolation 拦住（越界） |
| `node cr/cr.mjs append x C:/Windows/win.ini` | 非白名单 → ask → 会话键 allow → **full 注入** | ✅ 放行执行（full 跳过路径扫描） |

结论：**白名单确实生效**，作用是让只读命令走权限更窄的沙箱档；而会话键 allow 给其余命令注入 full。两者都应保留——白名单在**无人桶会话**（`__creator__~__creator__` 等，`effective` 恒 `{}`）里更是唯一出路（否则缺省 deny 直接拒）。

## 残留风险（③ 记录在案，暂不立项）

**生产态 + 已预授权（full）Agent + 变量拼接 → 可改写其他 Agent 的授权工件（提权他人）**。

- fs 工具面：恒禁可靠（路径解析后结构化判定；覆盖 ISSUE-20 原始事故路径 write/edit 自签）；
- shell 面：文本级 best-effort，**已实测可绕**（`Get-ChildItem … | Where-Object { $_.Name -like '*-gate*' } | %{ Get-Content $_.FullName }` 不含字面量即通过）；
- 本轮执行删除时即用该形态绕闸——既是操作手段，也是强度局限的现场取证。

用户裁决：接受该残留风险，fs 面覆盖原事故路径已足够。若将来威胁模型变化，候选方向：shell 执行前命令路径审计、或授权工件写侧来源校验（让自写无效）。
