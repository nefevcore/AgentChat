# cr-1054 restart 双工具引导优化：触发条件前置

## 动机
用户反馈：restart_host / restart_shell 引导不足，agent 开发时（改了宿主/壳装载代码后）不主动调用。

根因：两工具描述「机制先行」——安全属性与时序语义占开头，触发条件（何时该调）埋中后段长段落，agent 扫读抓不到决策规则；最关键的钩子「测试全绿 ≠ 运行时已生效」（不调的代价）没有前置。creator 模板 AGENTS.md 恒需项与 plugin-dev 技能 §5 同样只说「需要时自主发起」，没给触发判据。

## 改动面
| 文件 | 改动 |
|---|---|
| packages/ac-shell-rows/src/restart.ts | 两工具 description 重写：首句=动作判据（「改了 X 后必须调」+ 不热更新警告），触发判据枚举前置具体化（host.yml/shell.yml 点名的包、apps/host 等），互斥指引（壳侧↔宿主侧）收尾 |
| packages/ac-host-rows/templates/creator/AGENTS.md | 恒需项从「需要时自主发起」改为判据式触发 + 「测试全绿 ≠ 已生效」 |
| packages/ac-host-rows/templates/creator/skills/plugin-dev/SKILL.md | §5 重写：触发判据清单化，双工具分流判据 |
| .dsh/skills/agentchat-dev/SKILL.md（本地态） | 验证阶梯补「装载行源码改动环」 |
| apps/catalog/tool-catalog.json | gen-tool-catalog 重生成（仅 restart 双条目 + 时间戳变化） |

## 裁决
- 三层引导面分层：工具描述（产品面，所有 agent 常驻可见）+ creator 模板（copy-on-write，宿主 boot reconcile 跟随未编辑物化体）+ 本地 dev 技能（本机）。工具描述是单源主引导面，模板/技能只补触发判据与分流规则。
- 描述结构统一：首句=触发判据（满足即调、无需用户指示）→ 机制段 → 收尾互斥指引（判错了用哪个）。既有的机制细节（保壳保 run、回执语义、healthz 验证）保留在机制段。
- 模板改动走 copy-on-write：宿主下次 boot 时 reconcile 判定技能未编辑 → follow 跟随新版（preset-origin 机制，cr-879）。
