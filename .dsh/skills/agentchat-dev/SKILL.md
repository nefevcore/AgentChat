## 项目概览

AgentChat 是基于 cordis 4 的插件化 Agent 平台，定位「Agent 社区」——Agent 拥有性格、记忆、朋友圈，会自主社交。技术栈 Node + TypeScript。

架构总原则：**一切皆插件**——能力、工具、钩子、定时、HTTP、WebUI 全部是可挂可摘的行。

### 三层架构

一句话：会话状态机（串行化 + 队列 + 防自激）→ 信封投递（纯转发、零会话态；Agent 是数据不是插件）→ ReAct 编排（装配链 + steer + 语义化中断）→ 模型会话（协议住纯库，连接池是唯一事实源）。

## 设计原则（每次改动前过一遍）

### 根因优先

修改前先回答「它为什么坏」，定位到结构性原因再动手。

- 禁止打补丁式修复——在症状处贴胶布：特判绕过、重复兜底、就地吞错。
- 补丁修复会累积腐化：下次同类问题还要再打一层。
- 验收：修完能说出「根因是什么、为什么这样修能断根」。

### 插槽-插头

本框架交付物 = 一组可独立摘除的插件行 + 一份契约。

- 改动前自问：**摘掉这一行，依赖它的行能否由 cordis 自动回滚重载、零改动恢复？**
- 能力域 = 服务包（ctx.<key>，插槽）+ 生态薄行（插头）。
- 注册即归属、订阅即归属——卸载时 cordis 自动回收，作者零 dispose 代码。

### 事件归位（新事件必须归位）

| 意图 | 归位 |
|---|---|
| 否决 / 改写 | before-*（waterfall，可 veto） |
| 塑造记录 | transform-* |
| 观察通知 | after-*（emit） |

一切会话态按 conversationId（对桶键）寻址。

### 机制归位（需求先归位再动手）

| 需求 | 归位 |
|---|---|
| 能力调用（要返回值 / 依赖保证 / 同步） | Service 方法 + 消费方 inject |
| 拦截 / 改写 / 否决 | waterfall 事件（变异载体 + next()；不调 next = veto） |
| 纯通知（多方订阅，发送方不关心谁听） | emit 事件 |
| 协议实现 / 重算法 | 纯库包（零 cordis 依赖，可独立单测） |
| 实例 | 注册表里的数据，不是插件 |

推论：

- 禁止 if (ctx.xxx) 探测可选服务再注册副作用——硬依赖用 inject 声明，可选依赖运行时 ctx.get()。
- 部分功能依赖拆独立子行。

### 写完即精简（自主姿态，无需指令）

代码写完，在验证阶梯前后过一遍精简。

- 目标：降低理解成本，而非减少行数。
- 验收：行为分毫不变；要改行为即停，转功能修改流程。

项目内五条：

1. **零冗余**——死代码与重复实现是 bug 藏身处；判死须全仓求证（含测试）；重复两份迟早走散，趁早并源。
2. **最少抽象**——单实现抽象就地内联，不等以后；「未来可能复用」不构成理由。
3. **体量克制**——代码量与功能面成比例；一函数一可名动作；警惕每轮生成重新解释同一设计的「解说式膨胀」。
4. **风格一致**——以仓库事实源为准：学一次，而非每次重学。
5. **模块独立经显式契约**——服务、事件、纯域词汇；与插槽-插头原则同源。

过头信号（出现即回退）：为省行数合并关切；删掉仍有调用方的抽象；变得难调试难测；聪明写法替代直白写法。

范围与裁决：默认只精简近期改动，全量审计是显式决策；看似反模式的既定设计，先查 `src/docs/` 出处再下结论——合法设计的背书只能是文档，不是直觉。

## 红线（不可越）

### 架构红线（三条，框架腐化起点）

1. 能力间直接 import 实例。
2. 手动编排激活顺序。
3. 跨插件传引用。

以上一律换用：服务方法、inject 声明、事件。

### 兼容红线（Node 原生 TS strip-only 加载器）

- 实现面相对导入写显式 .ts。
- 不用类参数属性。
- 纯类型导入用 import type。
- cordis.yml 每行带稳定 id。
- 运行时依赖在 package.json 显式声明，禁靠 hoisting 隐式生效。
- 出厂态 yml 永不运行时写入——本机偏好走 cordis.patch.yml。

### 共性反模式（发现即改）

- 手写清理（注册中心已代管）。
- 跨行 import 实现 / 实例（走服务方法 / 事件 / RPC / slot）。
- 观察型 waterfall 不调 next()——等于静默吞掉下游默认行为。
- 行序表达依赖（一律 inject）。
- yml 行不带 id，或 TREE 与 yml 漂移。
- if (ctx.xxx) 探测后注册副作用。

### 数据根隔离红线（2026-09-25 会话污染事故）

跑测试/验证用的第二 host 实例（bootTree 拉起的进程、脚本里的临时宿主）**必须**把 AGENTCHAT_DATA_ROOT 指向独立临时目录——环境变量随 pwsh 继承，不显式覆盖即与主进程并发写同一 sessions 目录（曾致会话文件双段 seq + 重复收束行）。ac-session 已设数据根独占锁（活进程持锁 → 第二实例 fail-loud 拒启），但纪律先行：新起验证进程一律 AGENTCHAT_DATA_ROOT=.dsh/tmp/test-home-<n> 再 node。

轨道专属反模式见对应 reference 末节。

## 审核验证阶梯（完成后按改动面累加，全走仓库根）

| 改动面 | 必跑 |
|---|---|
| 任何 `src/` 改动 | `pnpm typecheck && pnpm test:unit && pnpm check:deps` + 定向 lint（`npx eslint <改动文件/目录>`） |
| 动了 webui / 前端行 | + `pnpm webui:typecheck` |
| 动了契约 / 事件 / 行集 / 装配链 | + `pnpm smoke` |
| 动了持久化 / 会话链路 / 子进程 | + `pnpm test:integration`；定向 `npx vitest run src/ac-<pkg>`（包内直接跑找不到用例） |
| 发版前 | `pnpm lint` 全量 + `pnpm test` 全量（CI 同款） |

注：typecheck 与 check:deps 是全仓快扫、秒级；CI 无 lint 门禁，全量 `pnpm lint` 只在发版前跑，日常全量纯耗时。

### 提交前自查（六问）

1. 这次修改针对根因了吗——能说出「根因是什么、为什么这样修断根」。
2. 摘掉这个改动，依赖方能否零改动恢复？
3. 事件归位对了吗——before / transform / after + @mode @scope 标注。
4. 依赖声明齐了吗——值导入进 dependencies，type-only 进 devDependencies。
5. 涉平台分支的测试，本地显式过非常规分支（Windows dev 测不到 Linux/macOS 分支）。
6. 改了布局 / 链路 → 同步 `src/README.md`。
