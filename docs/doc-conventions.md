# 文档规范（doc-conventions）

> 性质：docs/ 全域书写与归档规约（命名 / 格式 / 目录 / 归档纪律）。
> 状态：现行 · cr-1008 2026-11-11 成文；整理批（00-ToRevise 清空）期间兼作各批次验收基准。
> 读者：本仓库写文档的人（含 Agent 会话）——新文档落笔前、整理归档前读一遍。

日期与变更登记红线（正文日期一律真实日历日 YYYY-MM-DD、动手前先登记 CR）见仓库根 cr-log.md 头部引言与 [design/meta/epoch-marking-convention.md](design/meta/epoch-marking-convention.md)——本档不重复，只补文档域细则。

## 一、命名规范

1. **全小写 kebab-case**，ASCII，主扩展名 .md；图表附件 .html/.png/.svg 与主档同目录、同名或主档名 + -fig 后缀。
2. **体裁后缀**（见 §二体裁表）：-plan 实施计划 / -handoff 交接 / -postmortem 事故复盘 / -audit 审计 / -survey 与 -report 调研 / -checklist 与 -verify 验证清单 / -convention(s) 规约 / -inventory 清点 / -backlog 活清单。**域深设计与裁决簿无后缀**（session-design.md、host-shell-decisions.md）。
3. **日期尾缀**仅用于一次性事件档，真实日历日 YYYY-MM-DD（如 mic-integrity-sandbox-incident-2026-10-27.md）；永不写裸 YYYY-MM；文件名中的日期是标识符，落笔后不改。
4. **CR 号进正文头部状态行，不进文件名**（历史既名如 llm-pool-hardening-cr99.md 原样保留）。
5. **版本演进**：新稿取代旧稿用独立文件名或版本号（plugin-architecture-v2.md 取代 plugin-architecture.md），被取代稿随整理批归档——禁止同文件内新旧双轨叙事。
6. **禁止**：空格、中文文件名、下划线、大写字母、临时后缀；草稿住 sandbox/ 或分支，docs/ 只收定稿。

## 二、文档格式（人类可读优先）

### 头部三行（现行档强制，缺一即不合规）

```markdown
# <标题>（与文件名呼应）

> 性质：<域深设计 | 裁决簿 | 实施计划 | 调研报告 | 事故复盘 | 审计 | 规约 | 活清单>——一句话说清本文是什么
> 状态：<现行 | 已实施待归档 | 已冻结归档 | 已被 <档名> 取代> · cr-<号> YYYY-MM-DD
> 读者：<谁在什么时机需要本文>（默认「本仓库开发者」可省）
```

- 三行让读者 10 秒判断「要不要读、还作不作数」；**状态行是唯一时效声明**——状态变化只改这一行，不在正文散写 TODO / 待定 / 已过期。
- 正文段落整体过时就整段迁移或删除（登记 CR），不留划痕式「以下过时」注记。

### 正文规则

1. 标题层级：一级只有文档标题一个；二级起编号（## 一、或 ## 1. 择一，档内统一）；层级深不过四。
2. 目录：超过约 300 行的长档在头部后放锚点目录；短档不放。
3. **表格优先**：并列事实（对照 / 清单 / 映射 / 状态板）一律表格，prose 只留论证、裁决与因果。
4. 代码 / 路径 / 命令 / 字段名一律反引号；文件路径写仓库相对路径（docs/design/…），保持可点击。
5. 交叉引用：引文档给相对路径链接；引具体裁决带 cr 号；**移动或改名文档必须全仓 grep 同步引用**（node scripts/cr.mjs check 的路径锁会提示未命中）。
6. 段落一事一段、不超过 6 行；超限拆列表。
7. 简体中文技术文体，术语首现给英文原词；状态符沿用 ☐（开放）/ ◐（部分）/ ☑（完成），不引入装饰性 emoji。
8. 图表（.html/.png）随主档同目录存放、主档内嵌链接；图表是文档的一部分，同受归档纪律约束。

### 体裁必含节与收官判据

| 体裁 | 必含节 | 收官判据（何时归档） |
|---|---|---|
| 域深设计（无后缀） | 设计目标 / 终态规格 / 与代码的映射点 | **永不归档**，随代码演进维护 |
| 裁决簿（无后缀） | 判例编号 / 判据 / 裁决 / 取代关系 | **永不归档**（被取代判例标注不删） |
| 实施计划 -plan | 背景与根因 / 分批切分 / 测试标准 + 验证目标 | 实施完成且验证目标全达 → archive/ |
| 交接 -handoff | 当前进度 / 未竟事项 / 接力入口 | 接力完成 → archive/ |
| 事故复盘 -postmortem | 时间线 / 根因 / 修复 / 防复发 | 修复落地 → archive/ |
| 调研 -survey / -report | 首节「结论速查」/ 证据 / 建议 | 裁决采纳后 → archive/ |
| 审计与清单 -audit / -checklist / -verify / -inventory | 范围 / 逐项判定（☐◐☑）/ 出处 | 逐项闭环 → archive/ |
| 规约 -convention(s) | 规则 / 例外 / 先例 | **永不归档**（本身是现行规约） |
| 活清单 -backlog | 条目 + 状态符 + 出处（cr 号） | 逐项闭环标注；清空后整档归档 |

**实施计划的两层验收（cr-1026）**：必含节分两栏，各有其主——

- **测试标准** = 过程门：按改动面走验证阶梯（typecheck / test / lint 等）。它与计划目的无关——任何改动都要过，全绿是**必要非充分**；
- **验证目标** = 目的态断言：该批做完后世界应有的样子（旧机制死透 / 行为不变 / 等价可证 / 文档无双轨……），可判定、不依赖「跑了什么命令」。

分批表两列分记；收官判据只认验证目标全达，测试标准不单独构成完成。

## 三、目录划分与归档纪律

域目录划分与代表档见 docs/README.md「design/ 域目录」表（单一事实源在 README，本节只立规则）。

1. **现行档**住 docs/design/<域>/；**归档档**住 docs/design/archive/（批 6 起按域分子目录，一次成型后不再挪）。
2. 归档三去向，按序判断：
   a. 有复用价值（决策轨迹 / 踩坑实录）→ archive/<域>/，内容冻结原样；
   b. 整体过时且无复用价值 → 仓库外归档根（Note\AgentChat\docs-archived-<日期>\）；
   c. 内容已被他档吸收 → 直接删除，吸收档记一笔来源。
3. 归档不改内容不改名（重名冲突加 -old 后缀例外）；移动一律 git mv 保 blame，同步全仓引用后登记 CR。
4. **整理暂存队列不是常设机制**：cr-1008 曾用 `design/00-ToRevise/` 作为分批整理的中转（批后已移除）。后续整理若需分批，用分支或 `sandbox/` 暂存，不在 `docs/` 下新设状态目录。
5. **移动文档的引用纪律**：已落位档一律指终态路径；移动当批内全仓 grep 同步（`node scripts/cr.mjs check` 的路径锁会提示未命中）。
