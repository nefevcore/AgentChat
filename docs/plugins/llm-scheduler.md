# @agentchat/llm-scheduler（规划中 · 未实现）

## 概述
LLM 动态调度能力：在 `ctx.llm`（`LLMService` 适配器注册表）之上增加一层"按请求动态决定用哪个模型/供应商"的调度层。现状是每个 Agent 的 `provider/model` 静态写死在 AgentConfig 里，一次配置全程不变；本插件的目标是让每次 LLM 请求在发出前先经过调度决策，按任务特征、成本、健康度实时选择最合适的后端。前端配合：输入框工具栏提供模型快速切换，Agent 配置的 LLM 退化为工具栏上的默认模型选择。

## 功能描述（简单描述，不含实现）
- **模型分流**：按请求特征选择模型档位——短消息/简单问答走轻量便宜模型，长上下文/复杂推理/带工具调用的请求走旗舰模型；分流规则可配置。
- **故障降级（fallback 链）**：主模型超时、限流（429）或报错时，按预设的备选链自动切换重试，而不是直接失败。
- **供应商负载与并发控制**：多 API Key 轮换、按供应商设并发上限、失败退避重试，把请求分散到多个后端。
- **成本与配额控制**：支持设置预算/配额上限，按 Agent、会话维度统计用量，超限时降档或拦截。
- **策略配置**：全局默认策略 + Agent 级 / 会话级覆盖（例如某个 Agent 强制指定模型，某类任务固定走某供应商）。
- **输入框工具栏快速切换**：WebUI 聊天输入框工具栏提供模型选择器，用户可随时为后续请求手动切换模型；Agent 配置里的 LLM 仅作为该选择器的**默认值**（详见下节）。

## UI 交互（输入框工具栏）
- **模型选择器位置**：`ChatInput`（`@agentchat/webui`）工具栏内，与现有输入操作并列的下拉选择器；候选项来自当前已注册的 provider/模型清单（openai/deepseek/glm/ollama 适配器 + 用户配置的模型列表）。
- **Agent 配置语义变化**：AgentConfig 的 `llm`（provider/model）不再表示"锁定模型"，而是**工具栏上的默认选中项**——新会话/未手动切换时用它；用户在工具栏切换后，本次会话的后续请求以工具栏选择为准。
- **优先级**：工具栏手动选择（会话级） > Agent 配置默认 > 调度策略自动分流。手动选择视为"用户显式指定"，动态分流不覆盖它，但故障降级链仍生效（切换失败时按备选链重试并提示）。
- **回执与可见性**：切换即时生效于下一条消息；界面需可见当前生效模型（如发送中在消息流/状态区展示实际使用的模型），避免"以为在用 A 实际跑了 B"。
- **实现提示（待定）**：可能需要 webui 新增 `chat-input` slot 或内置组件 + protocol 增加对应 WS/REST 契约（切换、生效模型查询、候选模型列表），实现时再定。

## 与其他插件的关系
- 依赖 `@agentchat/llm`：复用其适配器注册表（openai/deepseek/glm/ollama），调度层只做"选哪个"，不自己对接 API。
- 服务 `@agentchat/agent-loop`：ReAct 引擎在每次发起 LLM 请求前调用 `ctx.llmScheduler` 拿到本次应使用的 `LLMConfig`；未启用本插件时行为不变（直接用 Agent 静态配置）。
- 关联 `@agentchat/webui`：`ChatInput` 工具栏的模型选择器是本能力的前端入口；Agent 配置的 llm 退化为工具栏默认值（需 webui 配合改造 Agent 设置页的表述）。
- 关联 `@agentchat/protocol`：模型切换、当前生效模型、候选模型清单需要新的跨端契约（WS 事件 / REST），实现时定义。
- 关联 `@agentchat/agent-session` 的 log-usage 钩子：调度产生的实际用量可并入现有用量记录。
