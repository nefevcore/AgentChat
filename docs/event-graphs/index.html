AgentChat · 事件图谱 以事件为核心要素

cordis 第一性原理轨道（src/）——事件是能力域之间的唯一接缝：waterfall（决策/改写/否决）与 emit（纯通知）二选一，按 domain/action 命名、按 owning package 归属。

① 事件全景图谱（Event Atlas）

全部 owning 包事件按「域」分组，并按 作用域 分两带：run 域（发生在某个 Agent 的执行里，可经 agentOf* 读取器 per-Agent 门控）与 host 域（宿主上下文，无身份、不可门控）。悬停查看语义。

图例：W = waterfall（拦截/变换链，before-*/transform-*）；E = emit（纯通知）；● = run 域 / ● = host 域。框架层另有 vendor cordis 的 internal/* 元事件，见图谱底部。

② 端到端事件时序图谱（Run Lifecycle Flow）

一轮投递的完整事件链路：conversation.deliver → router.send → agentLoop.run。每个 run 依次经历「三档装配链 → 步循环 → 收束」，事件按 before-* → started → 主体 → transform-* → after-* 归位。

③ 事件模式图谱（Pattern Taxonomy）

全项目唯一公开约定：变换落 transform、观察落 after、否决落 before。每个执行环节的事件词汇都套用同一五段骨架（before → started → 主体 → transform → after）。

④ 订阅关系图谱（Subscription Graph）

谁 emit 谁声明 → 谁订阅谁消费。左=emit 方（owning 服务），中=事件，右=订阅方（行）。扩展能力一律落 loop/before-run* 事件监听，无专有 hook 机制。

非穷举（dev-tools / timer-tools 等次要订阅与测试订阅未列全）；ac-ws-bridge 的桥接面见 ⑥。

⑤ 作用域图谱（Run vs Host Scope）

判定式 =「这次分发发生在谁的执行里」：答得出唯一 Agent 的为 run 域，答不出的为 host 域。载荷带 agentId ≠ run 域——run 域才有 agentOf* 读取器，per-Agent 门控可用性由作用域结构性编码。

⑥ WS 桥接图谱（Bridge to Frontend）

ac-ws-bridge 把 emit 面桥接成 WS 帧（帧 type = 事件名直转）。waterfall（拦截链）绝不桥；机制来源（source='event'）的自会话桶/归档整理 run 流式帧被后台过滤。

数据源：src/*/src/events.ts（owning 包事件目录，@mode/@scope JSDoc）· src/ac-app/tests/event-catalog.test.ts（目录锁定）· src/README.md（契约归属总表）· src/ac-ws-bridge/src/index.ts（桥接面）。 统计口径：52 个 owning 包事件 = 11 waterfall + 41 emit；25 run + 27 host（system/restarting 未标 @scope，按 host 归）。
