# 第一部分 · 统一设计（壳模型）

## S0. 统一命题

**cell ≡ CLI 壳**：cell 档案设计的「执行面独立进程 boot 独立树」与 per-agent 档案的
「agent 子树独立进程（CLI 直连形态）」是**同一实体的两个视角**。统一不是兼容拼接，是
同一性认定：执行面同一 + 控制面取代。

一句话：**壳 = boot 了 agent 子树的运行时容器；宿主 = 邮局 + 监护人 + 可选 UI；
activation = agent 的执行单例（锁）；账本 = 状态层（身份键 = 端点）**。

统一成立的论证链：

1. **cell 的前提被 per-agent 逐条拆除**：数据根独占锁退役降粒度（D1）→ 壳可承载账本
   （cell 档案硬问题 2 增补已自认「不必再 loop-only」）；承重行随子树 boot（D3 激进化）→
   横切服务 RPC 回控制面（硬问题 4）消解；审批 = user 端点消息（R-9）→ 交互回合跨进程
   （硬问题 1）消解。
2. **cell 的控制面被取代**：旧 ac-conversation 状态机 + 已退役 ac-router 集中投递的设想，被
   per-agent 宿主模型（邮局非必经、投递原语恒一）取代——控制面不是被补充，是退位。
3. **反向馈赠成立**：per-agent 缺容器经济学（冷启动实测、重启阶梯、warm pool 论证），
   cell 档案恰好提供——两档案各自发明了对方的一半。

M6 后补记：cell 档案至此遗产全部吸收完毕（实测经济学 → S2 池化解散论证；契约分层思想
→ 投递协议层 additive-only 纪律；L2 勘察教训 → S5 剃刀注记），无剩余独立角色。

## S1. 对象模型（四件）

```
Agent        = 账本 + 身份（注册表数据）+ 工具面（per-agent D1 原样）
activation   = 逻辑单例——锁辖域 = agent 级，跨壳跨形态同一把（per-agent D1 两层锁语义）
壳 shell     = 物理容器——boot agent 子树的进程（唯一形态，S2）
宿主 host    = 邮局 + 监护人 + 可选 UI——唯一持久进程（per-agent D0 一句话）
```

activation 与壳解耦：**activation 是逻辑事实（谁在跑），壳是物理事实（在哪跑）**。
一 agent 同时一个 activation；一个 activation 任一时刻住一个壳。

## S2. 壳恒为进程（M4 终态裁决 + M5 过渡态删除，2026-10-14）

**壳只有一种形态：进程，从第一天起就是。** activation 长命（会话粒度）、进程随
activation 生灭。M5 删除「宿主内子树」过渡态——理由：过渡态验证的不是终态（内存
锁 / 共享故障域 / 同进程直调 transport 三样在终态全不存在，语义 spike 在其上跑通对
终态说服力打折）；锁与 transport 双实现 = 双踩坑面（承重件不分叉）；per-agent 账本
语义本就不依赖执行位置（现状单宿主即是验证场地）。壳模型自此单形态、无双轨。

四个直接后果：

1. **形态唯一，选址只剩拉起方与授权宽度**：谁拉起（宿主按需 / CLI 直连 / 恢复环边 2
   agent 拉宿主）与拿多宽授权（per-agent 配置，S3）——无形态轴、无指派字段（M1）。
2. **transport 单模式**：宿主 ↔ agent 恒跨进程，「同进程退化为直调」双模式退役——
   R-9 形状约束残余价值归零；所有边界（宿主↔agent、agent↔agent、父↔子）同一套
   投递协议、一种通道语义。
3. **故障域完整闭合**：D0 痛点「一处 in-flight run 全灭」真正解决——native crash
   死一个 agent 进程，宿主与邻居无恙。
4. **锁介质天然**：activation 单例锁 = 进程持有的文件锁——boot 取锁、进程死 OS 自动
   释放，崩溃即放锁、无陈锁（开放问题 1 就此收口）。

**宿主变纯**：宿主进程内零 agent 代码——邮局 + 监护人 + webui + 授权注册表写者。
「监护人」从比喻变字面事实（N 个 agent 进程的父进程）；宿主崩溃面骤缩，D5 恢复环
边 2 从常态变罕见。**监护职责成文**（宿主新组件，开放问题 2 就此收口）：按需拉起、
健康监视、idle-exit 收割（长闲进程退出放锁，来件重拉 +200ms，会话粒度生灭不违背
池化解散）、崩溃退避熔断（crash-loop 防抖）。

**代价（诚实清单）**：内存地板 = 每活跃 agent ~50–80MB（cell 档案实测口径）——5 活跃
≈ +300MB，现代工作负载可感度低（对照：单开 VS Code ~1GB）；idle-exit 阈值是运维旋钮
（太紧抖动 / 太松驻留）；children 探查逐个成进程（run 内 3 子 = 并行 ~200ms 墙钟 +
瞬时 3×50MB，可接受；RSI 影子隔离反而更顺）。**换取**：一形态、单协议、完整隔离、
纯宿主、天然锁——D0 一句话（Agent = 自治实例 = OS 进程）在 OS 层面的字面兑现。

**池化解散**（维持）：进程在会话粒度生灭，不在 run 粒度；RSI 切换分钟级节奏，200ms
冷启动是噪声。cell 档案实测自证「10ms 多为伪需求」全局成立。

## S3. 授权宽度 = 参数，非角色（M6，2026-10-14 剔除「沙箱」）

**不存在沙箱这个架构角色。** 每个 agent 启动即「拿自己的授权投影跑」——机制全 agent
统一（per-agent 授权注册表层 + 数据根直读，D3/R-11）；「沙箱化某 agent」= 给它配更窄
的授权——普通配置行为，无独立形态、无专用协议层。

三条客户查证（原沙箱场景全部有着落）：

1. **RSI 候选**：影子 = R-5 spawn 派生身份，天然 ⊆ 父授权投影 + per-agent 授权隔离——
   隔离由授权粒度免费覆盖，无需沙箱机制。
2. **高风险 / 第三方重 agent**：实质 = 用户对其信任低 → 同一解法：更窄授权投影。
3. **不可信代码执行**：与 D3 二值信任模型互斥——装载 = 授权动作（域外，经授权信），
   已装载即进信任域（单一信任域 per 子树进程，D3 代价清单第 1 条已裁决接受）。
   架构里不存在「已装载但不可信」状态，沙箱假设的可信度光谱没有位置。

协议层无「沙箱硬化版」：transport 单模式（M4）后所有边界本就是同一套投递协议（信封 /
requestId 幂等 / 落账即确认 / 授权信）——它就是宪法层本身，无需按信任度分版本。

剔除代价（诚实）：纵深防御少一道物理墙（授权数据被操纵的对手模型 ≈ 物理访问，单机
单用户产品中该墙本就挡不住）；未来多租户 / 开放生态需重新发明——但那是不同产品，
YAGNI。宪法层思想（additive-only / 修宪权物理剥离）归投递协议层继承，不随沙箱退役。

## P2. cell × activation 子问题 · 壳模型答案（✓ 已裁决 2026-10-17）

① **映射基数**：壳 : activation = 1:1 恒成立——每 activation 独占进程（M4 + M5 后无
共进程形态）；「何时必须独占进程」之问随之消失，选址 = 拉起方 × 授权宽度（S2/S3）。
② **无 runtime 字段（M1）× 单例锁**：选址无旋钮（拉起方 × 授权宽度决定），锁辖域恒
agent 级；迁移语义 = 现任收束 → 去激活（放锁）→ 新壳激活（取锁）。RSI 切流量不经
字段：uuid 寻址（与影子派生身份会话即新流量），转正 = 授权动作走宿主管道（R-5 已裁）。
③ **影子不撞锁**：影子 = 派生身份新 agent（R-5 机制），非 w 的第二激活；两者各自单例。
④ **词汇撞车**：账本身份键恒端点（agent），壳（cell / CLI 进程）= 临时容器与写者执行
体。cell「无状态」原则以「壳不拥有账本、壳死账本在」形式幸存。
⑤ **形态唯一化（M4 + M5）**：壳恒为进程且从第一天起就是——无过渡态、无双轨。开放
问题 1（锁介质 = 进程文件锁）与 2（调度归属 = 宿主监护组件）已随之收口。
