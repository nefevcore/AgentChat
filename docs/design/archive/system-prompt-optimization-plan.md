## 二、优化原则（五条红线）

1. **分工红线**：system prompt 只放工具描述教不了的——**何时用、结果怎么
   解读、何时停**（旧轨 audit 实证 + "工具描述自足则退出"先例）。
2. **缓存红线**：新增内容一律静态块；动态信息仍只归对话信息与 datetime。
3. **预算红线**：静态区净增 ≤350 token；新增条目须归入"响应纪律 / 反推断 /
   流程闭环 / 旧轨行为策略回归"四类之一。
4. **词形锁定**：指引关键词 = 工具名/参数名原文（`old_string`、
   `timer(action="set")`、`job_id`、`subagent(action="spawn")`）——已逐一
   核对新轨工具名。
5. **可测可回滚**：措辞变化过快照基线显式 diff（P3）；git revert 即回。

## 三、改动项

### P1 framework 块退役（v3 用户裁决）

- 删 `DEFAULT_FRAMEWORK` 与块装配分支；静态块变为：系统环境 → 术语约定 →
  指引（含吸收的命令/后台任务条目）。
- **配置面同步退役**：行 `Config.framework`、`settings['system-prompt'].framework`、
  `extension.fields` 的 framework 项——类型删除强制迁移（M24 X1 先例）。
- **断言换锚**：portb-e2e `toContain('你是 AgentChat')` → `'## 系统环境'`
  （比 `'## 指引'` 更稳——不依赖注册工具集；persona 组合测试锚同换）。
- KV：部署期一次 invalidate-from-0，之后零抖动。
- loop 协议句（一次只做一步/二选一/续推/完成即停）随块消失；需要者由
  persona 作者自行承载（admin 现文本未含，作者自决）。

### P2 指引重构：dsh 句式 + 条目级门控 + 并入命令与后台任务

**门控总则**：每条只在该条提及的工具在场时注入；全空则整块消失。
**排序**：执行类（文件/命令/后台）→ 产出 → 协作类 → 行为策略类。

| # | 条目 | 门控 | 来源 | 拟文 |
|---|---|---|---|---|
| 1 | 文件操作 | read+write+edit | 现网改写 | 文件操作：改现有文件用 edit，old_string 从 read 的输出中原样复制（自拟文本会匹配失败）；同一文件有多处独立修改时，并行发多个 edit 调用。write 是整文件覆盖，只用于新建文件。找文件用 glob，搜内容用 grep；不确定文件位置时先用 glob 确认，不要凭记忆拼路径。bash 只做文件工具办不到的事（组合命令、进程、环境）。 |
| 1b | （edit 缺席） | read+write | 不动 | 文件操作：edit 不可用，修改文件需先 read 再用 write 写入完整内容。 |
| 2 | 命令执行 | bash | 新增 | 命令执行：命令以非零退出码结束时，先读输出定位原因，修正后再继续（原样重跑大概率再次失败）；被中断的命令按已终止处理，不代表命令本身有错。长输出会被截断，需要完整输出时先重定向到文件再 read。 |
| 3 | 后台任务 | job ∥ bash | 现网 2 条合并改写 | 后台任务：后台命令会返回 job_id，记住 id，任务完成时会收到通知，不要用 job list 忙轮询；确需等待完成时，用前台 bash 配合较长 timeout 更直接。给出最终回答前，先收集仍在运行的相关任务的结果；不再重要的任务用 job kill 及时清理，避免占用并发额度。 |
| 4 | 产出物引用 | write/edit/bash 之一 | 微调 | 产出物引用：创建或修改文件后，最终回复中简要列出主要产出文件，路径用 markdown 行内代码格式；只说"已修改"而不给路径，用户无法定位文件。 |
| 5 | 多Agent协作 | list_agents+send_agent | 改写 | 多Agent协作：先 list_agents 找对象，再 send_agent 发消息。消息异步送达：发出后继续手头工作，回复会作为新消息到达；仅当下一步依赖对方结果时才设 wait=true。 |
| 6 | 群聊协作 | list_groups+send_group | 不动 | 群聊协作：先 list_groups 查看所在群组，再 send_group 发消息。 |
| 7 | 主动安排 | timer | **旧轨回归** | 主动安排：发现值得持续跟进或适时提醒的事项时，主动用 timer(action="set") 安排，不必等用户指令。 |
| 8 | 不可逆操作前询问 | ask_questions | 微调 | 不可逆操作前询问：删除、覆盖、花钱、对外发言等不可逆或涉及授权的操作，先 ask_questions 征求确认，不要擅自替用户决定。 |
| 9 | 并行子任务 | subagent | 改写 | 并行子任务：独立、可并行的子任务用 subagent(action="spawn") 派出，完成后 subagent(action="await") 取结果；若后续步骤依赖其输出，则不适合派出。 |
| 10 | 系统管理 | system_restart | **旧轨回归** | 系统管理：修改 src/ 业务包源码后，需要 system_restart 重启才能生效（reload 只重读配置，不加载代码改动）；仅在确实需要时使用。 |

**"命令与后台任务"并入指引的裁决分析**（详见示例 B5）：

- 赞成：dsh 事实形态 = 无独立章节、每工具一段平级散文（结构对齐）；门控
  本就是条目级实现，并入零机制改动；省一个块标题；#1→#2→#3 构成"工具执行"
  三连，语义连贯。
- 反对及回应："未来条目膨胀"——膨胀再分块不迟（YAGNI）；"标题有检索作用"
  ——LLM 靠词形而非标题检索（词形锁定红线）。
- **结论：并入**；若最终改判保留独立，仅需 #2/#3 拆出为 `## 命令与后台任务`
  块（门控不变），其余零改动。

framework 遗产去向：报错勿原样重发 → #2；勿凭记忆拼路径 → #1 尾句；
loop 协议句（完成即停等）→ 随块消失（persona 可承载）。

## 四、显式不做（带理由）

1. **dsh 逐工具全量散文段**：预算红线；audit 实证用法句与工具描述大面积冗余。
   只在"结果解读/何时停"维度加句。
2. **模型身份注入**（"powered by <model>"）：Agent↔模型解耦；换模型即全桶
   前缀重置，价值/代价不成比例。
3. **宿主环境散文锚定**：结构化 KV 行已更优。
4. **持久化存储块恢复默认注入**：框架层→角色层裁决确认。
5. **标签约定 / 引号段复辟**：旧轨晚期移除有实证理由。
6. **时间挪出 system prompt**：链路代价 > 每日一次前缀重置（M21 §4.4）。
7. **persona 内容治理**：角色块归 Agent 作者。
8. **`<memory>` / `<available_skills>` 等外部注入**：v3 用户指示先不管。
