AgentChat 系统架构

多 Agent 协作框架 · ReAct 推理引擎 · 插件化扩展 · WebSocket 实时推送

Node.js + TypeScript v0.1.0 ~2000 行核心 20 个源文件 MIT

启动流程

bootstrap() -- 7 步串联全链路
Step 1 Router + Registry + GroupManager最先就绪，无 Agent 依赖
Step 2 AgentLoader.loadAll()扫描 agents/ → 解析 config.json → 发现全局插件
LLM 池引用解析 · $ref 覆盖合并 · autoInject 标记识别 · MCP manifest 发现
Step 3 VirtualAgent 注册user 等虚拟 Agent -- 无 LLM，仅走 preHook → postHook 管道
Step 4 真实 Agent 实例化LLM 工厂 → 注册工具(静态 + autoInject + MCP) → 拦截器 → Pre/Post Hook
每个 Agent 独立 LLM 实例 · DeepSeek user_id 缓存隔离 · 凭据自动注入
Step 5 MessageQuery 初始化JSONL 只读查询服务 → 注入 AppState 供 query_history 工具使用
Step 6 WebUI Server 启动Express REST + WebSocket，端口 3831（可 --no-webui 跳过）
Step 7 TimerManager 启动加载所有 Agent 定时任务 + 全局报时 (chime) → 开始调度

ReAct 推理循环

核心引擎 · Agent.run()
Agent.run(ctx) → ReAct 循环
(1) 入口串行化
执行队列 (MAX=32) 保证同一 Agent 同时只有一个 ReAct 循环运行。后续消息自动排队。
(2) preHooks 链式变换
agent-prompt 生成提示词 → agent-memory 注入记忆 → agent-session 加载历史。每步修改 context 传递给下一步。
(3) executeLoop
中断检查 → steer 指令注入 → invokeLLM（流式）→ processTurn：有 tool_calls 则执行后循环，否则退出。
(4) runTools
每条 tool_call 经过所有 Interceptor（强制约束）→ 执行 → 结果注入 messages。interrupted 则保存部分输出。
(5) postHooks 副作用
agent-session 持久化会话 → agent-memory 更新记忆。唯一出口：中断/正常/异常都经过此节点。
(6) 流式事件桥
chat.thinking.{start|update|end} · chat.message.{start|update|end|error} · chat.toolcall.{start|update|end} · chat.tool_execution.{start|update|end} · chat.turn.{start|end} · chat.{start|end}
