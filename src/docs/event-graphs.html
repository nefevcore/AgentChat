图谱一 · 事件目录全景

全部 52 个事件按 owning 包分卡陈列，分 run 作用域（分发发生在某个 Agent 的执行里，可用 agentGate 做 per-Agent 门控） 与 host 作用域（宿主进程域）。菱形 = waterfall（可变载体 + next() 委托，可 veto），圆点 = emit（纯通知广播）。
数据源：16 个 owning 包事件目录（13 个 src/events.ts + plugin/webui/durable-interaction 声明在 service.ts），由 ac-app/tests/event-catalog.test.ts 静态锁定 @mode/@scope 全量标注。

图谱二 · 事件模式解剖（词汇的公开约定）

事件模式完整形：before-\*（决策/改写/否决）→ started（通知）→ 主体 → transform-\*（塑造记录）→ after-\*（通知终值）。 变换落 transform、观察落 after、否决落 before——模式是公开约定，新事件必须归位。
五条链对齐展示：router 投递链 / loop run 链 / loop step 链 / llm 会话链 / tool 执行链。灰槽 = 该链无此相位词汇。

图谱三 · 端到端事件时序（一条消息的生命周期）

conversation.deliver → router.send → agentLoop.run → llm.chat / tools.execute 全链事件发射时间线。 泳道内菱形段 = waterfall 拦截链（监听器内联在链上），圆点 = emit 广播（箭头射向右侧事件总线，标注进程内订阅方）。
链路事实源：src/README.md 端到端链路 · ac-agent-loop/src/service.ts beforeRunChain 三档装配 · ac-ws-bridge/src/index.ts 后台会话过滤。

图谱四 · 发布-订阅图谱（谁 emit、谁订阅）

三列二部图：owning 行（左）→ 事件（中）→ 订阅行（右）。点击事件节点高亮其全部边；点击左侧行/右侧行查看其收发面；顶部按域过滤。虚线圈出 ac-ws-bridge 桥接面（emit 面 → 前端 WS 帧）。
扫描口径：ctx.emit / ctx.waterfall（发射点）与 ctx.on（订阅点）全仓静态检索，不含测试代码；CLI（ac-app/src/chat.ts）流式消费单独标注。

图谱五 · 拦截链洋葱图（waterfall 嵌套栈）

一轮 run 的 waterfall 层层委托：next() 不带参数、改写输入的唯一方式是变异载体，调用沿层向内、返回值沿层向外。 三档装配链 before-run-first → before-run（主档）→ before-run-last（尾档）——cordis waterfall 无优先度，档位拆分就是次序本身。
veto = 任一层不调 next() 即短路外层全部（LLM 不被调用，finish='veto'）；观察型监听器必须调 next()。

图谱六 · 事件反应环（事件驱动的自驱动再入）

事件不只是观测：多个行订阅事件后反手投递新会话（conversation.deliver，source:'event'）， 形成闭环自驱动。串行化门排队防并发，MAX_AUTO_WAKES=3 防自激；真人消息（source:'user'）重置预算。
机制任务不过 LLM：归档/备份直调服务方法；“触发 Agent 干活”统一 source:'event' 信封投递，事件痕迹自然进会话流。
