AgentChat 移动端链路图

单核心端 + 哑中继 + 扫码配对（remote-client-relay-plan 方案 B，M1–M3 已实施）。手机是瘦客户端：真相源（会话/记忆/凭据）全部留在 PC 核心端；relay 只转发密文帧——不存储、不探测是密码学结构，不是运营承诺。

① 总览：三端一管道

② 配对协议：二维码 → XK → SAS

一次性配对（XK）
  1. PC：startPairing → roomId（32B 随机，p: 前缀信令）+ 二维码 agentchat://pair?v=1&relay=…&room=…&pk=…&exp=…（5min 过期）
  2. 手机：扫码（深链唤起）→ 双方各自出站连 relay → join(roomId) → 房间封闭（恰好两方，第三人一律 room-unavailable）
  3. Noise XK 握手（发起方=手机，已带外获知 PC 静态公钥）：PC 静态公钥加密传输（防收集身份）+ 双重 DH；设备信息放 m3（加密段——设备公钥不以明文过 relay）
  4. SAS 比对：SHA256(handshake_hash) 前 4 字节 → 8 位数字，双端屏幕人工核对（封死二维码被副录抢配的残余通道）
  5. PC confirmPairing → 设备写入 remote/known_devices.json（含 scopes）→ 加密通道下发 remote/paired{deviceId, scopes} → 房间销毁
运行态重连（KK）

双方已知对方静态公钥 → 双向认证 KK 握手。roomId 确定性派生：SHA256(core_pub ‖ deviceId ‖ device_pub)——两侧各自可算，无需协商。会合模式：PC 长驻在房 70s 等，手机短撞 7s/轮 ×10——互补相位避免对称重试死锁（relay 只转发实时帧，m1 早于对端进房即丢）。实测：闪断 1.8s 自愈 / 杀 relay 23s 会合。

③ 安全模型

四道防线
传输层：Noise E2E（ac-noise-core / Noise.kt 对称双实现）XK/KK 状态机 + ChaCha20-Poly1305 AEAD + HKDF-SHA256；帧 {n, ct} 单调计数防重放；握手绑定 Ed25519 身份——relay 被接管也无法解密/注入/MITM。自签 TLS 仅混淆层（认证在 Noise 层）
授权层：scopes 分档 + elevation 恒剥除read（纯查询 + GET /api）→ chat（投递面）→ files（HTTP 写面，显式开启）→ admin（空数组显式禁用）。deliver 类转发恒剥 elevation——远程设备永远不能借提权通道武装
设备层：Keystore + 吊销 + 生物锁私钥硬件级不可导出；吊销 = 删注册表（下次握手即败）；生物识别解锁才连 relay、切后台即断
结构层：哑中继纪律统一错误码无存在性回声 + 无持久化 + 只允许错误码计数日志——「不存储不探测」由结构兑现，开源可审计（RelayCore 13 测试）

④ 业务帧同构：远程 = 本地

密文内载荷与本地 WS 协议同构

密文解开就是 rpc/call / rpc/result / 事件帧——核心端与手机端各只有一个「加解密壳」，业务层零改动：

上行（手机 → PC）  WebView rpc/call → 回环桥 → Noise 加密 → relay 密文转发 → remote-link 解密 → scopes 闸门 → webServer.callRpc（本地同一处理器）
下行（PC → 手机）  ctx 事件 emit → 白名单过滤 → Noise 加密单播 → relay → 回环桥 → WebView 事件帧（webui 实时流照常）
HTTP 面            WebView /api/* → 回环桥拦截 → http/read|write RPC（加密链路） → 回环 127.0.0.1 投自身 web-server（同一代码路径）

断线语义：真相源在 PC 账本（ac-session journal），手机离线期间消息全部入账；重连后按 conversationId 增量拉取（history/replay RPC）。
