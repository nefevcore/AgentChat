# 日期标记规约（epoch-marking）

> **cr-1（2026-09-27）重写**：日期语义从「特性批次代号」改为「真实日历日」；
> 存量月份标记已分层全量修正（底册见 `archive/epoch-inventory-2026-09-27.md`）。
> 变更登记（CR 目录）住 `cr-log.md`——一切变更动手前先登记。

## 一、日期语义（现行）

**注释/文档中的日期 = 真实日历日期，格式 `YYYY-MM-DD`。**

- 日期回答「这件事发生在哪天」，批次归属由既有的 M 编号（M27/M28/M29…）承担，
  两者不再混用——一个日期只承担时间，一个编号只承担批次。
- 写新注释：取**真实当日**。
- **禁止**写裸 `YYYY-MM`（无日的月份标记）——这是 cr-1 全量清除的形态，不再产生。

## 二、书写规则

### 规则 1：新标记一律完整日期

```
// 正确：2026-09-27 用户裁决……
// 错误：2026-09 用户裁决……（裸月份禁止）
// 错误：2026-12-00 xxx……（-00 是历史存量专用形态，不可新写）
```

### 规则 2：存量 `-00` 标记只读不写

全仓存量 `YYYY-MM-00`（约 26 处：史前标记 2026-01/02 及个别不可考行）是「日缺失」声明。
读取时按该事件原语义理解；顺手改动所在注释行时**原样保留**，不补日（无从考证，编造即失真）、
不改月。

### 规则 3：引用历史裁决，日期保持原样

转述/引用既有裁决（含存量 `-00` 标记与旧完整日期）时照抄，不翻译、不换算。

### 规则 4：命名中的日期原则上不改；确需校准须全链同步

文件名/路径中的日期是标识符：文档文件名（`*-2026-09-20.md`）保留不动。确需校准的
（如 cr-1 将外部归档目录 `docs-stale-2026-12\` 改名 `docs-stale-2026-09-18\`）必须
物理实体 + 全部引用（仓库内外）一体同步，并先在 `cr-log.md` 登记 CR。

### 规则 5：功能性日期值不受本规约约束

测试冻结时钟（FROZEN_NOW）、运行时数据面（节假日清单等）是数据不是标记（见底册 §五）。

## 三、历史背景（已退役语义，仅供考古）

2026-09-20 曾裁决 `YYYY-MM` = 特性批次代号（「计划纪元」：计划文档标未来月份，实现注释
照抄——2026-10/11/12 共 800+ 处超前于真实日历的自洽时间线）。该语义在实践中持续造成
误读（无法区分「哪天写的」与「哪个批次」），cr-1 起退役：日历归日历，批次归 M 编号。
全量修正的方法与底册见 `archive/epoch-inventory-2026-09-27.md`。
