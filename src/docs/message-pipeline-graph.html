Bug 窗口带：双管线时序差的可观察后果

每处窗口都是「直播管线与权威管线对不上」的具体形态，按链路位置排序。
W1 · 收束竞态（全局窗口）
300ms 延时重拉与 settlement 落盘竞速：慢机器/远程链路下重拉拿到旧数据 → 直播行换不成权威行（persistedMsgId 缺失 → 分支/编辑/删除不可用）。cr-60：resume 快照尾部追加越过 journal 活投影步——同族窗口。
W2 · 步行锚点去重
多步轮步行共享收束行 message_id（同锚）但渲染 id 各异——单键去重把同轮第二条起的步行全部吞掉。2026-09-21 改双键 persistedMsgId|id。
W3 · event 行重复投递
直播 event 行与历史 event 行同 message_id 重复渲染——liveEventIds 过滤（feed-core L615-629）为点补丁。
W4 · 前缀复用过期 Turn
run 中后台 job 通知 event 行插入后工具卡永久转圈——turnContentSig 漏 tool result 长度，前缀复用了过期 Turn。cr-61
W5 · 孤儿 partial 行幻影回放
崩溃窗口的未收束 partial 行每轮活投进上下文诱发幻觉（78 行孤儿事故）。读侧 7 天闸门 + v6 迁移清除。cr-44
W6 · 恢复物化 agent_id 错根
recoverJournal 从桶键推导 agentId，singles 桶拿到桶键本身 ≠ 运行 Agent → 整轮丢失。cr-45
W7 · 双人格共桶锚串台
记忆锚检测扫桶内全部行不看 agent_id，双端点桶互相打掉基线无限震荡。cr-46
同族先例（链路层，同构根因）：cr-52 大帧风暴、cr-78 桶键分裂、cr-85 两条下行链路各自为政——都是「同一数据多管线、口径靠约定不靠构造」的变体。

结构结论：为什么消息区「总是有些小问题」

F1 · 双管线无收敛协议（主根因）

直播事件流与权威历史投影是两条独立管线，最终视图 = 两者在前端的时序敏感合并。合流只靠「去重 + 300ms 延时重拉」，没有「权威行到达即替换」的收敛事件。W1~W4 全部是同一根因的不同切面：任一管线迟到、乱序、多投，视图即错位。

F2 · 三读路径口径漂移

同一存储被 LLM history()、web-api records()、remote lite 三种口径读取，还有 viewer/pair/group/single 投影变体。口径一致性靠人工维护，cr-54/55 缓存污染、cr-78 桶键分裂、cr-45 agentId 错根都是漂移实例。
